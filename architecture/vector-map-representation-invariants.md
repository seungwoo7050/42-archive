# `vector`의 객체 구간과 `map`의 노드 트리

두 컨테이너 모두 `insert`, `erase`, `size`를 제공하지만 정상 상태를 설명하는
말은 전혀 다르다. [`ft_vector.hpp`](../include/ft_vector.hpp)는 한 블록 안에서
어디까지 객체가 생성됐는지를 관리하고,
[`ft_map.hpp`](../include/ft_map.hpp)는 흩어진 노드의 소유권과 양방향 링크,
색을 함께 관리한다. 공개 함수 이름보다 이 표현 차이가 실패 처리와 반복자
계약을 결정한다.

## 두 컨테이너가 소유하는 상태

| 컨테이너 | 소유 상태 | 살아 있는 값 | 구조 변경을 확정하는 시점 |
|---|---|---|---|
| `vector` | 할당자, 블록 포인터, 크기, 용량 | `[data, data + size)` | 새 블록이나 임시 컨테이너를 완성한 뒤 저장 상태를 교체한다. |
| `map` | 값·노드 할당자, 헤더 센티널, 크기, 비교자 | 헤더의 루트에서 도달 가능한 값 노드 | 탐색과 노드 생성을 마친 뒤 연결하고 색·링크를 보정한다. |

공통 타입 도구와 반복자는 공유하지만 두 컨테이너의 저장 표현은 서로 의존하지 않는다. `stack`만 기본 저장 컨테이너인 `vector`의 상태 관리에 직접 의존한다.

## `vector`의 표현

현재 상태는 네 멤버로 구성된다.

```cpp
allocator_type _alloc;
pointer        _data;
size_type      _size;
size_type      _capacity;
```

정상 상태에서는 다음 조건이 함께 성립해야 한다.

| ID | 조건 |
|---|---|
| V1 | `_size <= _capacity <= max_size()`이다. |
| V2 | `_data == NULL`이면 소유한 블록이 없고 `_capacity == 0`이다. |
| V3 | `_data != NULL`이면 `_alloc`이 `_capacity`개 슬롯의 저장공간을 소유한다. |
| V4 | 정확히 `[0, _size)`에만 `value_type` 객체가 살아 있다. |
| V5 | `[_size, _capacity)`는 객체가 아직 생성되지 않은 원시 저장공간이다. |
| V6 | 비어 있지 않을 때 `begin() == _data`, `end() == _data + _size`이다. 빈 상태에서는 두 함수가 `_data`를 그대로 반환한다. |
| V7 | 저장공간을 반환할 때 획득에 사용한 할당자와 용량을 함께 사용한다. |

V4와 V5가 어긋나면 소멸 과정에서 생성하지 않은 객체를 파괴하거나, 생성한 객체를 빠뜨릴 수 있다. 공개 원소열만 비교해서는 이 오류를 발견하기 어렵기 때문에 예외 검사에서 살아 있는 주소와 할당 블록을 별도로 기록한다.

### 새 블록의 준비와 교체

재할당은 기존 상태를 유지한 채 새 블록을 준비한다.

```text
새 블록 획득
  └─ 기존 원소를 [0, size) 순서로 복사 생성
      ├─ 성공: 기존 객체·블록 정리 → 새 포인터·크기·용량 저장
      └─ 실패: 새로 만든 접두사 정리 → 새 블록 반환 → 예외 전달
```

개수 생성자는 같은 방식으로 생성된 객체 수를 추적한다. 개수·범위 `assign`과 복사 대입은 임시 `vector`를 완성한 뒤 `_swap_storage`로 포인터·크기·용량만 교환한다. 임시는 호출 대상과 같은 할당자를 사용하므로, 저장 블록이 다른 할당자에 넘어가지 않는다.

재할당 삽입도 앞부분, 삽입 원소, 뒷부분을 새 블록에 모두 만든 뒤 `_replace_storage`를 호출한다. 실패하면 새 블록에서 만든 객체만 역순으로 파괴한다.

### 여유 용량 안의 삽입

기존 블록을 재사용할 때는 먼저 `[old_size, old_size + count)`에 필요한 꼬리 객체를 생성한다. 이 구간이 완성된 뒤 기존 객체 대입으로 원소열을 정렬하며, 마지막에만 `_size`를 늘린다.

```text
old_size 유지
  ├─ 미사용 꼬리 슬롯에 객체 생성
  ├─ 기존 객체 대입으로 뒤쪽 이동
  ├─ 삽입값 대입
  └─ 전부 성공한 뒤 size = old_size + count
```

복사 생성이 실패하면 새 꼬리를 모두 파괴하므로 원래 수명과 크기가 남는다. 대입 단계에서 실패하면 이미 대입한 원소 값은 달라질 수 있지만 새 꼬리는 정리되고 `_size`는 이전 값이다. 따라서 V1~V5는 유지되며 컨테이너를 계속 사용할 수 있다.

범위 삽입은 입력을 임시 `vector`에 먼저 보관한다. 자기 컨테이너의 반복자를 입력으로 주더라도 이후 재할당이나 이동 때문에 읽을 값이 사라지지 않는다. 개수 삽입과 재할당 `push_back`은 참조가 현재 원소를 가리킬 수 있으므로 입력값을 먼저 복사한다.

범위 `assign`과 `insert`는 입력을 임시 저장해 별칭을 분리한다. 임시 입력이
보장하는 것은 원본을 변경하는 동안에도 **읽을 값의 수명**이 유지된다는 점이다.
여유 용량 안 삽입의 대입 단계까지 원소열 전체를 되돌린다는 뜻은 아니며, 그
단계가 실패하면 값 일부는 달라질 수 있다. 현재 실패 sweep는 재할당 range
삽입을 다루고, 제자리 range assignment 실패는 검사하지 않는다. 정상 자기
범위와 확인한 예외 경계는
[`008-vector-self-range-aliasing.md`](../devlog/008-vector-self-range-aliasing.md)와
[`016-throwing-elements-and-vector-rollback.md`](../devlog/016-throwing-elements-and-vector-rollback.md)에서 함께 다룬다.

### 크기와 용량 변경

- `clear()`는 `[0, _size)`를 역순으로 파괴하고 블록을 유지한다.
- `_destroy_storage()`는 `clear()` 뒤 블록을 반환하고 포인터와 용량을 초기화한다.
- 감소 `resize`는 마지막 객체부터 파괴한다.
- 증가 `resize`는 한 객체의 생성이 끝난 뒤 `_size`를 늘린다. 실패하면 이번 호출에서 만든 접미부만 정리한다.
- `reserve`는 새 블록을 완성하기 전까지 기존 상태를 유지한다.
- full-capacity `push_back`은 `reserve` 성공 뒤 마지막 원소를 생성한다. 그 생성이
  실패하면 크기와 값은 유지돼도 새 capacity와 block은 이미 공개됐을 수 있다.
- `_next_capacity`는 두 배 성장을 기본으로 하며 오버플로 전에 `max_size()`로 포화한다.
- `erase`는 대입으로 값을 당긴 뒤 마지막 객체를 파괴한다. 대입이 실패하면 크기는 그대로지만 값 일부가 바뀔 수 있다.

### 실행으로 확인하는 조건

[`tests/test_vector_exceptions.cpp`](../tests/test_vector_exceptions.cpp)의 `tracked_value`는 다음을 기록한다.

- 살아 있는 객체 주소
- 복사·대입 시도 횟수와 실패 위치
- 수명이 없는 주소에서 복사하거나 같은 객체를 두 번 파괴한 횟수
- 반환하지 않은 할당 블록

생성, `assign`, 대입, `resize`와 개수 삽입의 실패 위치를 바꾸어 가며 검사한다.
range 삽입은 재할당 복사 실패와 정상 제자리 경로를 나누어 확인한다. 개수 삽입의
대입 실패 뒤에는 `push_back`을 다시 수행해 상태가 계속 사용 가능한지도 본다.
제자리 range·erase 대입, capacity 부족 resize의 내부 reserve가 끝난 뒤 suffix
생성이 실패하는 경로와 full-capacity push의 마지막 생성 실패는 미검사다.
기존 여유 capacity에서의 resize suffix 실패는 주입한다.

## `map`의 표현

`map`은 값이 없는 기반 노드와 값을 가진 노드를 분리한다. 다음 코드는 두 형식의
관계만 보여 주기 위해 생성자와 접근 지정자를 덜어 낸 구조 요약이며
`include/ft_map.hpp`를 그대로 옮긴 인용은 아니다.

```cpp
// 설명용 구조 요약: 생성자는 생략
struct node_base
{
    node_base* parent;
    node_base* left;
    node_base* right;
    bool       red;
    bool       is_header;
};

struct node : node_base
{
    value_type value;
};
```

컨테이너 멤버 `_header`는 `node_base`이며 실제 키·값을 생성하지 않는다. 따라서 기본 생성할 수 없는 키도 빈 `map`에 사용할 수 있다. 값 노드만 할당자로 획득하고 파괴한다.

### 헤더 센티널

헤더는 루트와 양 끝을 한곳에 연결한다.

| 상태 | `_header.parent` | `_header.left` | `_header.right` |
|---|---|---|---|
| 빈 트리 | `NULL` | 헤더 자신 | 헤더 자신 |
| 값이 있는 트리 | 루트 | 최솟값 노드 | 최댓값 노드 |

루트의 부모는 헤더이며 `end()`도 헤더 주소를 가리킨다. 반복자는 노드 포인터 하나만 저장한다. `--end()`는 헤더의 현재 최댓값을 사용하므로, 회전이나 루트 삭제 전에 얻은 끝 반복자도 갱신된 트리를 따라간다.

`_refresh_header()`는 삽입·삭제·대입·교환 뒤 다음을 다시 연결한다.

1. 루트 부모를 현재 컨테이너의 헤더로 설정한다.
2. 왼쪽 링크에 현재 최솟값을 저장한다.
3. 오른쪽 링크에 현재 최댓값을 저장한다.

빈 상태에서는 `_reset_header()`가 자기 참조를 복구한다.

### 소유권과 연결 불변식

| ID | 조건 |
|---|---|
| M1 | 빈 트리는 `_size == 0`이고 헤더가 빈 상태 링크를 갖는다. |
| M2 | 값이 있으면 루트의 부모가 헤더이다. |
| M3 | `parent->left/right == child`이면 `child->parent == parent`이다. |
| M4 | 루트에서 도달 가능한 값 노드 수가 `_size`와 같다. |
| M5 | 헤더는 값 노드의 자식으로 나타나지 않는다. |
| M6 | 각 값 노드는 재결합한 노드 할당자로 한 번 생성되고 한 번 파괴된다. |
| M7 | 비교자가 동등하다고 보는 키마다 노드가 하나만 존재한다. |

단일 삽입은 비교를 마쳐 부모와 방향을 저장한 뒤 노드를 만든다. 생성한 노드를 연결한 후 삽입 보정을 수행하고 크기를 늘린 뒤 헤더의 양 끝을 갱신한다. 노드 할당 뒤 비교자를 다시 부르지 않으므로 비교 예외가 미연결 노드 누수로 이어지지 않는다.

범위·복사 생성자는 중간 실패 시 `clear()`를 호출한다. 대입은 대상 할당자로
임시 트리를 완성한다. 비교자 교환은 루트·크기 소유권을 옮기기 전에 수행하므로,
비교자가 자신의 상태를 바꾸기 전에 던지는 검사 경로에서는 대상 tree가 그대로
남는다. 임의 비교자의 부분 변경이나 할당자 교환 예외까지 강한 보장을 일반화하지
않는다.

### 정렬과 레드-블랙 불변식

모든 값 노드는 비교자가 정한 열린 구간 안에 있어야 한다. 왼쪽 서브트리의 키는 현재 키보다 작고, 오른쪽 서브트리의 키는 현재 키보다 크다. 키 동등성은 `operator==`가 아니라 두 방향 비교가 모두 거짓인지로 판정한다.

균형 조건은 다음과 같다.

| ID | 조건 |
|---|---|
| M8 | 루트와 헤더는 검정이다. |
| M9 | 널 자식은 검정 잎으로 취급한다. |
| M10 | 빨강 노드의 자식은 모두 검정이다. |
| M11 | 한 노드에서 모든 널 잎까지의 검정 노드 수가 같다. |
| M12 | 회전과 이식 뒤에도 중위 순서와 부모 링크가 유지된다. |

삽입 보정은 부모와 삼촌의 색에 따라 재색칠하거나 회전한다. 삭제는 대상 노드의 값을 복사하지 않고 후계 노드를 구조적으로 이식한다. 실제로 빠진 노드의 색이 검정이면 형제의 색과 자식 상태를 따라 삭제 보정을 수행한다. 마지막에는 루트를 검정으로 고정하고 헤더 링크를 갱신한다.

`clear()`는 후위 순회로 자식부터 정리한 뒤 헤더를 빈 상태로 돌린다. 레드-블랙 높이가 유지되는 정상 상태에서는 재귀 깊이도 트리 높이에 제한된다.

### 구조 검사기

[`tests/support/map_inspector.hpp`](../tests/support/map_inspector.hpp)는 `map`에 선언된 `ft::detail::map_inspector` 친구를 통해 내부 상태를 읽는다. 운영 코드에 검사 분기를 넣지 않고 다음 항목을 한 번의 재귀 순회로 확인한다.

- 헤더 표식·색과 빈 상태 자기 참조
- 루트 부모, 헤더의 최솟값·최댓값
- 모든 부모·자식 링크
- 상·하한을 전달해 확인하는 전체 정렬
- 빨강 자식 연속 금지
- 좌우 검정 높이 일치
- 도달 노드 수, 실제 높이와 `size()`

고정 삭제 수열, 현재 루트 반복 삭제와 고정 시드 무작위 연산의 매 단계에서 검사기를 실행한다. 공개 원소열이 우연히 맞더라도 색이나 부모 링크가 틀리면 그 단계에서 실패한다.

## 저장 표현이 반복자에 드러나는 방식

`vector` 반복자는 저장공간의 주소이므로 재할당의 영향을 직접 받는다. `map` 반복자는 값 노드나 헤더의 주소이며 회전은 값 노드를 재할당하지 않는다.

| 변경 | `vector` | `map` |
|---|---|---|
| 삽입 | 재할당 시 모두 무효화되며, 재할당이 없으면 삽입 위치부터 값의 의미가 이동한다. | 기존 값 노드는 유지되며 헤더의 루트·양 끝이 갱신된다. |
| 삭제 | 삭제 위치 뒤 원소가 앞 슬롯으로 이동한다. | 삭제한 노드만 수명이 끝나며 다른 노드는 이식된 링크를 따른다. |
| 교환 | 블록과 할당자를 함께 교환한다. | 루트와 할당자를 교환한 뒤 각 루트를 새 헤더에 연결한다. |
| 끝 상태 | `_data + _size`이다. | 컨테이너에 내장된 헤더 주소이다. |

[`tests/test_map_iterators.cpp`](../tests/test_map_iterators.cpp)는 저장한 끝 반복자의 회전·루트 삭제 대응, 원소 반복자의 회전·교환 대응과 가변·상수 반복자의 양방향 비교를 확인한다.

## 어느 검사가 어느 조건을 읽는가

| 검사 파일 | 직접 확인하는 표현 조건 |
|---|---|
| `test_vector_exceptions.cpp` | V1~V5에 필요한 객체 수명과 블록 회수, 별칭 입력, 용량 상한 |
| `test_map_exceptions.cpp` | M4·M6에 필요한 노드 수와 회수, 생성·대입 실패의 원본 보존 |
| `test_map_iterators.cpp` | 헤더 양 끝의 갱신, 반복자 노드 표현과 교환 뒤 연결 |
| `test_map_policy_exceptions.cpp` | 복사 대입과 공개 교환의 비교자 실패 뒤 tree 소유권과 계속 사용 가능성 |
| `test_map_randomized.cpp` | M1~M5·M7~M12와 `std::map` 공개 결과의 단계별 동치 |
| `test_complexity.cpp` | M8~M12가 만드는 높이 상한과 탐색·삽입 비교 횟수 |
| `test_containers.cpp` | 정상 경로의 값·크기·순서와 공개 반환값 |

검사는 구현의 모든 가능한 형식과 입력을 증명하지는 않는다. 다만 값 결과만 비교하던 상태에서 객체 수명, 노드 소유권, 반복자 끝 상태와 트리 내부 조건까지 회귀 기준으로 포함한다.

`vector`와 `map`의 표현을 바꿀 때는 이 표의 검사 파일을 함께 갱신한다. 공개 값
비교만 통과해도 객체 수명, 헤더 링크나 레드-블랙 색 조건은 깨질 수 있으므로 표현
조건을 직접 읽는 검사를 생략하지 않는다.
