# 표준 컨테이너와 비교할 수 있는 범위

이 저장소는 C++98 컨테이너의 주요 동작을 재현하지만, 표준 라이브러리 전체를 대체한다고 주장하지 않는다. 현재 소스와 자동 검사가 뒷받침하는 범위를 공개 결과, 실패 뒤 상태, 반복자와 복잡도로 나누어 설명한다.

## 결과가 같다는 말의 네 가지 수준

| 수준 | 확인 방법 | 현재 상태 |
|---|---|---|
| 공개 형식 | 통합 헤더와 각 개별 헤더를 C++98로 컴파일한다. | Linux GCC·Clang, macOS Clang의 CI 행렬로 구성했다. |
| 공개 결과 | 같은 연산을 `ft`와 `std` 컨테이너에 적용해 크기·값·순서·반환값을 비교한다. | 고정된 정상 입력과 고정 시드 무작위 입력을 검사한다. |
| 실패 뒤 상태 | 복사·대입·비교·할당이 지정된 시점에 실패하도록 주입한다. | `vector`와 `map`의 주요 생성·대입·삽입 경로를 검사한다. |
| 내부 구조와 비용 | 테스트 전용 검사기로 트리 링크·색·검정 높이를 읽고 비교자 호출 횟수를 센다. | 매 무작위 연산과 1,024개 키 시나리오에서 검사한다. |

이 범위에는 모든 표준 과부하, 상태 보유 할당자의 전파 정책, 힌트 삽입 최적화와 모든 사용자 정의 형식 조합이 포함되지 않는다. 예를 들어 `is_integral`은 비한정 정수 형식을 특수화하며 `const int` 같은 cv 한정 형식까지 확장하지 않는다.

## `std`와 직접 맞춰 본 공개 결과

### 공용 도구

[`tests/test_containers.cpp`](../tests/test_containers.cpp)는 `pair`, `make_pair`, `is_integral`, `equal`, `lexicographical_compare`와 `reverse_iterator`의 선택된 결과를 확인한다. 개별 헤더의 최소 사용 경로는 [`tests/headers`](../tests/headers)에서 따로 컴파일한다. 컴파일에 성공했다는 사실은 아직 인스턴스화하지 않은 모든 템플릿 조합의 호환성을 뜻하지 않는다.

### `vector`

공개 비교 검사는 다음 동작을 `std::vector`와 대조한다.

- 추가, 개수·범위 삽입, 삭제, `resize`, `reserve`
- 범위 생성, 복사와 대입
- 역방향 순회와 관계 연산
- `at(size())`의 `std::out_of_range`
- 현재 컨테이너를 입력으로 쓰는 범위 `assign`과 `insert`

성장 정책의 정확한 용량값은 비교하지 않는다. 구현은 대체로 두 배씩 늘리되 할당자의 `max_size()`에 가까워지면 상한에서 포화한다. 제한된 `max_size()`에서 유효한 성장을 받아들이는지는 [`tests/test_vector_exceptions.cpp`](../tests/test_vector_exceptions.cpp)가 확인한다.

자기 범위 확장 동작은 표준 컨테이너 자체에 같은 자기 범위를 전달해 oracle로
삼지 않는다. `ft` 호출 전 입력을 외부 `std::vector` snapshot으로 복사하고 그
snapshot으로 기대 결과를 만든 뒤 값·크기를 비교한다.

### `stack`

기본 `ft::vector` 기반 `ft::stack<int>`에 대해 `push`, `pop`, `top`, `size`, `empty`와 관계 연산을 비교한다. 다른 하위 컨테이너가 만족해야 할 최소 인터페이스나 그 컨테이너의 예외 동작은 별도로 검사하지 않는다.

### `map`

고정 입력 검사는 다음 결과를 `std::map`과 대조한다.

- 중복 삽입의 성공 여부와 반환 반복자
- `operator[]`, `find`, `count`
- `lower_bound`, `upper_bound`, `equal_range`
- 정방향·역방향 순회
- 키·반복자·범위 삭제
- 범위·복사 생성, 대입과 `swap`
- 비교 함수 접근자와 관계 연산

[`tests/test_map_randomized.cpp`](../tests/test_map_randomized.cpp)는 시드 `0x5EED1234`로 3,000개 연산을 재현한다. 삽입, 갱신, 키·반복자 삭제, 조회, 복사, 대입, 교환과 `clear`를 섞어 두 개의 `ft::map`을 각각 `std::map`과 비교한다. 실패하면 시드와 연산 번호, 그 시점까지의 연산 목록을 출력한다.

## 연산별 타입 요구와 실제 비용

컨테이너 타입을 선언할 수 있다는 사실과 모든 멤버를 사용할 수 있다는 사실은
다르다. C++98에는 concepts가 없으므로 요구 조건은 실제 멤버가 인스턴스화될 때
compiler 오류나 실행 중 예외로 드러난다.

### 타입 요구 조건

| 범위 | 현재 구현이 실제로 요구하는 능력 |
| --- | --- |
| `vector<T, Alloc>` 저장소 | `Alloc::pointer`가 null과 비교되고 덧셈·뺄셈 가능한 raw-pointer-like 형식이어야 한다. 원소 destructor는 정리 중 예외를 밖으로 내보내지 않아야 한다. |
| vector 생성·추가·삽입 | 사용하는 연산에 따라 `T`의 copy construction이 필요하다. 제자리 삽입·erase에는 copy assignment도 필요하고, 기본 인자를 쓰는 개수 생성·resize에는 default construction이 필요하다. |
| vector range API | `InputIt`는 복사 가능하고 `!=`, dereference와 전진을 제공해야 한다. 역참조 결과로 `T`를 구성할 수 있어야 한다. category dispatch는 없고 범위를 한 번 소비해 임시 vector에 저장한다. |
| `stack<T, Container>` | `value_type`, `size_type`, `back`, `push_back`, `pop_back`, `size`, `empty`가 필요하다. 관계 연산을 쓰면 하위 container의 같은 관계 연산도 필요하다. |
| `map<Key, T, Compare, Alloc>` | 값 allocator를 `node`로 `rebind`할 수 있어야 하고 구현은 내부 링크에 raw `node*`를 사용한다. 삽입·복사에는 Key/T 복사가 필요하고 `Compare`는 const 함수에서 호출 가능하며 strict weak ordering을 제공해야 한다. 관계 연산을 쓰면 Key/T의 `==`·`<`도 필요하다. |
| `map::operator[]` | `mapped_type()`을 모든 호출에서 먼저 만들므로 `T`가 default-constructible이어야 한다. 기존 키 조회도 이 생성에서 예외가 날 수 있다. |

### 공개 연산의 현재 복잡도

아래 표는 이름이 비슷한 표준 연산의 일반론이 아니라 현재 소스가 실제 수행하는
경로다. `n`은 기존 원소 수, `m`은 입력 범위 크기, `k`는 처리할 map 원소 수다.

| 연산 | 시간 | 추가 공간·주의점 |
| --- | --- | --- |
| vector 조회, `begin/end`, `size/capacity`, `front/back` | O(1) | 범위·빈 상태 precondition은 호출자 책임인 연산이 있다. |
| vector `push_back` | amortized O(1), 성장 시 O(n) | 성장 시 새 블록 O(n). 마지막 원소 생성 전에 블록 교체가 끝날 수 있다. |
| vector `reserve`·성장 `resize` | O(n) 또는 O(n + 추가 원소) | `reserve(new_cap)`은 O(new_cap) 저장공간을 할당한다. 성장 resize는 정책이 정한 새 capacity만큼 저장공간을 얻는다. |
| vector range `assign` | O(n + m) | 항상 임시 vector O(m)를 만들고 교체 뒤 기존 n개 원소를 파괴한다. 기존 capacity를 재사용하지 않는다. |
| vector range `insert` | O(n + m) | 입력 snapshot O(m)을 항상 만들고, 필요하면 새 원본 블록 O(n + m)도 만든다. |
| vector `erase` | 뒤 원소 수에 선형 | 제자리 assignment 뒤 꼬리 객체를 파괴한다. |
| vector 관계 연산 | 공통 접두사 길이에 선형 | 원소 비교 비용이 곱해진다. |
| 기본 `stack` 조회·`top/pop` | O(1) | 다른 하위 container를 지정하면 그 비용을 그대로 따른다. |
| 기본 `stack::push` | vector의 amortized O(1) | 관계 연산은 하위 vector 길이에 선형이다. |
| map `find/count/lower_bound/upper_bound` | O(log n) | 레드-블랙 높이와 comparator 비용을 따른다. |
| map 단일 삽입·`operator[]` | O(log n) | hint overload도 일반 삽입으로 전달된다. |
| map range·복사 삽입 | O(k log(n + k)) | 원소별 단일 삽입을 반복하며 bulk build는 없다. |
| map iterator 삭제 | O(log n) | fixup 뒤 최솟값·최댓값을 다시 찾는다. range 삭제는 O(k log n)이다. |
| map `clear`·관계 연산 | O(n), 두 map 비교는 선형 | `clear`는 각 노드를 파괴한다. |
| map `begin/end` | O(1) | header가 최솟값·최댓값과 end 문맥을 보관한다. |
| map `swap` | O(log n + log m) | 필드 교환 뒤 두 header의 최솟값·최댓값을 다시 탐색한다. |

`tests/test_complexity.cpp`는 삽입·검색의 높이와 comparator 횟수만 검사한다.
삭제, range API, `swap`, vector movement와 추가 공간 표 전체를 자동으로
측정하지 않는다.

## `vector`의 실패 처리

`vector`가 관리하는 객체는 `[data, data + size)`에만 존재해야 한다. 예외 검사에서는 살아 있는 객체 주소와 할당 블록 수를 기록해 이 조건이 실패 뒤에도 유지되는지 확인한다.

### 완성한 뒤 교체하는 경로

| 연산 | 준비 단계 | 실패했을 때 |
|---|---|---|
| 개수 생성자 | 새 블록에 `count`개를 차례로 생성한다. | 생성한 접두사를 파괴하고 블록을 반환한다. |
| 개수·범위 `assign`, 복사 대입 | 임시 `vector`를 완성한다. | 임시 객체만 정리되고 원본 값·크기는 유지된다. |
| 재할당이 필요한 개수·범위 `insert` | 새 블록에 앞부분, 삽입값, 뒷부분을 모두 생성한다. | 새 블록만 정리하고 원래 저장공간을 유지한다. |
| `reserve` 내부 복사 | 새 블록에 기존 원소를 복사한다. | 복사한 원소와 새 블록을 정리한다. |

`push_back(values[0])`처럼 인수가 재할당으로 무효화될 저장공간을 가리킬 수 있으므로, 재할당 전에 값을 복사한다. 개수 삽입도 같은 이유로 입력값을 먼저 복사한다. 범위 삽입은 입력 범위를 임시 `vector`에 담아 자기 범위 별칭을 분리한다.

full-capacity `push_back`에는 별도 commit 지점이 있다.

```text
인수 value 복사
→ reserve로 새 블록 교체
→ 새 꼬리 원소 construct
→ size 증가
```

마지막 construct가 던지면 기존 값과 size는 유지되지만 reserve는 이미 성공했다.
따라서 capacity가 커지고 모든 기존 iterator·reference가 무효화될 수 있다.
이 경로를 “실패하면 vector 전체가 관찰상 그대로”라고 설명하지 않는다. 현재
`test_aliased_push_back()`은 정상 별칭 성공만 확인하며 마지막 construct 실패를
주입하지 않는다.

### 기존 블록을 사용하는 경로

`resize`는 새 원소를 하나씩 생성한 뒤에만 `_size`를 늘린다. 중간 실패 시 이번 호출에서 만든 접미부를 역순으로 파괴하고 이전 크기로 돌아간다. 다만 먼저 `reserve`가 성공한 뒤 원소 생성이 실패했다면 값과 크기는 유지되어도 용량은 커질 수 있다.

여유 용량 안의 삽입은 아직 객체가 없는 꼬리 공간을 먼저 구성하고, 그 뒤 기존 객체에 대입해 순서를 맞춘다.

- 꼬리 복사 생성 중 실패하면 이번에 만든 객체를 파괴하며 기존 값과 크기를 유지한다.
- 이동 또는 채움 대입 중 실패하면 이미 대입된 원소 값 일부는 달라질 수 있다.
- 어느 경우에도 새 꼬리는 정리되고 `_size`는 이전 값이므로, 객체 수명 범위와 크기는 일치한다.

따라서 용량 안 삽입의 대입 실패에는 유효한 상태를 보장하지만 원소열 전체의 롤백은 보장하지 않는다. `erase`도 뒤 원소를 대입해 당기므로 사용자 대입이 던지면 값이 일부 이동된 채 남을 수 있으며, 이 경로의 실패 주입은 현재 검사에 없다.

[`tests/test_vector_exceptions.cpp`](../tests/test_vector_exceptions.cpp)는 다음 사례를 실행한다.

- 개수 생성자, 개수 `assign`, 복사 대입, 증가 `resize`
- 재할당과 여유 용량 안의 개수 삽입에서 복사 생성·대입 실패
- 여유 용량 range 삽입의 정상 주소·capacity 보존
- 재할당 range 삽입의 복사 실패 sweep
- 할당 실패와 별칭 입력
- 빈 반복자와 제한된 `max_size()`
- 실패 뒤 살아 있는 객체, 잘못된 복사·파괴와 미반환 블록

range 제자리 assignment 실패, `erase` assignment 실패, capacity가 부족한
`resize`가 내부 reserve로 block을 교체한 뒤 suffix 생성이 실패하는 경로와
`push_back`의 마지막 construct 실패는 현재 검사하지 않는다. 기존 여유
capacity에서의 resize suffix 실패는 주입한다.

기본 `ft::stack`은 이 `vector`를 하위 컨테이너로 사용하고 별도의 롤백 계층을 두지 않는다. 따라서 값 저장과 실패 뒤 상태의 성질도 하위 `vector` 계약을 그대로 따른다.

## `map`의 실패 처리

### 삽입

단일 삽입은 비교자로 중복 여부, 부모와 연결 방향을 모두 결정한 뒤 노드를 할당한다. 할당 뒤에는 비교자를 다시 호출하지 않는다. 노드 값 생성이 실패하면 `_create_node`가 즉시 메모리를 반환한다. 따라서 비교자 실패는 트리를 바꾸기 전에 발생하고, 생성 실패는 연결되지 않은 노드를 남기지 않는다.

`insert(first, last)`를 이미 존재하는 컨테이너에 호출하면 원소별 단일 삽입을 반복한다. 중간에 실패하면 그 전에 성공한 삽입은 남는다. 범위 삽입 전체를 하나의 트랜잭션으로 되돌리는 인터페이스는 아니다.

### 생성과 대입

범위 생성자와 복사 생성자는 빈 트리에 원소를 넣으며, 도중에 실패하면 `clear()`로 이미 만든 노드를 정리한 뒤 예외를 다시 던진다. 생성자 본문에서 예외가 나면 `map` 소멸자가 호출되지 않으므로 이 명시적 정리가 필요하다.

복사 대입은 대상의 할당자를 사용해 임시 트리를 완성한 뒤 비교자를 먼저
교환하고 tree 소유권을 옮긴다. 비교자가 자신의 상태를 바꾸기 전에 던지는
실패 주입에서는 대상 루트·크기·원소가 유지된다. 공개 `swap`도 같은 순서로
비교자를 소유권 필드보다 먼저 교환한다. 임의 비교자가 일부 상태를 바꾼 뒤
던지는 경우와 할당자 교환 예외는 강한 보장 범위에 포함하지 않는다.

[`tests/test_map_exceptions.cpp`](../tests/test_map_exceptions.cpp)는 다음 상태를 기록한다.

- 비교자 호출 위치별 단일 삽입 결과와 소유 노드 수
- 비교·할당 실패가 발생한 범위 생성자의 노드 회수
- 복사 생성 실패 뒤 원본 노드와 할당 블록 수
- 비교·할당 실패가 발생한 대입 뒤 대상 원소와 블록 수

[`tests/test_map_policy_exceptions.cpp`](../tests/test_map_policy_exceptions.cpp)는
복사 대입과 공개 `swap`의 비교자 대입 실패 뒤 양쪽 tree 소유권, 순서와 계속
사용 가능성을 별도로 확인한다.

`operator[]`은 lookup 전에 `mapped_type()`을 만들어 `value_type`을 구성한 뒤
단일 삽입을 사용한다. 따라서 키가 이미 있어도 default construction 요구와
예외 가능성이 남는다. 이 경우 map은 아직 lookup·삽입을 시작하지 않아
바뀌지 않는다. 기본 생성 실패 형식은 별도로 주입하지 않는다.

## 반복자와 참조

### `vector`

`iterator`와 `const_iterator`는 각각 할당자 포인터와 상수 포인터이다.

- 재할당하면 모든 원소 반복자와 참조가 이전 블록을 가리키게 된다.
- 여유 용량 안 삽입에서는 삽입 위치 앞의 주소는 유지되고, 그 위치부터 원소의 의미가 이동한다.
- 삭제에서는 삭제 위치 뒤 원소가 앞 슬롯으로 대입되고 `end()`가 바뀐다.
- `clear()`는 저장공간을 유지하지만 모든 원소 수명을 끝낸다.
- `swap`은 할당자와 저장공간 소유권을 함께 교환한다.

범위 삽입이 여유 용량을 재사용하고 첫 원소 주소를 유지하는 사례는 검사한다. 변경 전 반복자와 참조의 전체 무효화 행렬은 자동 검사하지 않는다.

빈 `vector`의 `end()`는 널 포인터에 0을 더하지 않고 `_data`를 그대로 반환한다. 빈 `begin()`과 `end()`의 동등성도 예외 검사에서 확인한다.

### `map`

`map`은 값이 없는 `node_base` 헤더를 컨테이너 안에 보관한다.

- 헤더의 `parent`는 루트이다.
- `left`와 `right`는 각각 최솟값과 최댓값이다.
- 빈 트리에서는 `parent == NULL`이고 양쪽 끝 링크가 헤더 자신을 가리킨다.
- `end()`는 헤더 주소를 가진 반복자이다.

반복자는 현재 노드 하나만 저장한다. `--end()`는 헤더의 최신 `right`를 사용하므로 반복자를 저장한 뒤 회전하거나 루트를 삭제해도 현재 최댓값으로 이동한다. 끝이 아닌 반복자는 노드의 최신 부모 링크를 따라가며, 삭제하지 않은 노드는 회전으로 재할당되지 않는다.

`iterator`와 `const_iterator`는 양쪽 피연산자 순서에서 `==`, `!=`를 사용할 수 있다. 헤더가 컨테이너마다 다른 주소이므로 서로 다른 두 컨테이너의 `end()`도 같은 널 포인터로 겹치지 않는다.

`const_iterator == iterator`와 반대 피연산자 순서가 모두 컴파일되어야 한다.
[`tests/test_map_iterators.cpp`](../tests/test_map_iterators.cpp)는 두 방향을 함께 실행한다.
끝 반복자는 루트 주소를 복사하지 않고 컨테이너에 내장된 헤더 센티널을 가리킨다.
이 전환의 단계별 경계는
[`011-map-iterator-end-and-constness.md`](../devlog/011-map-iterator-end-and-constness.md)에 정리한다.

교환할 때 루트의 부모를 새 컨테이너 헤더로 다시 연결한다. 검사에서는 교환 전에 얻은 원소 반복자가 원소를 계속 가리키고, 증가했을 때 원소가 옮겨 간 컨테이너의 `end()`에 도달하는지 확인한다. 삭제된 원소 반복자는 계속 무효이며, 교환 전에 저장한 끝 반복자의 동작은 별도로 검사하지 않는다.

헤더는 `value_type`을 갖지 않으므로 기본 생성할 수 없는 키로 빈 `map`을 만들 수 있다.

## 레드-블랙 불변식과 복잡도

[`tests/support/map_inspector.hpp`](../tests/support/map_inspector.hpp)는 테스트 전용 `ft::detail::map_inspector`로 다음 조건을 확인한다.

- 헤더의 표식·색과 빈 상태 링크
- 루트의 부모와 검정색
- 헤더에 저장한 최솟값·최댓값
- 부모와 자식의 양방향 링크
- 비교자가 정의한 하한·상한 안의 키
- 빨강 노드 아래 빨강 자식이 없음
- 모든 널 잎까지의 검정 높이가 같음
- 도달 가능한 노드 수와 `size()`가 같음

고정 삭제 수열, 현재 루트 반복 삭제와 무작위 연산 뒤에 이 검사를 실행한다.

복잡도 검사는 1,024개의 서로 다른 키를 오름차순, 내림차순과 고정 난수 순서로 삽입한다. 노드 수를 `n`, `ceil(log2(n + 1))`을 `L`이라고 할 때 다음 상한을 사용한다.

- 트리 높이 `<= 2L`
- 전체 삽입 비교 횟수 `<= n * (4L + 4)`
- 한 번의 기존·미존재 키 검색 비교 횟수 `<= 2 * 실제 높이 + 2`

이는 입력과 환경에 관계없이 재현되는 구조·호출 횟수 회귀 기준이다. 실행 시간, 캐시 효과, 메모리 사용량을 측정하는 벤치마크는 아니다. 힌트 삽입은 현재 일반 삽입으로 전달되므로 성능 개선을 제공하지 않는다.

## 할당자 정책까지 같다고 말할 수는 없다

현재 구현이 할당자 상태를 다루는 방식은 연산마다 다르다.

| 컨테이너·연산 | 현재 선택 |
|---|---|
| `vector` 생성·복사 생성 | 인수 또는 원본의 할당자를 복사한다. |
| `vector` 복사 대입 | 대상 할당자로 임시 저장공간을 완성하므로 대상 할당자는 유지한다. |
| `vector::swap` | 할당자와 블록 포인터·크기·용량을 함께 교환한다. |
| `map` 생성·복사 생성 | 값 할당자를 보관하고 같은 상태에서 노드 할당자를 재결합한다. |
| `map` 복사 대입 | 대상 할당자로 임시 트리를 완성하고 트리·비교자만 교환한다. |
| `map::swap` | 값·노드 할당자, 루트·크기와 비교자를 함께 교환한다. |
| `map::max_size` | 재결합한 노드 할당자의 `max_size()`를 반환한다. |

값 할당자 상태로 노드 할당자를 구성하며, 추적 할당자 검사는 비교·할당 실패 뒤
블록 회수를 확인한다. 이 검사는 특정 검사 할당자에 대한 것이며 복사·대입·교환의
표준 전파 정책 전체를 뜻하지 않는다.

다음 항목은 아직 일반화하지 않았다.

- 서로 다른 상태를 가진 할당자 사이의 복사·교환 정책 전 조합
- 할당자 교환 예외와 상태를 일부 변경한 뒤 던지는 비교자 대입
- 표준 구현별 세부 용량 성장과 할당 횟수
- 힌트 삽입의 복잡도
- 모든 반복자·참조 무효화 조합
- 모든 표준 컨테이너 API와 형식 특성

현재 주장은 소스와 검사에서 재현되는 범위에 한정한다. [`make check`](../Makefile)는 일반 회귀·개별 헤더·다중 번역 단위 검사를 묶고, `make sanitize`는 같은 경로를 AddressSanitizer와 UndefinedBehaviorSanitizer로 다시 실행한다.
