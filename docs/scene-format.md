# `.rt` 장면 형식

이 문서는 현재 `src/parser.cpp`가 받아들이는 텍스트 계약이다. 비공개 과제
형식 전체나 다른 렌더러와의 호환성을 주장하지 않는다.

## 줄과 토큰

- 입력은 `std::getline`으로 한 줄씩 읽는다.
- 각 줄에서 첫 `#`부터 끝까지는 주석으로 제거한다.
- 앞뒤 공백을 제거한 뒤 빈 줄은 무시한다.
- 나머지는 C++ stream이 인식하는 whitespace로 토큰화한다.
- 벡터와 색은 쉼표를 포함한 한 토큰이어야 한다. `1, 2,3`처럼 쉼표 뒤에
  whitespace를 넣으면 여러 토큰이 되어 거절된다.
- 지시어 이름과 재질 이름은 대소문자를 구분한다.
- 알 수 없는 지시어와 정해진 개수보다 많거나 적은 토큰은 오류다.

`R`, `A`, `C`는 각각 정확히 한 번 필요하다. `L`, `sp`, `pl`, `cy`는 0개
이상일 수 있으므로 광원 0개와 도형 0개 장면도 파서 계약상 허용된다. 광원이
없으면 확산 표면은 환경광만 받고, 도형이 없으면 모든 주 광선이 배경색을
반환한다.

## 지시어 표

| 지시어 | 정확한 형식 | 개수 | 값 계약 |
| --- | --- | ---: | --- |
| `R` | `R width height` | 정확히 1 | 둘 다 1 이상 `INT_MAX` 이하의 십진 정수 |
| `A` | `A ratio r,g,b` | 정확히 1 | ratio는 유한한 `[0,1]`; 각 색 채널은 정수 `[0,255]` |
| `C` | `C x,y,z dx,dy,dz fov` | 정확히 1 | 위치·방향·FOV는 유한; 계산된 방향 길이는 `kEpsilon`보다 커야 하며 저장 전에 정규화; `0 < fov < 180` |
| `L` | `L x,y,z brightness r,g,b` | 0 이상 | 위치는 유한; brightness는 `[0,1]`; 색 채널은 `[0,255]` |
| `sp` | `sp x,y,z diameter r,g,b [material]` | 0 이상 | 중심은 유한; diameter는 유한한 양수 |
| `pl` | `pl x,y,z nx,ny,nz r,g,b [material]` | 0 이상 | 점·법선은 유한; 계산된 법선 길이는 `kEpsilon`보다 커야 하며 생성자에서 정규화 |
| `cy` | `cy x,y,z ax,ay,az diameter height r,g,b [material]` | 0 이상 | 중심·축은 유한; 계산된 축 길이는 `kEpsilon`보다 커야 하며 생성자에서 정규화; diameter와 height는 유한한 양수 |

`material`은 `diffuse` 또는 `metal`이다. 생략하거나 `diffuse`라고 쓰면 확산
재질, `metal`이라고 쓰면 난수·거칠기 없는 완전 반사 재질이다. 다른 토큰은
오류다.

지름과 높이의 parser 조건은 단순히 `> 0`이다. 기하 교차 코드는 반지름이나
높이가 `kEpsilon` 이하인 도형을 퇴화한 것으로 보고 교차하지 않을 수 있으므로
“파싱 성공”이 “모든 광선에서 가시적인 도형”을 뜻하지 않는다.

## 원자 토큰의 변환

실수는 `std::stod`, 해상도와 색 채널은 각각 `std::stoll`로 읽고 토큰 전체가
소비됐는지 확인한다. 실수 `NaN`과 양·음의 무한대는 거절한다. 과학 표기,
선행 부호와 선행 0은 표준 변환이 토큰 전체를 읽고 범위 조건도 만족하면
허용된다.

벡터와 색은 쉼표로 정확히 세 부분이어야 하며 빈 성분을 허용하지 않는다.
위치와 도형 크기에는 별도 크기 상한이 없고 유한성만 확인한다. 따라서 입력
토큰이 유한하더라도 이후 dot product, 제곱과 AABB 계산에서 `double` 범위를
넘어 inf 또는 NaN이 생기지 않는다는 보장은 없다. 파서가 제한하는 FOV와
해상도를 우회해 공개 카메라 API를 직접 호출할 때도 같은 전제를 별도로
확인해야 한다.

벡터 검사는 `std::hypot`으로 계산한 길이가 `kEpsilon`보다 큰지만 본다. 단순
제곱합보다는 중간 overflow에 강하지만, 성분은 각각 유한해도 실제 길이가
`double` 범위를 넘으면 결과가 `inf`일 수 있다. 이 비교는 `inf`를 통과시키고
그 뒤 유한 성분을 `inf`로 나눈 정규화 결과가 0벡터가 될 수 있다. 카메라는 렌더
때 기본 forward로 대체하고 평면·원기둥은 교차하지 않을 수 있으므로, “파싱
성공”이 “방향이 유효한 단위 벡터로 보존됨”까지 보장하지 않는다.

## 오류 위치와 완성 시점

`ParseError`는 표시용 `what()` 외에 `source()`와 `line()`을 보존한다.

- 특정 줄의 문법·중복·범위 오류: source와 1부터 센 줄 번호
- 파일 열기 실패와 `R`/`A`/`C` 누락: source와 line 0
- `what()`: line이 0보다 크면 `source:line: message`, 아니면
  `source: message`

파서는 지역 `Scene`에만 값을 추가한다. 문법·의미 오류나
`buildAcceleration()` 예외가 나면 호출자는 부분 장면을 받지 않고, 지역
장면이 소유한 `unique_ptr<Shape>`도 함께 정리된다. 필수 지시어를 확인하고
가속 구조까지 구축한 뒤에만 이동 전용 `Scene`을 반환한다.

이 원자성에는 두 한계가 있다.

- `getline` 루프 뒤 `badbit`을 별도로 확인하지 않으므로 필수 지시어를 이미
  읽은 후 발생한 비-EOF stream 실패를 정상 종료처럼 처리할 수 있다.
- 입력 byte, 줄 길이, 광원·도형 수의 별도 상한은 없다. 메모리 할당 실패는
  예외로 중단할 뿐 형식 수준의 resource limit가 아니다.

## 파서 밖의 기본값과 비범위

장면 배경색은 `(0.02, 0.03, 0.05)`로 생성되며 이를 바꾸는 지시어는 없다.
카메라의 up seed도 기본 `(0,1,0)`이고 장면 형식에서 지정하지 않는다.

텍스처, 유전체, rough metal, transform, mesh, 여러 샘플, gamma 설정을 위한
지시어는 없다. 파서를 거치지 않고 공개 C++ 생성자와 API를 직접 사용하면
해상도·색·방향·크기 검사를 우회할 수 있으므로 호출자가 같은 전제를 지켜야 한다.
