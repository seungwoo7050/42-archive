## chore(project): 빌드 산출물 제외
Ignore the server executables, object and dependency files, and runtime logs so the repository records source and configuration rather than machine-specific build products or transient execution output. Covering both executable names also keeps the ignore policy compatible with the project's current and legacy target names without requiring generated artifacts to be removed manually before each commit.

## feat(event): 이벤트 준비 상태 계약 정의
Introduce a platform-neutral event-management contract before binding the server to a specific operating-system API. `EventInterest` is a composable bitmask, so one descriptor can express read and write interest simultaneously, while `Event` reports readiness separately from error and hangup conditions. This distinction prevents upper layers from depending on `epoll` or `kqueue` flag layouts and gives them one semantic vocabulary for normal I/O and terminal conditions.

The abstract `EventManager` owns the add, update, remove, and timed-wait operations, and `createDefault()` returns the selected backend through `std::unique_ptr`. The resulting boundary makes backend lifetime explicit and establishes the invariant that platform-specific registrations and notifications must be translated into this common contract before the server loop acts on them.

## feat(event): kqueue 관심 상태 등록 구현
Implement the BSD/macOS registration side of the event abstraction by translating logical read and write interests into the independent `EVFILT_READ` and `EVFILT_WRITE` filters used by `kqueue`. A shadow map records the interests believed to be installed for each file descriptor, allowing updates to add or delete only the filters whose logical state actually changed rather than rebuilding every registration.

The backend owns the `kqueue` descriptor and closes it in its destructor, so the operating-system event resource follows object lifetime. Registration failures are surfaced as `std::system_error`; removal is deliberately idempotent, and cleanup tolerates `ENOENT` or `EBADF` when a watched descriptor has already disappeared. This establishes a practical lifecycle rule: the local interest map is updated only after the corresponding kernel change succeeds, while teardown may safely converge even when kernel state has already been removed.

## feat(event): kqueue 준비 이벤트 변환 구현
Complete the `kqueue` backend's wait path and make it constructible through `EventManager::createDefault()`. Millisecond timeouts are converted to `timespec`, with a negative timeout represented by a null pointer for an indefinite wait. An interrupted wait returns an empty event batch instead of turning signal delivery into a fatal server error, while other failures retain their operating-system error through `std::system_error`.

Each native `kevent` is translated into the platform-neutral `Event` contract: the descriptor identity is preserved, read and write filters become logical interests, and `EV_ERROR` and `EV_EOF` are exposed separately with their associated error data. The fixed native-event array bounds each individual wait result, and reserving the output vector to the returned count avoids needless reallocations. Upper layers can therefore consume readiness without knowing the `kevent` structure or flag conventions.

## feat(event): epoll 관심 상태 등록 구현
Add the Linux registration backend by mapping the common interest bitmask onto one `epoll` registration per descriptor. Error and hangup notifications are always requested, readable sockets additionally include `EPOLLRDHUP` when available, and write readiness is enabled only while the upper layer has pending output. This preserves the abstraction's semantics while respecting the fact that `epoll` stores all interests for a descriptor in a single mask rather than separate filters.

The backend creates its control descriptor with `EPOLL_CLOEXEC`, owns it through object lifetime, and keeps a shadow interest map so add, modify, and delete operations remain explicit and idempotent. Missing entries are promoted to adds, `None` becomes removal, and the map changes only after `epoll_ctl` succeeds. Cleanup tolerates descriptors already absent or closed, while other registration failures remain visible as `std::system_error` instead of leaving the server to operate on silently divergent kernel state.

## feat(event): epoll 준비 이벤트 변환 구현
Complete the Linux backend's wait path and expose it through the common factory. `epoll_wait` results are converted into the same descriptor, readiness, error, and hangup fields used by the `kqueue` implementation, including half-close detection through `EPOLLRDHUP` where the platform provides it. Because an `EPOLLERR` flag does not itself contain the pending socket error, the backend queries `SO_ERROR` and reports either that value or the `getsockopt` failure.

As with the other backend, signal interruption yields an empty batch while other wait failures propagate, and a fixed 128-entry native array bounds a single poll result. This commit makes the portability boundary operational on Linux: the server can select a backend at build time yet receive the same event representation and failure model on both supported event APIs.

## feat(connection): 스트림 연결 상태 계약 정의
Define a move-only `Connection` as the owner of one stream socket and all transport state coupled to that descriptor. Copying is prohibited to prevent double-close ownership, while move operations allow the connection to be transferred safely. Peer identity, the input accumulator, the output buffer and partial-write offset, the line-length limit, and local or remote closure state are kept together so socket lifetime cannot drift away from the buffers that describe its protocol progress.

`ReadResult` and `WriteResult` distinguish successful progress, temporary non-blocking backpressure, orderly peer closure, and hard errors instead of collapsing them into one return code. The public API also separates raw byte queuing from IRC line queuing and separates a requested graceful close from an observed peer close. These contracts give the future server loop enough information to decide when to retain write interest, when to drain output, and when connection removal is mandatory without exposing buffer internals.

## feat(connection): 소켓 소유권과 이동 수명 구현
Implement the ownership rules declared by `Connection`. Destruction closes the descriptor exactly once, and move construction transfers the descriptor, buffers, offsets, limits, and closure state before invalidating the source descriptor. Move assignment first releases any descriptor already owned by the destination, then performs the same transfer. This prevents both leaks and double closes when connection objects are relocated or replaced.

The constructor normalizes a zero line limit to the protocol default of 512 bytes, while `wantsWrite()` and `pendingBytes()` derive their answers from the write offset rather than treating the whole buffer as unsent. That representation is designed for partial non-blocking writes: bytes before the offset are already committed to the socket, and only the suffix remains part of the connection's pending-output invariant.

## feat(connection): IRC 입력 프레임 추출 구현
Add incremental IRC frame extraction over the connection's persistent read buffer. Newline is the framing delimiter, and an optional preceding carriage return is removed so both CRLF and LF-terminated input produce the same logical line. Multiple complete frames are emitted in order, while an incomplete suffix remains buffered for a later read instead of being mistaken for a complete command.

The maximum-line rule is enforced for both buffered fragments with no delimiter and completed frames including their newline. On violation, the method records a transport error, requests connection closure, and clears the accumulated bytes so oversized input cannot continue consuming memory or later be parsed as valid protocol data. Framing therefore becomes a connection-level responsibility, before command parsing, which keeps byte-stream concerns separate from IRC message semantics.

## feat(connection): 논블로킹 수신 상태 처리
Implement non-blocking receive as a drain loop rather than assuming one readiness notification corresponds to one IRC message or one `recv` call. Every successful read is appended to the persistent buffer and passed through frame extraction; the loop continues until the socket would block, the peer closes, framing rejects the input, or an unrecoverable error occurs. `EINTR` is retried because it does not describe connection failure, while `EAGAIN` and `EWOULDBLOCK` are reported as normal completion of the current readiness cycle.

An orderly zero-byte read records peer closure and requests cleanup, and hard receive failures preserve a human-readable operation error before requesting closure. The returned result may still contain lines extracted before the terminal condition, allowing the caller to observe all progress made during the callback while also receiving the exact lifecycle decision required for the connection.


## feat(connection): 부분 송신 대기열 처리
Implement output as a persistent queue whose progress is represented by `writeOffset_`, allowing a non-blocking socket to transmit only part of a message without duplicating or discarding bytes. `flushPending()` repeatedly sends the unsent suffix, retries interruption, and stops normally on backpressure; a hard send failure records the cause and requests connection closure. `MSG_NOSIGNAL` is used where available so a peer-side close is reported through the method's error result rather than terminating the process with `SIGPIPE`.

Completed queues are cleared and reset, while large consumed prefixes are compacted only after the offset exceeds 16 KiB. This avoids an erase on every partial write while preventing already-sent data from accumulating indefinitely. `queueLine()` strips any existing line terminators and appends exactly one CRLF, making outbound IRC framing canonical, whereas `queueRaw()` retains byte-for-byte control for transport-level responses. Close requests are stored as state rather than closing immediately, preserving the option to drain queued output before the server releases the socket.

## feat(server): 이벤트 서버 공개 계약 정의
Define the server as the owner and coordinator of the listening socket, portable event manager, and the map of active move-only connections. Configuration centralizes bind address, port, backlog, polling timeout, and line limit, while `std::unique_ptr` ownership makes it explicit that each accepted descriptor has one corresponding `Connection` object and that the event backend has one server-scoped lifetime.

The callback types establish the responsibility boundary between transport orchestration and IRC application behavior: the server reports accepted connections, complete input lines, disconnects, and infrastructure errors without embedding protocol state in the event loop. Public send, raw-queue, lookup, and disconnect operations allow application code to act on stable descriptor identities while leaving buffering and event-interest changes inside the server. Separating `start`, `run`, `pollOnce`, and `stop` also permits both a normal blocking runtime and deterministic single-iteration testing.

## feat(server): 서버 수명과 콜백 상태 구현
Implement the server's initial lifecycle state and callback ownership. Construction records configuration without opening resources, destruction first requests termination and then releases all connections before closing the listening socket. That cleanup order keeps descriptor-owning `Connection` objects and their application-visible disconnect state within the server's lifetime rather than relying on process exit to reclaim sockets.

`stop()` is deliberately non-throwing and changes control state rather than performing ad hoc teardown from an arbitrary call site. Handlers are moved into the server so the event loop has one authoritative callback set, and read-only accessors expose runtime state without transferring ownership. This commit therefore establishes the lifecycle skeleton on which socket creation and event dispatch can be added without changing who owns resources or application callbacks.

## feat(server): IPv4 리스닝 소켓 구성
Implement listener creation as a staged, exception-safe operation. The socket is marked close-on-exec and non-blocking before it becomes visible through `listenFd_`, `SO_REUSEADDR` supports prompt rebinding after restarts, and the platform-specific `SO_NOSIGPIPE` option complements per-send signal suppression on systems that provide it. The configured bind address is parsed explicitly as IPv4, so malformed configuration is rejected before `bind` rather than being interpreted through name resolution.

All setup steps run while the descriptor is still a local variable; any failure closes it and rethrows, and ownership is committed to the server only after `listen` succeeds. Port zero is supported by querying the kernel-assigned port with `getsockname`, which preserves the externally observable configuration and enables isolated tests without hard-coded port coordination. This establishes the listener invariant that a non-negative `listenFd_` denotes a fully configured, listening, non-blocking socket.

## feat(server): 논블로킹 연결 수락과 등록 구현
Drain the listening socket after a read-ready notification, accepting clients until `EAGAIN` or `EWOULDBLOCK` proves that the current accept queue is exhausted. Interrupted accepts are retried, whereas other accept failures are reported without terminating the whole server. Each accepted descriptor receives the same close-on-exec, non-blocking, and signal-suppression policy as the listener before it is wrapped in a descriptor-owning `Connection`.

The new connection is registered for read readiness, inserted into the server's authoritative connection map, and only then exposed to the application callback. Callback exceptions are contained at the connection boundary: they are reported and converted into a close request rather than unwinding the event loop. Rechecking map membership before refreshing interests anticipates callbacks that may disconnect the client, preventing the server from blindly acting on an object whose logical registration may already have been removed. Peer-address formatting is kept observational and falls back to `unknown` rather than making address presentation a prerequisite for accepting a valid socket.

## feat(server): 준비 이벤트 루프 구동
Connect listener setup, the portable event backend, and per-descriptor dispatch into an operational server loop. `start()` creates the backend, opens the listener, registers read interest, and marks the server running; `run()` repeatedly delegates one wait cycle to `pollOnce()` and performs centralized resource teardown when termination is requested. Keeping `pollOnce()` public preserves the same production dispatch path while allowing tests or embedding code to advance the server deterministically one iteration at a time.

Listener and client events are separated by descriptor identity. A listener error is treated as a server-level failure because no new connections can be accepted reliably, while readable listener events drain pending accepts and all other descriptors are delegated to client handling. The loop checks `stopRequested_` between returned events so a callback-triggered stop prevents additional callbacks from the same stale readiness batch. Calling `pollOnce()` before startup is rejected as a lifecycle error, making event dispatch contingent on a live backend and registered listener.

## feat(server): 클라이언트 입력 이벤트 전달
Implement the client read-dispatch boundary from portable readiness events to complete IRC lines. Unknown descriptors are ignored because a returned readiness batch can outlive a connection removed by an earlier callback. Socket-level event errors disconnect immediately; otherwise a readable connection is drained through `Connection::readAvailable()`, and every successfully framed line is delivered in order before an observed peer close becomes a close request.

Application callbacks are contained so an exception becomes a reported error and a connection-local close request rather than escaping the server loop. After each callback the connection map is checked again, because application code is allowed to disconnect the current client; this avoids continuing through a stale `Connection*`. Processing also stops once closure is requested, preventing later lines from the same read batch from mutating protocol state after a terminal command or failure. The final interest refresh is therefore performed only for a connection that remains server-owned.

## feat(server): 송신 큐와 쓰기 관심 상태 연결
Link connection-local output buffering to kernel write readiness. `sendTo()` and `queueRawTo()` now append data only for currently registered clients and immediately recompute that descriptor's event interests, so queued output cannot remain dormant while the server waits only for reads. On a write-ready event, the server drains as much of the queue as the non-blocking socket accepts and converts a hard send failure into normal connection cleanup.

`refreshInterest()` becomes the single policy function for readiness state. Healthy connections always retain read interest and add write interest only while bytes are pending; once closure is requested, new input is suppressed and only write readiness remains until the queue is drained. A closed connection with no pending bytes is disconnected immediately. This establishes the graceful-close invariant that previously queued protocol output is given an opportunity to leave, without busy-polling writable sockets that have nothing to send.

## feat(server): 연결 해제와 오류 정리 구현
Centralize connection removal so event registration, ownership, and application notification transition together. `disconnect()` first attempts to remove the descriptor from the event backend, then moves the `Connection` out of the authoritative map and erases the entry before invoking the disconnect callback. The local `unique_ptr` keeps the object alive for notification, while erasing first makes recursive lookup or repeated disconnect observe that the connection is already gone. Backend-removal and callback exceptions are reported but do not prevent descriptor destruction.

Hangup is treated as terminal once no output remains, while a pending queue may still be drained through the existing write path. Listener cleanup unregisters before closing and is idempotent; bulk shutdown snapshots descriptor keys before disconnecting them, avoiding iterator invalidation as callbacks and map erasure occur. The lookup helpers expose non-owning access only while an entry remains present, and error reporting is routed through the configured handler. Together these operations establish one cleanup path for explicit disconnects, peer termination, I/O failure, and server shutdown.

## feat(parser): IRC 메시지 값과 직렬화 정의
Introduce an explicit IRC message value that separates optional prefix, normalized command, ordered parameters, and the original frame text. Commands are uppercased at construction and comparison time, making dispatch case-insensitive without requiring every caller to normalize independently. Safe indexed access with a fallback lets command handlers express optional parameters without exposing unchecked vector indexing.

`toLine()` provides the inverse representation needed for generated protocol messages: it emits an optional prefix, command, parameters, and a terminating CRLF, using the IRC trailing-parameter marker when a value is empty, contains spaces, or begins with a colon. Retaining both structured fields and `raw` text supports semantic handling while preserving the exact parsed content for diagnostics. The class also declares line and buffer parsing at the same boundary, making this type the authoritative translation point between IRC wire syntax and application-level command data.

## feat(parser): IRC 한 줄 구문 해석 구현
Implement deterministic parsing of one IRC frame into the message value. Transport terminators are removed first, the protocol's 510-octet pre-CRLF limit is enforced, and an optional prefix is accepted only when a non-empty prefix is followed by command text. The parser then normalizes the command to uppercase, splits middle parameters on spaces, and treats a colon-prefixed parameter as the trailing field that consumes the remainder verbatim, including embedded spaces.

The output object is reset before parsing and retains the trimmed raw frame, so failed calls cannot accidentally leave structured fields from an earlier message. Empty input, malformed prefix syntax, a missing command, and oversized frames return explicit diagnostic text through the optional error channel. This keeps syntax rejection in the parser while allowing callers to choose how protocol errors affect connection policy.

## feat(parser): 버퍼에서 IRC 프레임 소비
Add incremental parsing for callers that accumulate raw socket data outside `Connection`. Complete newline-terminated frames are removed from the front of the buffer and parsed independently; valid messages are returned in order, while a malformed frame is discarded and reported without preventing later complete frames in the same buffer from being examined. An incomplete final frame remains untouched for the next receive cycle.

A 4 KiB cap on an unterminated remainder bounds memory growth when a peer never supplies a delimiter. Exceeding that cap reports the discard and clears the fragment, restoring the buffer to a known framing boundary. `trimFrame()` centralizes removal of CR and LF suffix bytes so direct line parsing and buffered consumption share the same frame-normalization rule.

## feat(reply): IRC 서버 응답 생성
Add a dedicated response-construction layer so command handlers do not assemble wire syntax independently. Numeric codes are rendered as three digits, numeric replies always place the recipient first and substitute `*` when no nickname is available, and all formatted messages terminate with CRLF. Only the final parameter may receive the trailing marker, matching IRC's distinction between middle parameters and the one field allowed to contain spaces.

The helpers also standardize `ERROR` messages and user hostmasks. Missing user or host components receive explicit fallbacks, allowing registration and early-error paths to produce syntactically complete prefixes before all identity fields exist. Centralizing these rules reduces differences among handlers and establishes one formatting boundary for server-generated protocol output.

## feat(channel): 채널 상태 계약 정의
Define `Channel` as the authoritative aggregate for membership, operator privilege, invitations, topic state, and the supported `+i` and `+t` modes. Integer client identifiers link channel state to the server's connection registry without transferring connection ownership, while set-backed membership and operator collections guarantee uniqueness. Invitations are stored by canonicalized nickname because they authorize an identity that may not yet be a channel member.

The public operations keep state transitions behind the aggregate rather than exposing the containers directly: callers can add or remove membership, grant operator status, mutate topic and modes, consume invitations, and request a snapshot of members. Static channel-name and nickname-normalization helpers place protocol identity rules alongside the state whose keys depend on them. This boundary is necessary for command handlers to preserve relationships such as operator status being meaningful only for current members.

## feat(channel): 구성원과 운영자 상태 관리
Implement the core membership invariant that every operator must also be a channel member. Adding a member may atomically confer initial operator status, removing a member always removes the corresponding operator entry, and later privilege changes are ignored for non-members. These rules prevent the two sets from diverging through ordinary channel operations.

Membership uses sets, so duplicate joins and repeated removals are naturally idempotent, and the exported member vector has deterministic key order. New channels start open to joins, with topic changes protected by default and no active topic. The implementation therefore supplies predictable baseline state while keeping all privilege transitions subordinate to membership.

## feat(channel): 주제·초대·모드와 이름 규칙 구현
Complete the channel's non-membership state transitions. Topic presence is tracked separately from topic text, so an explicitly empty topic can still be distinguished from no topic; invite-only and topic-protection flags have direct query and mutation operations; and invitations are inserted, checked, and removed through one lowercase canonical form. Repeated invitations and removals remain idempotent because the underlying representation is a set.

Channel names are accepted only when they begin with `#` or `&`, contain at least one following character, and exclude whitespace, commas, and the bell character that conflict with IRC channel-list syntax. `modeString()` derives the externally reported mode sequence from authoritative booleans rather than storing a second textual representation. These rules keep protocol presentation and authorization decisions synchronized with the channel's internal state.

## feat(config): 기본 실행 인자 해석 모듈 구성
Introduce a runtime-configuration object distinct from the transport server's bind configuration. It establishes initial policy values for command-rate limiting, idle and ping timeouts, and registration timeout, creating a single place where later option parsing can alter operational behavior without spreading constants through application code.

Port parsing uses `strtol` with complete-consumption and range checks, rejecting empty, fractional, trailing, zero, negative, and out-of-range values before they reach the socket layer. The initial option parser deliberately accepts only the required `<port> <password>` shape and reports the first extra argument as unknown, while the usage helper defines that external command-line contract. This first version is a scaffold: it records defaults and validation boundaries without yet mutating `Server::Config` from optional flags.

## feat(client): 연결별 등록 상태 저장
Add a registry that separates IRC identity and registration progress from transport-owned `Connection` objects. Each descriptor-keyed `ClientState` records password acceptance, nickname and user completion, final registration, and the identity fields needed for replies and hostmasks. Keeping these flags explicit allows registration to be modeled as a multi-command state transition rather than inferred repeatedly from non-empty strings.

`state()` provides create-on-first-access semantics, while `find()` and `contains()` support read paths that must not create phantom clients. Erasure is idempotent, and exporting descriptor keys as a value snapshot permits safe iteration when later operations may remove registry entries. The ordered map also gives deterministic traversal, with the map key serving as the authoritative descriptor association until the state's `fd` field is populated by connection setup.

## feat(client): 닉네임 색인 관리
Add a reverse nickname index so identity lookup is no longer a linear scan through all client states. Both insertion and lookup use the same canonicalization function as channel invitations, making nickname references case-insensitive across client and channel subsystems. The registry preserves the user's presented spelling in `ClientState` while using the canonical form solely as the uniqueness and lookup key.

Changing a nickname removes the previous key before installing the new one, and erasing a client removes both the descriptor-owned state and its reverse mapping. This establishes the two-index consistency requirement that every stored nickname mapping must point to the descriptor whose state currently carries that nickname. Collision policy remains the caller's responsibility: command validation must reject an occupied canonical key before invoking `setNickname()`.

## feat(app): IRC 동작 조율 계약 정의
Define `IrcApplication` as the protocol coordinator between the transport server and domain state. The server remains responsible for descriptors, buffering, and readiness, while the application owns password policy, runtime limits, client registration state, command dispatch, reply construction, and protocol-aware cleanup. Its public surface matches the server's connect, line, and disconnect callbacks, keeping transport events from leaking directly into individual command handlers.

Private handlers separate registration commands and connection controls from shared concerns such as registration completion, reply targeting, hostmask creation, numeric formatting, raw sends, close requests, and client-state removal. This establishes one orchestration boundary through which later channel and messaging behavior can access consistent identity and lifecycle rules instead of coupling directly to `Server` internals.

## feat(app): 연결 수명 콜백 조율
Connect transport callbacks to protocol-state creation, parsing, dispatch, and removal. On acceptance, the application creates a descriptor-keyed client record, derives the initial host from the connection's peer address, and marks password authorization complete only when the configured password is empty. This makes transport acceptance distinct from IRC registration: a connected client still progresses through PASS, NICK, and USER state before becoming registered.

Each delivered line is parsed exactly once at the application boundary. A missing registry entry is reconstructed defensively, malformed syntax receives numeric 417 without entering command dispatch, and valid messages are forwarded as structured values. Disconnect callbacks delegate to the same protocol cleanup path used by explicit quits, allowing nickname indexes and later channel memberships to be removed regardless of whether termination originated in the protocol or the socket layer.

## feat(app): 등록 전 명령 분배 구현
Establish registration-aware command dispatch. PASS, NICK, USER, PING, and QUIT are routed regardless of registration state because they either construct the registration state machine or maintain and terminate the underlying connection. Any other command is rejected with numeric 451 until registration completes; after registration, an unsupported command receives numeric 421 with the normalized command name.

This ordering makes the registration gate an application-level authorization boundary rather than a parser concern. Syntax can be valid while the client's lifecycle state still forbids the operation, and the dispatcher supplies the protocol-specific distinction between “not registered” and “unknown command.” Centralizing the gate also prevents individual post-registration handlers from inconsistently deciding whether premature use is allowed.

## feat(app): 응답과 클라이언트 정리 지원 구현
Implement the shared application services required by command handlers. Numeric targets fall back to `*` before a nickname exists, user prefixes fall back to the server name before client identity is usable, and registered identities are rendered as hostmasks through the reply formatter. Both trailing-text numerics and parameter-only numerics are supported so handlers can preserve the protocol shape of different reply families.

All outbound protocol text is funneled through the server's queued send path, preserving non-blocking delivery and canonical line termination. Close requests update the live `Connection` rather than destroying it immediately, allowing the server's graceful-drain policy to apply. Client cleanup initially removes the registry and nickname-index entry through one method; its reason and peer-notification parameters reserve the same boundary for later channel and broadcast cleanup without duplicating erasure logic.

## feat(registration): PASS 인증 상태 처리
Implement PASS as one irreversible stage of the registration state machine. A client that is already registered or whose password stage has already succeeded cannot submit PASS again, preventing credential state from being rewritten after identity establishment. Missing credentials receive numeric 461, while an incorrect configured password receives numeric 464 and requests connection closure.

Only a matching password—or the empty-password authorization established at connect time—sets `passOk`. The handler then invokes `maybeRegister()` rather than marking the client registered directly, preserving the invariant that password acceptance, nickname selection, and USER information must all be complete before the final registration transition and welcome replies occur.

## feat(registration): 닉네임 검증과 색인 갱신
Implement NICK validation before mutating the registry's reverse index. Nicknames must be non-empty, at most 30 characters, cannot begin with a digit or channel/prefix punctuation, and reject whitespace and separators that conflict with IRC addressing syntax. Failure is distinguished between a missing nickname, syntactically erroneous input, and a canonical nickname already owned by another descriptor through numerics 431, 432, and 433.

Collision lookup occurs before `setNickname()`, satisfying the registry's caller-enforced uniqueness contract. The same descriptor may retain or change to an equivalent canonical nickname, while another descriptor cannot claim that identity with different letter casing. After a successful update, registration is reevaluated rather than forced, so NICK remains one independent prerequisite in the PASS/NICK/USER state machine.

## feat(registration): USER 정보와 환영 응답 연결
Implement the USER stage and the single transition into registered state. USER is rejected after registration, requires the protocol's four parameters, and stores the username and trailing real name before marking that stage complete. `maybeRegister()` checks all three prerequisites—password authorization, nickname, and user data—and returns harmlessly when called early or repeatedly.

Once every prerequisite is true, the method marks the client registered before queueing welcome numerics 001, 002, and 003. Updating the state first prevents reentrant or repeated registration checks from sending duplicate welcome sequences. Registration therefore becomes an explicit monotonic transition rather than a condition inferred independently by every command handler.

## feat(registration): PING과 QUIT 기본 명령 처리
Add connection-maintenance commands that remain valid before full registration. PING requires an origin token and returns numeric 409 when it is missing; a valid request produces a server-prefixed PONG containing both the server name and the supplied token, allowing clients to correlate liveness responses.

QUIT records either the client's supplied reason or a stable default and requests graceful closure through the transport layer. It does not close the descriptor inside command dispatch, so any already queued output follows the server's normal drain-and-disconnect lifecycle, and the eventual disconnect callback remains responsible for authoritative protocol-state cleanup.

## feat(server): IRC 애플리케이션 실행 진입점 구성
Add the process-level composition root that turns the previously separate transport and protocol components into an executable server. Command-line validation constructs `Server::Config` and `RuntimeConfig`, the `Server` is created before the `IrcApplication`, and the server callbacks are bound to the application's connection, line, and disconnection entry points. This keeps dependency direction explicit: the application depends on the server interface, while `main` alone decides how their lifetimes and callbacks are connected.

The polling loop uses an interruptible process flag and `Server::pollOnce()` rather than hiding execution inside an unobservable blocking call. SIGINT and SIGTERM request the same orderly stop path as normal shutdown, and SIGPIPE is ignored at process level in addition to the per-send socket protections so a closed peer cannot terminate the server. Before leaving the scope, all callbacks are cleared so server teardown cannot invoke lambdas that reference an application object whose lifetime is ending. Startup and runtime exceptions are converted into a nonzero process result with diagnostic output, establishing one failure boundary around configuration, socket setup, and event processing.

## build(project): 플랫폼별 IRC 서버 빌드 구성
Introduce the reproducible build contract for the complete executable. ## fix(heartbeat): 단조 시계와 토큰으로 응답 대기 상태 관리
Move all elapsed-time state from wall-clock `std::time_t` values to `std::chrono::steady_clock` time points. Connection age, last activity, heartbeat deadlines, and command-window entries now share a monotonic clock, and comparisons use explicit `std::chrono::seconds` durations. System time corrections can therefore no longer make registration or ping deadlines run backward, expire prematurely, or retain stale rate-limit entries.

Strengthen the heartbeat exchange from a Boolean acknowledgement to a correlated challenge-response. Each emitted PING receives a process-local increasing token, the exact token is stored in `ClientState`, and PONG clears `awaitingPong` only when it contains exactly one parameter equal to that pending value. Unsolicited, malformed, stale, or unrelated PONG messages are ignored, so only a response to the current challenge proves liveness. Clearing the token and timestamp together preserves the invariant that an idle client is either not awaiting a response or has one identifiable outstanding probe with a monotonic send time.

The same monotonic timestamp captured for an input line remains the source for activity and command-rate accounting, retaining the earlier single-observation-time decision. This commit therefore corrects both clock selection and protocol-state correlation at their shared per-client state boundary instead of adding special cases to timeout handling.

## test(heartbeat): PONG 토큰과 시간 경계 검증
Disable automatic heartbeat replies for dedicated contract peers so the test controls the response state explicitly. For a valid case, it captures the exact token from the server's PING, echoes that token in PONG, waits across multiple one-second intervals, and continues issuing METRICS successfully. This demonstrates that a correlated response clears the outstanding ping deadline and the connection remains usable after the original challenge would otherwise have aged toward timeout.

A second peer sends a syntactically valid PONG carrying an unrelated token. The test requires the server to retain the pending challenge, emit `ERROR :Ping timeout`, and close the connection. Because receipt of the forged line still refreshes ordinary activity state, this scenario specifically proves that heartbeat completion depends on token correlation rather than generic traffic or the presence of any PONG command.

## fix(connection): 송신 대기열 계산과 재시도 상태 보호
Make outbound-capacity checks overflow-safe by expressing admission as `pending <= limit` and `byteCount <= limit - pending` instead of adding untrusted sizes before comparison. `queueLine()` applies the check first to the normalized payload and then to the two CRLF bytes, so neither `pending + payload` nor `payload + 2` can wrap around and incorrectly admit data beyond the configured hard limit. Rejected appends continue to request closure without mutating already queued output.

Introduce an injectable send operation while retaining the real `send()` syscall as the production default. The operation moves with the connection's other owned state, allowing the write state machine to be exercised deterministically without changing its public result contract. `flushPending()` now also rejects a positive result larger than the requested byte count before advancing the offset. Although a conforming kernel cannot return that value, guarding the boundary prevents an invalid transport implementation or test double from moving the cursor beyond the buffer and turning subsequent pending-byte arithmetic into underflow.

Together, these changes protect both sides of the queue invariant: capacity arithmetic cannot wrap before bytes are appended, and send progress cannot advance beyond bytes actually offered. EINTR, would-block results, zero progress, and terminal errors continue to preserve the unsent suffix for the existing retry or close path.

## test(connection): 부분 송신과 대기열 경계 검증
Add a focused C++ test executable for the connection write state machine and integrate it into the default `make test` path before the real-server smoke suite. A scripted sender supplies an exact sequence of byte counts and errno results, allowing each transition to be asserted without depending on socket buffer pressure or scheduler timing. The test binary is treated as a generated artifact by cleanup and ignore rules.

Boundary tests exercise capacity arithmetic at `std::size_t` maximum, exact-limit line admission including canonical CRLF, rejection of the first excess byte, and preservation of the existing queue after rejection. The scripted partial-send scenario combines EINTR retry, successful prefixes, EAGAIN and EWOULDBLOCK pauses, capacity reuse after progress, and final completion. It verifies that pending counts exclude only bytes actually sent and that the reconstructed output is exactly `abcdefghijkl`, with no duplication, omission, or reordering across writable events.

Separate cases establish that a zero-byte send consumes nothing and remains retryable, a terminal EPIPE reports failure and requests closure without discarding pending data, and an impossible result larger than the requested buffer is rejected without corrupting the offset. These checks lock down the central non-blocking transport invariant: every queued byte remains accounted for until one successful send reports that exact portion as transferred.

## fix(server): 연결 콜백 수명과 이벤트 등록 롤백 보장
Rework server-side connection access around descriptor-based lookup rather than retaining raw pointers or references across application callbacks. Connect, line, disconnect, and error handlers are externally supplied code and may synchronously remove the current connection or throw. After each such boundary, the server now resolves the descriptor again before requesting closure, continuing event processing, or updating readiness interests. This prevents a callback-triggered `disconnect()` from leaving the event loop with a dangling `Connection*` while preserving the callback API itself.

Make connection ownership and event registration an explicitly rolled-back transition. An accepted `Connection` is first inserted into the owning map; if registering its descriptor with the event backend fails, erasing that map entry releases the socket through RAII. Listener registration receives the same treatment during startup: a failed `addFd()` closes the listener, discards the unusable event manager state, and rethrows instead of leaving a partially started server. Duplicate accepted descriptors are treated as a logic error rather than silently replacing an owned connection.

Change readiness refresh to accept an fd, re-fetch the currently owned connection, and return whether the transition completed. A failed `updateFd()` is reported and converges on the ordinary disconnect path, while `sendTo()` and `queueRawTo()` expose that failure to callers instead of claiming that queued output is deliverable without write interest. Error reporting is made `noexcept` and contains exceptions thrown by the error callback so diagnostic code cannot interrupt cleanup. These changes establish the invariant that the connection map, event-manager registration, and descriptor lifetime either advance together or are torn down together, even under reentrant callbacks and backend failures.

## test(server): 연결 제거와 이벤트 등록 실패 경로 검증
Add a deterministic server-lifetime test built around an injected `FakeEventManager` and real loopback TCP clients. The fake backend records descriptor interests, can fail the next add or update operation, and can deliver selected readable events without relying on the host event queue. This isolates lifecycle behavior that is difficult to reproduce reliably with epoll or kqueue timing while still exercising the server's actual listener, accept, connection, and callback code.

The suite verifies five failure contracts. A failed event registration after `accept()` must leave neither a map-owned connection nor a backend descriptor. A connect callback and a line callback may each disconnect their own connection and then throw without causing later access to freed state. An exception from the error handler must remain contained. A write-interest update failure must make `sendTo()` fail and remove both ownership and event registration. Finally, exceeding the outbound queue limit must complete the requested close immediately when no bytes remain to drain.

Integrate the test as a separate build target in the default test pipeline and remove its binary during cleanup. Running it before the end-to-end smoke suite gives direct regression evidence for the map/event-registry consistency and callback-reentrancy invariants introduced in the server fix, rather than depending on a crash or leaked descriptor to appear nondeterministically in a broader scenario.

## fix(app): 응답 실패 뒤 클라이언트 상태 다시 확인
Treat response delivery as a possible application-lifecycle transition instead of an infallible side effect. `Server::sendTo()` can now fail while refreshing event interest and may synchronously disconnect the target; the disconnect callback then removes client records, channel memberships, and possibly entire channel aggregates before the sending handler resumes. Response helpers therefore return success, and multi-frame paths stop after the first failed enqueue rather than continuing to read state that the failure may already have erased.

Harden the command sequences that retain application state across broadcasts or replies. JOIN copies the requested channel name and nickname, rechecks the client after fan-out, and resolves the channel again before topic and NAMES replies. KICK and PART similarly cache stable identifiers and re-find the channel after broadcasting before mutating membership. NICK verifies that the source client still exists after notifying common peers. Registration caches the nickname and emits 001, 002, and 003 sequentially, logging completion only if all three responses were accepted. INVITE constructs both outbound frames from cached values before either send can trigger cleanup.

Heartbeat state is committed before queuing its PING, because setting fields after a failed send would write through a client pointer that may no longer be valid. The heartbeat metric advances only after the frame is accepted. Topic and NAMES helpers also copy the channel name and propagate failure, with NAMES suppressing its terminating 366 when the preceding 353 could not be queued. The change does not make transport failure transactional—earlier state changes or already queued frames are not rolled back—but it establishes the required reentrancy rule: after any send that can synchronously remove application state, code must either return or re-resolve every client, channel, and connection object it intends to use.

## test(app): 작은 송신 한도에서 상태 정리 검증
Add an application-lifetime regression that forces response enqueueing to fail during registration. The test composes the real `Server` and `IrcApplication` with a controllable event manager and a loopback client, but configures `maxPendingBytes` to one byte—too small for the first welcome numeric. Supplying NICK and USER therefore reaches the registration transition and then deterministically exercises the synchronous queue-rejection path without depending on socket pressure.

The expected outcome is complete connection removal while the server remains running. Standard error is captured to require that `client_registered` is not emitted after the failed response, proving that the application does not continue through the 001–003 sequence or record a completed lifecycle transition after its client state has been erased. The test thus distinguishes a contained per-client output failure from a server-wide failure and locks down the ordering between response acceptance, registration observability, and cleanup.

Build the test against all production application sources except `main`, run it in the default test target, and clean its generated binary alongside the existing transport and server-lifetime tests. This gives the reentrant-send fix direct coverage at the application boundary rather than inferring safety solely from lower-level connection tests.

## test(event): 160개 연결과 느린 수신자 처리 공정성 검증
Add a real-process event-loop regression covering both simultaneous descriptor progress and isolation from a non-reading recipient. The first scenario opens 160 TCP connections, sends a distinct pre-registration PING from every peer, and uses the client's platform-default selector to collect all exact PONG responses under one deadline. This verifies that the epoll or kqueue backend continues registering and dispatching a connection set well beyond the handful used by the functional smoke suite, without losing descriptor-specific readiness or confusing responses between peers.

The second scenario registers a sender, a probe, and a recipient whose receive buffer is deliberately small and which stops reading. The sender directs 4,096 large PRIVMSG frames to that slow client, creating sustained outbound pressure on one connection. An unrelated probe then sends PING and must still receive its PONG. The property under test is isolation: a socket that reaches non-blocking backpressure must retain its own pending output rather than blocking the single event loop and preventing unrelated connections from advancing.

Run the server with explicit high command, connection, and pending-byte limits so the exercise measures event and buffering behavior rather than tripping protective defaults. Use monotonic deadlines, exact frames, bounded process termination, and log disclosure on failure. This remains a correctness stress test rather than a throughput benchmark—it establishes eventual progress for all 160 peers and for an unrelated connection under slow-reader pressure, but does not claim a latency distribution or maximum capacity.

## fix(app): 응답 실패 뒤 명령 처리를 중단
Complete response-failure propagation in the channel commands that emit variable-length sequences. LIST now stops if its opening 321 or any per-channel 322 cannot be queued, and NAMES stops after any failed channel projection or terminating 366. Returning immediately is required because a failed response can synchronously disconnect the requesting client; that cleanup may remove memberships and erase channels, invalidating the map iterator that a loop would otherwise increment on its next iteration.

Apply the same rule inside compound MODE processing. Cache the channel name before any response, require every mode broadcast and recoverable error numeric to succeed before continuing to the next mode character, and obtain a target client through a non-inserting lookup before copying its nickname. Operator changes still mutate the channel before their notification, but a failed broadcast terminates the command rather than reusing a potentially erased channel or client object. Query-only and final replies need no continuation check because the handler returns immediately afterward.

This change closes the remaining gap left by the earlier application-lifetime hardening: response helpers already reported failure, but LIST, NAMES, and the MODE loop ignored that signal while retaining iterators or pointers. The resulting contract is consistent across multi-step handlers—once output failure can have triggered disconnect cleanup, no further command step may execute unless all state it needs is known to remain valid.

## test(app): 연결 정리 뒤 모드 변경 중단 검증
Extend the application-lifetime suite with a white-box regression for a compound MODE command whose first notification removes the command sender. Two real server connections are accepted, then the test constructs registered client records and a shared `#room` aggregate directly so it can isolate mode-loop behavior without an unrelated registration transcript. The fake event manager is configured to fail the next interest update only for the operator's descriptor.

Processing `MODE #room +it` first applies invite-only mode and attempts to broadcast `+i`. The injected update failure causes the sender to be disconnected synchronously during that broadcast, invoking normal application cleanup. The test requires the channel to remain because the unrelated peer is still a member, the already applied `+i` state to remain, the sender's client state to be gone, and the peer to remain intact. Most importantly, topic protection must still be disabled, proving that the handler stopped before interpreting the later `t` character.

This captures the chosen failure semantics precisely. Compound mode processing is not rolled back as an atomic transaction—changes completed before transport failure remain authoritative—but no subsequent transition may run after the actor and its borrowed state have been removed. Targeted event-backend failure makes that lifecycle boundary deterministic and protects against reintroducing the stale-channel-pointer continuation that the preceding fix eliminated.

## ci: Linux·macOS 회귀와 새니타이저 자동화
Add a GitHub Actions workflow that runs the repository's complete build and regression pipeline for every push and pull request with read-only repository permissions. A non-fail-fast matrix executes on both Ubuntu and macOS, compiling with the project's warning-as-error defaults before running `make test`. This validates not only ordinary C++ portability but both platform-specific readiness implementations: epoll is exercised on Linux and kqueue on macOS through the same unit, contract, smoke, and event-fairness targets.

Add a separate Linux job that rebuilds with AddressSanitizer and UndefinedBehaviorSanitizer, frame pointers, debug information, and modest optimization. Leak detection, immediate ASan termination, UBSan stack traces, and halt-on-error settings turn memory leaks, invalid lifetime access, buffer misuse, integer undefined behavior, and related defects into job failures while the same real-network regressions execute. Passing the compiler flags to both the build and test invocations keeps generated test executables under the same instrumentation as the server.

Each job has a bounded timeout so a deadlocked event loop, failed shutdown, or stalled network test cannot consume an unbounded runner. The workflow therefore converts the project's portability, ownership, non-blocking I/O, and lifecycle assumptions from local expectations into repeatable checks across the two supported operating-system backends and under dynamic memory and undefined-behavior analysis.
