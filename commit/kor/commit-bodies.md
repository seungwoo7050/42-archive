## build(shell): C99 실행 골격 구성
셸을 C99 프로그램으로 빌드하기 위한 최소한의 재현 가능한 빌드 경계를 구성한다.

Makefile은 컴파일과 링크 단계를 분리하고, 환경에 따라 재정의할 수 있도록 컴파일러·전처리기·링커·라이브러리 변수를 노출한다. 기본적으로 `-Wall`, `-Wextra`, `-Wpedantic`을 활성화한다. 실행 파일 이름과 소스 목록을 명시하며, 생성되는 바이너리·오브젝트·의존성 파일·임시 검증 산출물은 버전 관리에서 제외한다.

초기 진입점에는 의도적으로 동작을 넣지 않고 POSIX.1-2008 기능 수준만 선언한다. 런타임 상태나 입력 처리를 추가하기 전에 툴체인, 언어 모드, 실행 파일 계약이 제대로 갖춰졌음을 확인하는 것이 목적이다. 첫 코드 커밋부터 빌드 가능한 골격을 유지하면 이후 각 하위 시스템을 독립적으로 통합할 수 있는 안정적인 기준점이 생긴다.

## feat(input): 표준 입력 반복과 EOF 처리 연결
셸의 첫 번째 명령 입력 수명을 정의한다. 한 줄 전체를 할당해 루프에 소유권과 함께 반환하고, 다음 명령을 읽기 전에 해제한다.

대화형 모드는 표준 입력과 표준 오류가 모두 터미널일 때만 활성화한다. 프롬프트는 표준 출력이 아니라 표준 오류에 기록해, 표준 출력은 향후 명령 결과와 파이프라인 데이터에 사용할 수 있도록 비워 둔다. 기본 입력기는 버퍼를 기하급수적으로 확장하면서 개행에서 읽기를 멈춘다. 데이터가 있는 상태에서 EOF에 도달하면 개행 없이 끝난 마지막 줄도 보존하고, 데이터가 전혀 없는 EOF에서는 루프를 종료한 뒤 터미널에서 관례적으로 출력하는 개행을 기록한다.

초기 API는 입력 종료와 메모리 할당 또는 스트림 실패 모두에 NULL을 반환한다. 루프와 소유권 경계를 정의하기에는 충분하지만, 정상적인 EOF와 실행 중 오류를 호출자가 구분할 수는 없다. 이후 입력 처리 강화 과정에서 두 경우를 분리한다. 이 단계에서는 파싱을 수행하지 않으므로, 명령 의미를 연결하기 전에 입력과 정리 동작을 먼저 확정한다.

## build(input): 선택적 readline 입력 경로 제공
Readline을 필수 런타임 또는 빌드 의존성으로 만들지 않으면서 선택적인 대화형 입력 백엔드를 추가한다.

기본 타깃은 기존의 표준 I/O 입력기를 계속 컴파일한다. 전용 `readline` 타깃으로 빌드하면 `USE_READLINE`을 정의하고 `libreadline`을 링크하며, 이 경우에도 대화형 입력에만 `readline`을 사용하고 비어 있지 않은 명령만 히스토리에 추가한다. 비대화형 입력은 의도적으로 기본 입력기를 그대로 사용하므로, 선택적 라이브러리의 가용 여부와 관계없이 리다이렉트된 스크립트와 테스트 스트림은 동일한 줄 단위 동작을 유지한다.

두 백엔드에서 입력 API의 소유권 계약은 동일하다. 성공하면 셸 루프가 해제해야 하는 동적 할당 문자열을 반환하고, NULL이면 입력 처리를 종료한다. 컴파일 시점 경계로 터미널 편집과 히스토리를 핵심 파서 및 실행기에서 분리해, 외부 의존성이 없는 이식 가능한 빌드 경로도 유지한다.

## feat(utils): 문자열 소유권 도구 제공
셸이 동적으로 구성하는 표현을 위해 소유권 중심의 작은 문자열 유틸리티 계층을 추가한다.

`sh_strdup`, `sh_substr`, `shell_strndup`은 항상 별도로 소유하는 NUL 종단 문자열을 반환한다. `sh_strjoin_free`는 결합된 문자열을 만든 뒤 왼쪽 피연산자를 소비하고 해제함으로써 소유권 이전 규칙을 명확히 한다. `sh_free_words`와 공개 어댑터는 NUL 종단 벡터와 그 안의 모든 문자열을 함께 해제한다.

이 단계에서는 메모리 부족을 프로세스 종료가 필요한 오류로 취급한다. `sh_xcalloc`과 `sh_strdup`은 할당 실패를 진단한 뒤 부분적으로 초기화된 데이터를 반환하지 않고 종료한다. 성공적으로 반환된 값이 항상 유효한 소유 메모리임을 보장하므로 초기 호출부는 단순해지지만, 이후 안정성 강화 과정에서는 이 치명적 할당 가정을 복구 가능한 오류 전파 방식으로 교체한다.

## feat(utils): 종료 상태 문자열 변환 제공
셸 상태 값을 별도 소유하는 10진수 문자열로 변환하는 기능을 추가한다.

루틴은 입력을 `long`으로 확장하고, 필요한 경우 선행 부호를 기록하며, 0은 별도로 처리한다. 0이 아닌 값의 각 자릿수는 역순으로 모은 뒤 정방향으로 복사한다. 마지막으로 결과 문자열과 종단 문자를 담는 데 필요한 크기만 정확히 할당하며, 이 최종 할당이 실패하면 `NULL`을 반환한다.

상태 형식을 유틸리티로 분리하면 `$?` 확장과 다른 상태 출력 경로에서 호출자가 고정 크기 버퍼를 제공하지 않아도 일관된 표현을 사용할 수 있다. 소유권도 명확하다. 성공 시마다 호출자가 해제해야 하는 별도 할당 문자열을 반환한다.

## feat(utils): 환경 식별자 문자 판정 제공
셸 변수 식별자에 사용하는 어휘 규칙을 한곳에 모은다.

`sh_is_name_start`는 영문자와 밑줄을 허용하고, `sh_is_name_char`는 첫 문자 이후에 숫자도 허용한다. 두 함수 모두 값을 `unsigned char`로 변환한 뒤 `ctype` 함수를 호출해, 음수인 일반 `char` 값으로 인해 발생할 수 있는 정의되지 않은 동작을 피한다.

이 판정 함수를 공용 유틸리티로 두면 환경 변수 이름 검증과 변수 확장 스캔이 동일한 문법을 사용한다. 공통 정의가 없으면 `export`가 허용한 이름을 `$NAME` 확장에서 다르게 해석할 수 있다.

## feat(env): 프로세스 환경 적재와 수명 관리
셸 전체 프로세스 수명 동안 유지되는 자체 환경과 상태 값을 구성한다.

`env_from_environ`은 유효한 각 `key=value` 항목을 순서가 있는 연결 리스트로 깊은 복사하고, 가져온 항목을 export 상태로 표시한다. 따라서 셸은 저장 공간과 헤드 포인터를 소유하지 않는 시작 시점의 `envp` 배열과 독립적으로 변수를 변경할 수 있다. `env_free`는 생성 과정에 대응해 모든 키, 값, 리스트 노드를 해제한다.

`main`은 셸에 진입하기 전에 `env`, `last_status`, 루프 제어 플래그를 초기화하고, 루프가 끝난 뒤 환경을 해제한 다음 최종 상태의 하위 8비트를 반환한다. 이로써 환경 메모리의 소유자를 하나로 정하고 명령 상태를 프로그램 외부에서 관찰 가능한 종료 코드에 연결한다.

## feat(env): 환경 조회와 변경 연산 제공
가져온 환경 리스트를 셸이 소유하고 변경할 수 있는 변수 저장소로 확장한다.

이름은 삽입 전에 식별자 시작 문자와 후속 문자 규칙으로 검증한다. `env_get`은 존재하지 않는 변수를 단어 확장에 필요한 빈 문자열로 매핑한다. `env_set`은 값이 제공되면 기존 값을 갱신하고, 값을 바꾸지 않은 채 항목을 export 상태로 승격할 수도 있으며, 이름이 없으면 새 항목을 뒤에 추가한다. 포인터의 포인터를 받는 인터페이스를 사용해 빈 리스트에 삽입하거나 헤드를 교체할 수 있다.

`env_unset`은 헤드를 포함해 일치하는 노드의 연결을 다시 잇고 해당 노드를 해제하며, 이름이 없으면 아무 작업도 하지 않고 성공으로 처리한다. 조회·변경·검증·노드 소유권을 이 모듈에 모아 두면 확장과 builtin이 `environ`을 직접 수정하지 않고 동일한 환경 모델을 사용할 수 있다.

## feat(env): export 배열과 출력 뷰 생성
셸의 환경 저장소에서 export된 항목만 대상으로 하는 두 가지 뷰를 제공한다.

`env_to_environ`은 먼저 export된 항목 수를 세고, 정확한 크기의 NUL 종단 벡터를 할당한 뒤 각 항목에 대해 별도 소유 `key=value` 문자열을 만든다. 이 스냅샷은 연결 리스트 노드를 외부에 노출하거나 셸 로컬 변수를 포함하지 않으므로 프로세스 실행에 사용할 수 있다. 반환된 벡터와 문자열의 소유권은 호출자에게 있다.

`env_print`는 동일한 export된 항목만을 순회하면서 일반 `key=value` 형식이나 `declare -x` 형식의 선언을 출력한다. 변환과 출력을 환경 모듈에 두어, 저장소에 존재하는지 여부가 아니라 export 메타데이터가 자식 프로세스나 사용자에게 노출되는 환경 경계를 결정한다는 규칙을 한곳에서 관리한다.

## feat(env): 공개 환경 저장소 어댑터 제공
기존 연결 리스트 구현 위에 호출자가 소유하는 안정적인 환경 핸들을 추가한다.

`shell_env_init`은 전달받은 `t_env` 객체를 센티널로 만들고, 그 `next` 포인터가 `envp`에서 가져온 실제 항목을 소유하도록 한다. 공개 조회·변경·export·변환·정리 함수는 이 센티널을 감지해 건너뛴 다음 기존 리스트 연산에 위임한다. 정리 시 실제 항목은 해제하지만 외부 핸들은 초기화된 재사용 가능 상태로 남긴다.

센티널은 포인터 안정성 문제를 해결한다. 첫 번째 실제 변수를 삽입하거나 삭제하면 리스트 헤드는 바뀔 수 있지만 호출자가 보관하는 주소는 바뀌지 않는다. 따라서 변경 함수는 내부 포인터-투-포인터 API에 `&env->next`를 넘기면서도 테스트와 상위 셸 코드에는 더 단순한 고정 핸들 인터페이스를 제공할 수 있다.

## feat(lexer): 인용 단어와 토큰 수명 관리
소유권이 명확한 단어 토큰을 도입하고, 중간 어휘 표현에서 인용 의미를 보존한다.

렉서는 셸 공백과 인용되지 않은 연산자 문자를 기준으로 입력을 나누되, 서로 인접한 인용 구간과 비인용 구간은 하나의 단어로 결합한다. 인용 부호 자체는 제거한다. 작은따옴표 안의 문자 앞에는 내부 리터럴 마커를 붙이고, 큰따옴표 안의 문자는 이후 확장 대상이 될 수 있도록 그대로 둔다. 원래 인용 부호가 제거된 뒤에도 두 인용 방식의 의미 차이를 유지하며, 인용된 빈 단어도 실제 토큰으로 보존한다.

각 토큰은 자신의 텍스트를 소유하고 단어가 시작된 소스 오프셋을 기록한다. 닫히지 않은 인용 부호가 있으면 토큰화를 중단하고 이미 누적한 리스트를 해제한다. `free_tokens`는 이에 대응하는 리스트 전체 정리 연산을 제공한다. 따라서 생성된 토큰 스트림은 원본 입력 줄의 수명과 독립적으로 유지된다.

## feat(lexer): 셸 연산자를 토큰으로 구분
인용되지 않은 모든 조각을 단어로 처리하지 않고, 렉서가 타입이 구분된 셸 연산자 토큰을 생성하도록 확장한다.

스캐너는 접두사가 겹치는 연산자에 최장 일치를 적용해 `||`와 `|`, `>>`와 `>`를 구분한다. 파이프라인, 입력·출력 리다이렉션, append 리다이렉션, 조건 연결자, 세미콜론 시퀀싱에 각각 전용 토큰을 만들고, 이후 파서에서 사용할 수 있도록 연산자의 소스 위치와 텍스트를 함께 보존한다.

지원하지 않는 단독 `&`와 아직 지원하지 않는 `<<`는 파서가 모호한 구조를 만들기 전에 어휘 분석 단계에서 실패한다. 이런 오류에서도 누적한 토큰 리스트를 해제한다. 이로써 파서는 안정적인 토큰 체계를 사용하고 문자 단위의 연산자 판정을 문법 코드에서 분리할 수 있다.

## feat(parser): 명령 트리 소유권 모델 정의
원시 토큰과 분리된 계층형 셸 구조 표현을 정의한다.

하나의 파이프라인은 순서가 있는 명령 리스트를 소유한다. 각 명령은 NUL 종단 인자 벡터와 순서가 있는 리다이렉션 리스트를 소유하고, 각 리다이렉션은 대상 문자열을 소유한다. 연결 연산자는 파이프라인 단위에 저장해 개별 명령이 아니라 완전한 파이프라인 사이의 순서를 표현한다. 명령과 파이프라인의 개수를 함께 유지하므로 실행기는 구문 텍스트를 다시 순회하지 않고 필요한 할당 크기를 알 수 있다.

`free_pipeline`은 이 계층을 말단부터 상위 방향으로 따라가며, 컨테이너 노드보다 먼저 인자 문자열과 리다이렉션 대상을 해제한다. 재귀적인 정리 진입점을 하나만 두는 것이 핵심 소유권 결정이다. 파싱된 파이프라인이 공개된 뒤에는 중간 노드가 어디까지 채워졌는지 호출자가 알지 못해도 전체 구조를 정리할 수 있다.

## feat(parser): 인자와 리다이렉션 구문 구성
토큰 스트림으로부터 처음으로 실행 가능한 명령 표현을 구성한다.

단어 토큰은 소스 순서대로 NUL 종단 `argv`에 복사한다. 리다이렉션 연산자 바로 뒤에는 반드시 단어가 있어야 하며, 해당 단어는 순서가 있는 리다이렉션 리스트의 대상으로 복사되고 인자가 아니라 구문 요소로 소비된다. 인자와 리다이렉션을 별도 소유 구조로 분리하면 실행 단계에서 명령 텍스트를 다시 파싱하지 않고 디스크립터를 변경할 수 있다.

리다이렉션만 있는 명령도 의미 있는 명령으로 유지하고, 완전히 빈 토큰 스트림은 파이프라인을 만들지 않는다. 리다이렉션 대상이 없거나 이 파서가 아직 지원하지 않는 연산자가 나오면 구문 오류를 보고하고, 부분적으로 구성한 명령을 해제한 뒤 실패를 반환한다.

## feat(parser): pipe로 명령을 pipeline에 결합
파싱을 단일 명령에 제한하지 않고 파이프라인을 순서가 있는 명령 리스트로 표현한다.

`|`를 만나면 현재 명령을 확정해 파이프라인에 추가하고 새 명령 노드를 시작한다. 따라서 구분자 뒤에서 수집한 인자와 리다이렉션은 다음 단계에 속하며, `command_count`에는 이후 pipe와 프로세스 할당에 필요한 실행 위치 수를 기록한다.

명시적인 `after_pipe` 상태로 선행·연속·후행 pipe를 거부하고, 일반적으로 지원하지 않는 연산자와 오른쪽 명령이 빠진 경우를 구분한다. 실패 시 진행 중인 명령과 이미 파이프라인에 연결된 모든 명령을 모두 해제하므로 잘못된 파이프라인이 부분 구조를 누수하지 않는다.

## feat(parser): 조건 연결자를 sequence로 결합
파서를 하나의 파이프라인에서 `;`, `&&`, `||`로 연결된 순서 있는 파이프라인 시퀀스로 확장한다.

각 연결 연산자는 왼쪽 파이프라인의 `next_op`에 저장해 다음 파이프라인을 실행할지 판단하는 데 필요한 구문을 보존한다. pipe는 계속 하나의 파이프라인 안에서 명령을 결합하고, 시퀀스 연결 연산자는 현재 파이프라인을 끝내고 다음 파이프라인을 시작한다. 따라서 범용 구문 트리 없이도 파이프라인이 조건·순차 결합보다 높은 결합 우선순위를 갖도록 표현한다.

이제 파서는 연결 연산자 앞의 빈 명령, pipe 뒤에 빠진 명령, 후행 조건 연산자를 거부한다. 후행 세미콜론은 앞 연결 연산자를 `CONN_NONE`으로 정규화해 허용한다. 모든 오류 경로에서 현재 조립 중인 파이프라인과 이미 완성된 앞부분을 모두 해제해 부분 파싱 상태에서도 소유권을 지킨다.

## feat(parser): 공개 sequence parse 수명 제공
파서의 파이프라인 리스트를 감싸는 공개 `t_sequence` 소유권 경계를 정의한다.

`shell_parse_line`은 이제 토큰화와 파싱을 한 번의 연산으로 수행하고, 파서가 필요한 데이터를 복사한 뒤 임시 토큰 스트림을 해제하며, 생성된 파이프라인 수를 기록한다. 빈 입력은 성공한 빈 시퀀스로 표현하고, 어휘 또는 구문 진단이 발생하면 파싱 실패로 처리한다.

초기화와 정리 함수를 짝으로 제공해 소유권을 명확히 한다. 시퀀스는 파이프라인이 없는 상태에서 시작하고, 성공 후에는 전체 파싱 리스트를 소유하며, `shell_sequence_free` 이후 다시 빈 상태로 돌아간다. 따라서 호출자는 토큰과 파이프라인의 수명을 따로 조정할 필요가 없다.

## feat(parser): hook 기반 sequence 실행 seam 제공
연결 연산자 의미를 실제 프로세스 실행과 분리하는 훅 기반 시퀀스 평가기를 추가한다.

평가기는 소스 순서대로 파이프라인을 순회하고, 직전 연결 연산자를 현재 파이프라인의 실행 조건으로 사용한다. `&&`나 `||` 조건이 실행을 허용할 때만 주입된 실행 함수를 호출한다. 실행 함수가 반환한 파이프라인 상태는 다음 조건 판단의 입력이 되고 `last_status`에도 기록된다. `;`와 최초 상태에는 조건을 적용하지 않는다.

`run_pipeline`을 주입하면 fork나 파일 디스크립터 조작 없이 단락 평가 동작을 테스트할 수 있다. 실행 함수가 없으면 구성 오류로 간주해 선택적으로 `on_error`를 호출하고, 불완전한 실행 인터페이스를 역참조하는 대신 상태 1을 반환한다.

## feat(expand): 인용 표식 제거 경로 제공
렉서의 리터럴 마커를 런타임 바이트로 되돌리는 전용 인용 제거 단계를 추가한다.

렉서는 보호된 문자 앞에 내부 마커를 붙여 인용 정보를 유지한다. `dequote_word`는 마커와 그 다음 바이트를 함께 소비하고 실제 리터럴 바이트만 결과에 복사하며, 마커가 없는 바이트는 그대로 통과시킨다. 따라서 마커는 명령 인자나 파일명으로 유출되지 않는 중간 표현의 세부 사항으로 남는다.

인용 제거를 `shell_dequote_word` 뒤에 두어 어휘 인용 보존과 이후 확장 정책을 분리한다. 공개 래퍼는 출력 대상도 검증하고 선택적 오류 채널을 초기화해 파서 또는 실행기 측 코드가 호출할 수 있는 경계를 만든다.

## feat(expand): 환경과 종료 상태 단어 확장
토큰화가 만든 인용 정보를 보존한 표현에 런타임 단어 확장을 구현한다.

리터럴 마커를 만나면 다음 바이트를 해석하지 않고 그대로 복사해 인용으로 보호된 문자를 유지한다. 보호되지 않은 `$?`는 셸의 마지막 상태로 치환하고, `$NAME`은 유효한 식별자 전체를 소비한 뒤 셸 소유 환경에서 값을 조회한다. 지원하는 확장을 시작하지 않는 달러 기호를 포함한 나머지 문자는 리터럴로 유지한다.

확장기는 하나의 문자열만 반환하며 의도적으로 필드 분할이나 경로명 확장은 수행하지 않는다. 이렇게 하면 파서의 토큰 하나를 인자 하나로 유지하는 계약을 지키면서 환경과 상태에 의존하는 치환은 셸 컨텍스트가 준비된 시점까지 늦출 수 있다.

## feat(expand): argv와 리다이렉션 확장 연결
단어 확장을 독립 문자열 유틸리티로 남겨두지 않고 파서가 만든 실행 표현에 적용한다.

순회 과정에서 모든 인자와 리다이렉션 대상을 `expand_word`의 결과로 교체하고, 확장된 값으로 소유권을 이전한 뒤 인코딩된 원본 문자열을 해제한다. 리다이렉션 피연산자와 일반 인자를 동일한 확장 경계에서 처리해 명령과 파이프라인의 구조는 유지하면서 변수 및 상태 치환 동작을 일관되게 만든다.

`shell_expand_sequence`는 환경 조회와 `$?`에 필요한 최소 셸 컨텍스트를 구성해 공개 시퀀스 API에 연결한다. 이렇게 확장 입력을 실행 로직과 분리하고, 호출자가 파싱된 시퀀스에 적용할 수 있는 단일 연산을 제공한다.

## feat(builtin): echo 출력 명령 제공
builtin 디스패치 경계를 도입하고 첫 번째 명령으로 `echo`를 구현한다.

`builtin_is_known`, `builtin_is_parent`, `builtin_run`은 명령 인식, 실행 정책, 실제 구현을 분리한다. 이후 실행기는 이 인터페이스를 통해 외부 프로그램을 실행하지 않고 내부에서 처리할 수 있는 명령인지 안정적으로 판단할 수 있다.

`echo`는 연속된 `-n` 피연산자가 `n`으로만 구성된 경우 이를 허용하고, 나머지 인자는 하나의 공백으로 구분해 출력하며, 요청된 경우에만 마지막 개행을 출력한다. 출력 스트림에 오류가 있으면 실패를 반환해 리다이렉션이나 pipe 쓰기 실패가 부분 출력에도 불구하고 성공으로 처리되지 않고 명령 상태에 반영되도록 한다.

## feat(builtin): pwd 작업 디렉터리 출력
프로세스의 실제 현재 작업 디렉터리를 기준으로 `pwd`를 구현한다.

`getcwd(NULL, 0)`을 사용하면 고정 버퍼 제한을 두지 않고 시스템이 경로에 필요한 크기를 할당할 수 있다. 반환된 경로는 출력한 뒤 해제하고, 조회 또는 출력 실패는 필요에 따라 진단 메시지와 함께 0이 아닌 명령 상태로 변환한다.

프로세스 상태를 직접 읽으면 오래되어 실제 경로와 달라질 수 있는 `PWD` 환경 항목에 의존하지 않는다. 따라서 텍스트 표현이 저장된 환경 값과 다른 경로를 통해 디렉터리를 변경했더라도 `pwd`가 실제 작업 디렉터리를 정확히 출력한다.

## feat(builtin): cd 이동과 PWD 상태 동기화
`cd`를 부모 프로세스가 소유하는 작업 디렉터리 전환으로 구현하고 `PWD`, `OLDPWD`를 함께 갱신한다.

프로세스 상태를 변경하기 전에 대상 경로를 결정한다. 피연산자가 없으면 `HOME`, `-`이면 `OLDPWD`를 사용하고, 피연산자가 둘 이상이면 오류로 처리한다. `chdir`을 호출하기 전에 이전 물리 경로를 저장하고, 이동에 성공한 뒤 새 물리 경로를 구해 환경 저장소를 갱신한다. `cd -`에서는 결정된 목적지도 출력한다.

현재 작업 디렉터리는 프로세스별 상태이므로 이 builtin은 셸 프로세스에서 실행해야 한다. 자식에서만 `chdir`을 호출하면 자식 종료와 함께 변경도 사라진다. `chdir` 성공 뒤에만 환경을 갱신해 실제로 일어나지 않은 디렉터리 변경을 환경에 반영하지 않는다. 이 단계에서는 `getcwd`나 `env_set`이 값을 제공하지 못하면 동기화를 가능한 범위에서만 수행하며, 파일 시스템의 실제 작업 디렉터리를 기준 상태로 유지한다.

## feat(builtin): env 환경 목록 출력
`env`를 프로세스 전역 `environ` 배열이 아니라 셸이 소유한 환경의 뷰로 구현한다.

출력을 `env_print`에 위임해 필터링과 형식화를 export 메타데이터를 소유한 컴포넌트 안에 유지한다. 따라서 셸 환경 저장소를 통해 변경한 내용이 즉시 반영되며, builtin에서 저장 표현을 다시 구성하거나 중복 구현할 필요가 없다.

지원되는 `env` 계약에 명령 실행, 옵션 처리, 임시 대입 의미가 포함되지 않으므로 이 구현은 의도적으로 피연산자를 거부한다. 스트림 오류도 0이 아닌 명령 상태로 변환해 출력 실패가 성공으로 보고되지 않도록 한다.

## feat(builtin): export 대입과 선언 출력
`export`를 환경 변경 명령과 셸에 저장된 변수의 선언 뷰 두 역할로 구현한다.

피연산자가 없으면 환경 계층에 정렬된 선언 형식 출력을 위임한다. 피연산자가 있으면 첫 `=`를 기준으로 이름을 분리하고 확장과 동일한 이름 규칙으로 식별자를 검증한 뒤 `env_set`을 통해 해당 항목을 export 상태로 표시한다. 명령 구문 해석은 builtin 경계에 두고, 환경 저장소는 값 교체·할당·export 메타데이터 관리만 담당하게 한다.

잘못된 식별자는 각각 진단하되 이후 피연산자도 계속 처리하고, 하나라도 거부되면 명령 전체는 0이 아닌 상태를 반환한다. 메모리 할당이 실패하면 요청된 상태 전환이 일관되게 적용됐다고 보장할 수 없으므로 즉시 중단한다.

## feat(builtin): unset 환경 이름 제거
셸의 환경 저장소를 부모 측에서 변경하는 `unset`을 추가한다.

builtin은 전달된 모든 이름을 순회하며 제거를 `env_unset`에 위임하므로, 연결 리스트 소유권과 노드 해제는 환경 계층 안에 유지된다. 존재하지 않는 이름을 제거하는 작업은 자연스럽게 멱등하며, 한 번의 호출로 여러 항목을 처리할 수 있어 저장 구조를 명령 디스패치에 노출하지 않고 일괄 변경을 지원한다.

중요한 경계는 소유 프로세스의 `shell->env`에 변경을 적용하는 것이다. 이후 확장, `env` 출력, 자식 프로세스용 환경 벡터 생성 모두 이 삭제를 관찰해야 한다. 같은 변경을 자식에서만 수행하면 프로세스 종료와 함께 상태 변경도 사라진다.

## feat(builtin): exit 상태를 셸 수명에 연결
`exit`를 일반적인 명령 결과가 아니라 셸 상태 전환으로 만든다.

builtin은 선택적 숫자 인자를 `strtol`로 검증하고, 뒤에 남는 문자와 범위 오류를 거부하며, 허용 값은 셸에 노출되는 부호 없는 8비트 종료 범위로 정규화한다. 인자가 없으면 현재 `last_status`를 유지한다. 유효한 인자가 있으면 반환 상태와 최종 프로세스 종료 상태에 모두 반영한다. 숫자가 아닌 인자는 상태 2로 종료하고, 인자가 너무 많으면 오류를 출력하되 셸은 계속 실행한다.

`exit`를 부모 builtin으로 등록해야 하는 이유는 fork된 자식에서 `shell->running`을 변경해도 소유 프로세스의 명령 루프는 멈추지 않기 때문이다. 대화형·비대화형 루프의 지속 여부는 부모 셸만 결정한다는 수명 주기 계약을 이 단계에서 확정한다.

## feat(redirection): 파일 입출력 리다이렉션 적용
파일 리다이렉션을 표준 디스크립터에 순서대로 적용하는 실행 단계 변환으로 구현한다.

입력 리다이렉션은 대상을 읽기 전용으로 열어 `STDIN_FILENO`를 교체한다. 출력 리다이렉션은 모드 0644로 대상을 생성하고 truncate 또는 append 방식에 따라 연 뒤 `STDOUT_FILENO`를 교체한다. `dup2`가 성공하면 표준 디스크립터가 필요한 동일 open file description을 참조하므로 임시 디스크립터는 즉시 닫는다.

파싱된 리다이렉션 리스트를 왼쪽에서 오른쪽으로 순회하면 반복 리다이렉션에 셸의 의미가 그대로 적용된다. 각 파일 열기와 디스크립터 교체를 차례로 수행하고, 마지막으로 적용된 리다이렉션이 최종 표준 스트림을 결정한다. 파일 열기 또는 디스크립터 복제가 하나라도 실패하면 이 경계에서 진단하고 이후 리다이렉션 처리를 중단해 명령이 일부만 적용된 설정으로 실행되지 않도록 한다.

## feat(exec): 부모 builtin의 표준 스트림 복원
부모 셸에서 실행해야 하는 명령에 리다이렉션의 적용 범위를 한정한다.

리다이렉션을 적용하기 전에 실행기가 표준 입력과 표준 출력을 복제한다. 그 뒤 명령의 리다이렉션 리스트를 적용하고, 부모 상태를 변경하는 builtin을 실행하거나 인자가 없는 명령이라면 리다이렉션만 수행한다. 이후 버퍼링된 출력을 flush하고 원래 두 디스크립터를 복원한 뒤 저장해 둔 사본을 닫는다. 리다이렉션 설정이 실패한 경우에도 동일한 복원 경로를 거쳐 상태 1을 반환한다.

이 방식은 서로 충돌하는 두 요구사항을 동시에 만족한다. `cd`, `export`, `unset`, `exit` 같은 builtin은 영속적인 셸 상태를 변경해야 하므로 부모에서 실행되어야 하지만, 그 명령의 리다이렉션에 필요한 디스크립터 변경은 명령 하나에만 한정되어야 한다. 부모 실행 명령 경계에서 저장하고 복원하면 builtin의 상태 변경은 유지하면서 한 명령의 입출력 대상이 다음 명령에 영향을 주는 것을 막을 수 있다.

## feat(exec): 단일 명령을 자식에서 실행
파싱과 확장이 끝난 단일 명령을 위한 첫 실제 실행 경계를 도입한다.

리다이렉션만 있는 명령이나 효과가 지속되어야 하는 builtin은 부모 명령 경로에서 실행한다. 그 외 작업은 fork된 자식에서 수행한다. 자식은 먼저 리다이렉션을 적용하고, 알려진 builtin이면 셸 상태의 자식 복사본을 대상으로 실행하며, 외부 명령에는 직렬화한 최신 환경을 넘겨 `execvp`를 호출한다. builtin의 스트림은 `_exit` 전에 flush해 표준 I/O 버퍼에 남은 출력을 잃지 않으면서 부모 측 종료 핸들러는 실행하지 않는다.

부모는 정확한 자식을 `waitpid`로 기다리고 `EINTR`이면 다시 시도한다. 정상 종료는 하위 바이트의 상태 값으로, 시그널 종료는 `128 + signal`로 변환한다. 명령을 찾지 못한 경우는 127, 그 밖의 `execvp` 실패는 126으로 매핑한다. 이로써 일반 명령 실행은 자식에 격리하고 영속적인 셸 상태를 변경해야 하는 명령만 부모에 남긴다는 핵심 프로세스 상태 규칙을 확립한다.

## feat(exec): pipeline 자식 상태를 순서대로 회수
단일 외부 명령 실행을 파싱된 파이프라인의 모든 명령 노드로 일반화하고, 생성된 PID를 명시적으로 기록한다.

부모는 명령마다 하나의 PID 슬롯을 할당하고 소스 순서대로 fork한 뒤, 실제로 생성된 각 자식을 정확한 PID로 기다리며 중단된 wait 호출은 재시도한다. 특정 PID를 지정하지 않는 `wait`에 의존하지 않고 프로세스 식별자를 기록함으로써 명확한 소유권을 정하고, 상태를 해석하려는 단계와 다른 자식을 잘못 회수하는 상황을 막는다.

모든 명령이 정상적으로 생성되면 셸은 마지막 명령의 상태를 파이프라인 상태로 보고한다. 일부만 생성된 경우 존재하는 자식은 모두 회수하되 불완전한 파이프라인의 결과를 받아들이지 않고 상태 1을 반환한다. 이 커밋은 프로세스 수명 주기 골격을 확립하며, 다음 pipe 디스크립터 변경에서 실제 데이터 파이프라인으로 연결한다.

## feat(exec): 다단 pipeline의 pipe FD 연결
N개 명령에 대해 `N - 1`개의 pipe를 명시적인 테이블로 관리하고 명령마다 자식 하나를 생성하는 다단 파이프라인을 구현한다.

자식 단계 `i`는 이전 pipe의 읽기 끝을 표준 입력에 복제하고, 마지막 단계가 아니면 현재 pipe의 쓰기 끝을 표준 출력에 복제한다. 그 뒤 모든 원본 pipe 디스크립터를 닫고 명령 리다이렉션을 적용한다. 이 순서는 중요하다. pipe 토폴로지가 기본 입출력을 구성하고, 명령에 명시된 리다이렉션은 그 뒤 해당 표준 디스크립터를 다시 교체할 수 있다.

부모는 fork 전에 모든 pipe를 만들고 각 PID를 기록하며, 생성 루프가 끝나면 자신이 가진 pipe 사본을 모두 닫고 모든 자식을 기다린다. 셸에 노출되는 결과는 마지막 파이프라인 명령의 상태이고, 생성이 중간에 끊기면 실패로 처리한다. 디스크립터 슬롯은 `-1`로 초기화해 pipe 생성이 일부만 성공한 경우에도 전체 테이블을 안전하게 순회하며 정리할 수 있다.

부모 상태를 변경하는 단일 builtin 또는 리다이렉션만 있는 명령만 셸 프로세스에서 실행한다. 여러 명령으로 구성된 파이프라인에 포함된 builtin은 모두 자식에서 실행해 환경이나 디렉터리 변경이 부모에 새어 나가지 않도록 파이프라인 격리를 유지한다.

## feat(exec): 조건 연결자와 지연 확장 실행
셸 방식의 단락 평가 연결 연산자를 사용해 파싱된 파이프라인 리스트를 실행하고, 각 파이프라인이 실제 실행 대상으로 선택되는 시점까지 확장을 늦춘다.

실행기는 리스트를 순회하면서 직전 연결 연산자를 유지한다. 이전 상태가 0이 아니면 `&&` 오른쪽 파이프라인을 건너뛰고, 이전 상태가 0이면 `||` 오른쪽 파이프라인을 건너뛴다. 시퀀스 경계는 조건 없이 실행한다. `exit` 같은 부모 builtin이 셸의 running 플래그를 해제하면 순회도 중단한다.

확장은 의도적으로 이 조건 판단 이후에 수행한다. 선택된 파이프라인을 리스트에서 임시로 분리해 기존 확장 루틴이 해당 파이프라인만 변환하도록 한 뒤 연결을 복원한다. 따라서 건너뛴 분기는 확장 결과를 할당하지도 않고 변수나 `$?`를 평가하지도 않는다. 실행되는 분기는 바로 앞 파이프라인이 만든 상태를 관찰한다. 이 순서로 연결 연산자 제어 흐름과 확장 상태를 일치시켜, 전체 줄을 실행 전의 오래된 상태로 미리 확장하는 문제를 피한다.

## feat(shell): 한 줄 해석과 실행 수명 연결
입력 루프를 한 줄 단위의 완전한 파싱-실행 트랜잭션에 연결한다.

`shell_process_line`은 생성부터 정리까지 임시 토큰 리스트와 파싱된 파이프라인 리스트를 소유한다. 토큰화 또는 파싱 진단은 이 경계에서 출력하고 실행기를 호출하지 않은 채 셸 상태 258로 변환한다. 빈 파싱은 이전 상태를 유지하고, 유효한 파싱은 실행한 뒤 전체 구조를 해제한다.

줄 획득과 하위 시스템별 API 사이에 이 오케스트레이션을 두어 셸 루프가 사용할 안정적인 수명 주기 경계를 만든다. 루프는 입력 문자열과 영속적인 `t_shell` 상태만 소유하고, 줄 처리 과정은 해당 문자열에서 파생된 모든 표현을 소유하며 다음 프롬프트 전에 반드시 해제한다.

## feat(heredoc): 구분자 정규화 버퍼 구현
변수 확장은 적용하지 않고 렉서의 리터럴 마커 인코딩만 제거하는 전용 구분자 정규화 루틴을 추가한다.

렉서는 작은따옴표 안의 문자 앞에 내부 마커를 붙여 보존한다. heredoc 일치 판정에서는 문자 값 자체가 필요하지만 구분자를 일반적인 확장 가능 명령 단어로 처리해서는 안 된다. 따라서 정규화 과정은 마커가 붙은 문자는 리터럴로 복사하고 나머지 바이트도 그대로 복사해 별도 소유 가변 버퍼를 만든다.

로컬 버퍼는 문자를 추가할 때마다 NUL 종단을 유지하고, 할당 실패 시 부분 결과를 해제한다. 이로써 이후 heredoc 수집에 필요한 표현 경계를 마련한다. 파서가 소유한 인코딩된 단어는 그대로 유지하고, heredoc 계층에서 입력 줄과 비교할 정확한 텍스트를 의도적으로 파생한다.

## feat(heredoc): 수집 본문 저장소 수명 관리
heredoc 본문을 보관하는 실행 컨텍스트 소유 저장소를 추가한다.

각 항목은 별도 소유 본문 문자열과 그 본문을 요청한 정확한 파싱된 리다이렉션을 한 쌍으로 저장한다. 리다이렉션 식별자로 조회하면 동일한 구분자를 사용하는 heredoc이 여러 개 있어도 모호하지 않다. 항목을 찾지 못한 경우 빈 문자열을 반환해 리다이렉션 코드에 NULL이 아닌 정의된 기본값 본문을 제공한다.

저장소는 본문 할당과 항목 노드를 모두 해제하는 명시적인 정리 함수 하나를 가진다. 이를 `exec_context`에 연결해 수집된 입력의 범위를 하나의 실행 연산으로 제한하고, heredoc 저장소와 파서가 소유하는 리다이렉션 노드를 분리한다. 본문은 수집보다 오래 살아남을 수 있지만 키로 사용하는 리다이렉션 포인터가 속한 파싱된 구조보다 오래 유지될 수는 없다.

## feat(heredoc): 구분자별 본문 순차 수집
모든 파이프라인, 명령, 리다이렉션을 소스 순서대로 순회하는 heredoc 준비 과정을 구현한다.

각 heredoc 리다이렉션마다 수집기는 구분자의 인용을 제거하고, 정확히 일치하는 줄을 만날 때까지 입력을 읽으며, 각 본문 줄 뒤에 개행을 붙여 완성된 본문을 실행 컨텍스트에 저장한다. 대화형 수집에서는 보조 프롬프트를 사용하고, 구분자 전에 EOF가 오면 경고를 출력한 뒤 그때까지 모은 본문을 유지한다. 할당 실패 시 부분 버퍼를 폐기하고 준비 작업을 중단한다.

저장 항목은 구분자 텍스트가 아니라 파싱된 리다이렉션의 주소를 키로 사용한다. 따라서 같은 구분자를 반복해서 사용해도 본문을 각각 독립적으로 보존하고, 실행 시 적용 중인 정확한 리다이렉션에 해당하는 본문을 가져올 수 있다. 실행 전에 전체 파싱된 시퀀스를 순회해 수집을 끝냄으로써 입력 소비 순서도 결정적으로 만든다. 여러 heredoc은 실제로 분기나 명령이 실행되는지와 관계없이 소스에 나타난 순서대로 읽는다.

## feat(heredoc): 인용 여부에 따라 본문 확장
heredoc 구분자가 인용되지 않은 것으로 판단되는 경우에만 본문 줄에 셸 확장을 적용한다.

수집기는 인용되지 않은 본문 줄을 저장 버퍼에 복사하면서 `$?`와 유효한 환경 변수 이름을 확장한다. 알 수 없거나 문법적으로 완전하지 않은 달러 형식은 달러 기호를 그대로 유지하고, 설정되지 않은 변수는 빈 값으로 치환하며, 각 입력 줄에는 정확히 하나의 종단 개행을 붙인다. 인용된 구분자에서는 본문 바이트를 그대로 유지한다.

이 시점의 인용 판정은 구분자 단어 안의 리터럴 마커 인코딩에서 유도하고, 비교 전에 구분자 자체의 인용 표식은 제거한다. 따라서 종료 구분자 일치 판정과 본문 변환을 분리하고, heredoc 확장은 일반 명령 단어 처리보다 의도적으로 좁게 유지한다. 변수와 상태만 치환하며 단어 분할이나 글로빙은 수행하지 않는다.

## feat(redirection): heredoc을 stdin으로 연결
heredoc 구문과 미리 수집한 본문을 일반 리다이렉션 경로에 통합한다.

`<<`를 미지원 연산자가 아니라 정식 토큰 및 파서 리다이렉션 타입으로 추가한다. 파싱된 줄의 파이프라인을 실행하기 전에 명령 처리기가 실행 컨텍스트를 만들고 모든 heredoc 본문을 수집한다. 준비에 실패하면 상태 1로 해당 줄을 중단하고 수집 항목과 파싱된 파이프라인을 모두 해제한다. 성공한 경우 본문은 그 줄을 실행하는 동안에만 유지한다.

실행기는 저장된 각 본문을 해당 파싱된 리다이렉션 노드와 연결한다. 리다이렉션을 적용할 때 본문을 임시 스트림에 기록하고 처음으로 되감은 뒤 표준 입력에 복제한다. 일반 리다이렉션 순회를 재사용하므로 왼쪽에서 오른쪽으로 적용되는 우선순위를 유지한다. 소스 순서에 따라 heredoc이 들어오는 pipe를 덮어쓸 수도 있고, 뒤에 오는 입력 리다이렉션이 heredoc을 다시 덮어쓸 수도 있다.

heredoc 구분자는 일반 확장 단계에서 확장하지 않고 인용 표식만 제거한다. 구분자를 일반 인자로 잘못 해석하지 않게 하면서 본문 수집이 자체 확장 규칙을 담당하도록 한다. 이 통합으로 수명 주기를 명확히 정의한다. 리다이렉션을 파싱하고, 실행 전에 본문을 수집하고, 명령 실행 시 읽을 수 있는 디스크립터로 설치하며, 전체 파이프라인 리스트 실행이 끝나면 저장한 본문을 해제한다.

## test(smoke): 주요 셸 명령 흐름 검증
표준 입력으로 셸을 구동하고 프로세스 상태와 정확한 표준 출력을 함께 비교하는 end-to-end smoke 테스트 스위트를 추가한다.

각 케이스는 격리된 함수가 아니라 하위 시스템을 가로지르는 주요 계약을 검증한다. 부모에 상태가 유지되는 `cd`, `export`, `unset`, 인용에 민감한 확장, 명령을 찾을 수 없을 때의 상태가 `$?`로 전파되는 동작, 파이프라인 데이터 전달, truncate·append·입력 리다이렉션, 인용되지 않은 heredoc 확장, 구문 오류 복구, 여러 줄의 비대화형 입력, 이후 입력을 실행하기 전에 종료하는 `exit`를 포함한다.

각 케이스는 격리된 임시 디렉터리에서 실행하고 표준 출력과 표준 오류를 별도로 기록해, 파일 시스템 효과나 진단 메시지가 출력 검증을 우연히 만족시키지 못하도록 한다. 테스트 스위트를 `make test`에 연결해 이후 파서, 실행기, 실패 경로, sanitizer, 성능 변경을 비교할 재사용 가능한 동작 기준선을 마련한다.

## test(redirection): 부모 명령의 표준 입출력 복원 검증
부모에서 실행되는 builtin에 적용한 리다이렉션은 일시적이지만 builtin의 상태 변경은 유지되는지 검증한다.

새 변수를 이후에도 볼 수 있어야 하므로 `export`는 셸 프로세스에서 실행되어야 한다. 그러나 입력과 출력 리다이렉션이 셸의 표준 디스크립터를 영구적으로 교체해서는 안 된다. 이 케이스는 양방향 리다이렉션을 함께 사용해 변수가 유지되는지 확인하고, 이어지는 `echo`와 `env` 파이프라인이 정상 표준 출력을 사용하도록 요구하며, `export` 자체는 아무것도 출력하지 않으므로 리다이렉션 대상 파일이 비어 있는지도 확인한다.

이 테스트는 실행기의 분리된 두 책임을 고정한다. 부모 실행은 셸 상태 변경을 보존하고, 디스크립터 변경은 해당 명령 하나에만 한정되어 루프가 계속되기 전에 복원되어야 한다.

## test(heredoc): 인용 구분자와 본문 확장 검증
작은따옴표로 감싼 구분자가 본문 확장을 억제하는 end-to-end heredoc 케이스를 추가한다.

구분자의 인용 부호는 종료 구분자 자체가 아니라 구문이므로 입력은 여전히 인용되지 않은 `EOF` 줄에서 끝난다. 동시에 변수가 export되어 있어도 본문의 `$HD`는 리터럴로 유지되어야 한다. 따라서 이 테스트는 구분자 비교를 위한 인용 제거와 인용 여부에 따른 확장 정책을 하나의 관찰 가능한 시나리오에서 함께 검증한다.

이로써 일반 명령 단어 확장과 heredoc 구분자 처리의 차이를 보호한다. heredoc은 인용 표식을 제거한 텍스트를 일치 판정에 사용하되, 인용이 있었는지는 본문 처리 정책을 결정하는 데 사용한다.

## fix(heredoc): 구분자의 인용 상태를 실행 단계까지 보존
인코딩된 구분자 텍스트에서 인용 여부를 재구성하지 않고 어휘 분석에서 얻은 인용 여부 정보를 heredoc 실행 단계까지 전달한다.

기존 런타임 휴리스틱은 리터럴 마커가 있으면 구분자가 인용되었다고 판단했다. 이 방식은 마커로 인코딩되는 작은따옴표 문자에는 동작했지만, 최종 토큰 텍스트에 마커가 전혀 남지 않을 수 있는 큰따옴표 또는 부분 인용 구분자에서는 실패했다. 이제 렉서는 단어에 인용 구문이 한 번이라도 사용되었는지 기록하고, 파서는 그 정보를 heredoc 리다이렉션에 명시적으로 복사한다.

heredoc 수집은 일치 판정을 위해 구분자의 인용 표식을 제거하지만, 본문 변수를 확장할지는 보존된 `heredoc_quoted` 플래그로 판단한다. 최종 텍스트와 어휘 출처 정보를 분리하면 필요한 두 속성을 모두 유지할 수 있다. 종료 구분자 비교에는 인용 구문이 제거된 텍스트를 사용하고, 구분자 일부라도 인용되었으면 확장을 억제한다.

## test(heredoc): 이중·부분 인용 구분자 회귀 검증
heredoc 구분자의 어느 부분이든 인용되면 본문 확장이 비활성화되는지 보여 주는 회귀 케이스를 추가한다.

전체를 큰따옴표로 감싼 구분자와 인용되지 않은 구간과 큰따옴표 구간을 조합한 구분자 모두 인용 제거하면 동일한 종료 구분자 텍스트 `EOF`가 되어야 하며, 동시에 인용이 사용되었다는 사실은 유지되어야 한다. 따라서 변수가 정의되어 있어도 본문의 `$HD`는 리터럴로 남는다.

부분 인용 테스트가 중요한 이유는 최종 구분자 텍스트만으로 확장 정책을 결정할 수 없기 때문이다. 파서는 인용 제거된 구분자와 별도로 인용 여부 정보를 전달해야 하며, heredoc 수집은 이를 통해 올바른 종료 구분자를 일치 판정하면서 본문 확장 허용 여부를 독립적으로 판단한다.

## test(exec): 다단 파이프와 리다이렉션 순서 검증
긴 파이프라인 연결과 여러 리다이렉션의 적용 순서를 end-to-end로 검증한다.

4단계 파이프라인은 각 자식이 이전 단계의 출력을 표준 입력으로 받고 다음 단계로 출력을 보내는지, 그리고 관련 없는 pipe FD를 닫아 체인이 EOF에 도달하고 정상 종료되는지 확인한다. 테스트 바이너리 경로를 재정의할 수 있게 해 동일한 동작 테스트 스위트를 다른 빌드에도 재사용할 수 있다.

리다이렉션 케이스는 왼쪽에서 오른쪽으로 적용된다는 규칙을 확정한다. 출력 리다이렉션이 두 개면 첫 파일을 생성한 뒤 두 번째 디스크립터가 이를 대체하므로 명령 출력은 두 번째 파일에만 기록된다. 파이프라인 단계가 자체 stdout 리다이렉션도 갖는 경우에는 명시적 리다이렉션이 pipe 연결 뒤 적용되어 pipe를 덮어쓴다. 따라서 후단 `cat`은 데이터를 받지 못하고 파일만 데이터를 받는다. 파서 구조만으로는 알 수 없는 이 실행 순서 규칙을 테스트로 보호한다.

## test(status): 실행 불가 파일과 신호 종료 상태 검증
경로 해석 이후 외부 명령이 실패할 수 있는 서로 다른 두 경우를 회귀로 추가한다.

존재하지만 실행 권한이 없는 일반 파일은 상태 126을 반환해야 하며 파일 내용은 실행되어서는 안 된다. 이는 “찾았지만 실행할 수 없음”을 명령을 찾을 수 없는 상태 127과 구분한다. `SIGTERM`으로 종료된 자식은 `128 + SIGTERM`, 즉 143을 반환해야 하므로 연결 연산자 판단과 `$?`가 일반 실패가 아니라 시그널 종료를 반영한다.

각 결과는 다음 명령에서 관찰해 `execvp` 오류와 `waitpid` 상태 워드를 셸에 노출되는 상태 값으로 변환하는 실행기의 규칙을 고정한다.

## test(parser): 조건 연결자와 잘못된 연산자 검증
조건 연결 연산자와 잘못된 제어 연산자에 대한 end-to-end 파싱 검증 범위를 확장한다.

정상 케이스는 단락 평가 동작을 관찰 가능한 실행 계약으로 확정한다. 실패한 왼쪽 파이프라인 뒤의 `&&` 오른쪽은 실행하지 않고, 실패한 왼쪽 뒤의 `||` 오른쪽은 실행하며, 성공한 왼쪽은 `&&` 진행을 허용한다. 잘못된 케이스는 선행 또는 후행 조건 연산자가 있는 입력 줄 전체를 구문 상태 258로 거부하고 부분 명령도 실행하지 않아야 한다.

단독 `&`는 백그라운드 실행이 지원 문법 밖이므로 별도로 테스트한다. 토큰화 단계에서 이를 거부해 파서가 연결 연산자로 잘못 분류하거나 양옆 명령을 실행하는 일을 막는다.

## fix(parser): 오류 출력 포인터 없이도 구문 실패 반환
호출자가 오류 메시지를 요청하지 않아도 파싱 실패 의미를 유지한다.

렉서와 파서는 오류 슬롯을 채워 실패를 전달한다. 이전에는 `NULL`을 그대로 전달하면 `shell_parse_line`이 이 신호를 잃어, 래퍼가 검사할 상태가 없다는 이유로 잘못된 입력이 성공한 것처럼 보일 수 있었다. 공개 API는 이제 항상 실제 슬롯을 제공한다. 호출자 포인터가 있으면 이를 사용하고, 없으면 로컬 임시 포인터를 사용한다.

임시 진단 문자열은 모든 반환 경로에서 해제하고, 호출자가 제공한 진단 문자열은 호출자가 소유하도록 유지한다. 부분적으로 생성된 시퀀스 역시 실패를 반환하기 전에 계속 해제한다. 이로써 파싱 성공 여부와 설명 메시지를 원하는지 여부라는 서로 독립적인 API 선택을 분리해, 선택적 진단을 생략해도 정확성이 달라지지 않게 한다.

## test(parser): 공개 parser 오류 반환 검증
셸 실행을 통해서만 파싱을 검증하지 않고 공개 파싱 API 자체를 위한 소스 수준 테스트 실행 파일을 추가한다.

케이스는 API의 소유권과 선택적 출력 계약을 확정한다. 유효한 입력과 빈 입력은 성공하며 호출자가 해제할 수 있는 시퀀스를 제공한다. 구문 실패는 오류 문자열 요청 여부와 관계없이 0이 아닌 값을 반환한다. 진단을 요청한 경우 실패 시에는 소유권이 있는 메시지를 제공하고 성공 시에는 메시지가 없어야 한다. 출력 시퀀스가 `NULL`이면 역참조하거나 빈 파싱으로 취급하지 않고 거부한다.

테스트를 `main.c`를 제외한 모든 프로덕션 소스와 함께 빌드해 임베딩 호출자에 노출되는 동일 파서 구현을 검증한다. 이로써 대화형 명령 루프의 상태 처리와 진단 로직이 하위 반환값 계약의 오류를 가리지 못하게 한다.

## refactor(runtime): 프로세스 시스템 호출 경계 분리
`pipe`, `fork`, `waitpid`를 감싸는 런타임 경계를 도입하고 실행기가 시스템 호출을 직접 수행하지 않고 이 경계에 의존하도록 변경한다.

프로덕션 래퍼는 원래 동작을 그대로 전달하지만, 테스트 빌드에서는 지정한 호출 횟수에서 대표적인 `errno`와 함께 실패하도록 만들 수 있다. 호출 위치 기반 주입은 파이프라인 코드에서 특히 중요하다. 일부 pipe나 자식을 이미 생성한 뒤의 실패는 첫 호출 실패와 정리 책임이 본질적으로 다르기 때문이다.

이 리팩터링 자체는 실행기의 복구 정책을 아직 바꾸지 않는다. 드문 프로세스 자원 실패를 결정적으로 재현하고, 이후 수정에서 디스크립터 정리, 부분 자식 집합 종료, 자식 회수 오류 보고를 검증할 수 있는 경계를 만드는 것이 목적이다.

## fix(exec): 부분 생성 파이프라인의 자식과 FD 회수
부분적으로 구성된 파이프라인도 부모가 완전히 정리하는 하나의 정리 경로로 수렴하도록 한다.

후반 `fork`가 실패하면 앞 단계에서 이미 생성한 자식이 pipe 입력을 기다리며 블로킹되어 있거나 별도 명령을 실행 중일 수 있다. 부모의 디스크립터만 닫고 기다리면 무기한 멈출 수 있다. 이제 실행기는 부모가 보유한 모든 pipe FD를 닫고, 이미 생성한 각 자식에 `SIGKILL`을 보내며, 이미 종료한 자식은 허용하고, 기록된 모든 PID를 끝까지 wait해 좀비를 남기지 않는다.

자식 프로세스 회수도 별도 헬퍼로 분리해 `EINTR`이면 재시도하고, EINTR 이외의 실패에도 한 번 더 시도한다. 자식 회수 오류가 하나라도 있으면 파이프라인 상태는 1이 되며, 마지막 명령의 종료 상태는 해당 wait가 정상적으로 완료된 경우에만 인정한다. 부모가 PID를 기록한 순간부터 파이프라인 실행이 끝날 때까지 그 자식을 종료시키거나 관찰할 책임이 있다는 소유권 불변식을 유지한다.

## test(exec): pipe·fork·wait 실패 회귀 검증
별도로 컴파일한 fault injection 바이너리를 추가하고 파이프라인 생성, 자식 생성, 자식 회수 실패에 대한 회귀 케이스를 만든다.

동일 소스를 `SMALL_SHELL_TESTING`과 함께 컴파일해 프로덕션 동작은 바꾸지 않으면서 런타임 래퍼가 특정 시스템 호출 순번에서 결정적으로 실패하도록 한다. 첫 호출만 실패시키지 않고 뒤쪽 pipe 또는 fork 호출도 대상으로 해 실행기가 이미 디스크립터를 획득했거나 자식을 생성한 뒤의 정리를 검증한다.

각 케이스는 실패한 파이프라인이 상태 1로 끝나고 이어지는 `echo $?`가 이를 관찰해야 한다. 블로킹되는 `sleep` 파이프라인은 부분 fork 정리를 실제로 의미 있게 만든다. 뒤쪽 `fork`가 실패하면 이미 생성된 자식을 종료하고 회수해야 하며 그렇지 않으면 테스트가 멈춘다. `waitpid` 케이스는 회수 오류가 원래 성공했을 파이프라인 결과를 덮어쓰고 상태 1이 되어야 함을 검증한다.

## refactor(runtime): FD 시스템 호출 경계 분리
파일 디스크립터를 여는 연산과 복제 연산을 런타임 계층을 통해 호출하도록 변경한다.

파이프라인 연결, 리다이렉션 설정, heredoc 설치, 부모의 표준 I/O 저장·복원은 이제 libc를 직접 호출하지 않고 `shell_open`, `shell_dup`, `shell_dup2`를 공유한다. 래퍼는 프로덕션 의미를 그대로 유지하면서 디스크립터 고갈, 교체 실패, 권한 오류를 자식과 부모 실행 경로 모두에서 동일한 경계를 통해 fault injection으로 재현할 수 있게 한다.

주입 헬퍼에는 선택한 위치부터 이후 모든 호출을 실패시키는 반복 모드도 추가한다. 일회성 실패는 일반 정리 검증에 충분하지만, 단순 재시도로 복구할 수 없는 표준 스트림 복원 실패를 모델링하려면 반복 실패가 필요하다. 이 커밋은 정상 실행 동작을 바꾸지 않으면서 이후 리다이렉션 상태 복구를 검증하는 관찰 경계를 마련한다.

## fix(redirection): 부모 표준 입출력 복원 실패 전파
부모 셸의 표준 디스크립터를 복원하는 과정의 실패를 무시하지 않고 전파한다.

부모에서 실행되는 builtin은 영속 프로세스 상태를 일시적으로 변경하므로 `STDIN_FILENO`와 `STDOUT_FILENO` 복원은 best-effort 정리가 아니라 명령 정확성의 일부다. 각 디스크립터를 독립적으로 복원하고 `EINTR`이면 재시도하며, EINTR이 아닌 복구 가능한 오류를 기록한 뒤 실패로 확정하기 전에 한 번 더 시도한다. 저장한 사본은 두 디스크립터의 복원 시도가 모두 끝난 뒤 결과와 관계없이 닫는다.

일시적인 복원 오류가 결국 성공하더라도 실행이 완전히 정상적이지 않았다는 사실을 남기기 위해 명령 상태는 1로 강제한다. 어느 디스크립터든 끝내 복원할 수 없으면 셸의 `running`도 해제한다. 이후 입력이나 출력이 어떤 디스크립터 설정을 사용할지 신뢰할 수 없기 때문이다. 리다이렉션 설정 실패 후 복원하는 경우에도 같은 규칙을 적용하고, 원래 stdout을 복원하기 전에 버퍼링된 builtin 출력도 검사한다.

## test(redirection): 저장·적용·복원 실패 회귀 검증
부모에서 실행되는 리다이렉션의 각 단계, 즉 표준 디스크립터 저장, 대상 파일 열기, 교체 적용, 원래 디스크립터 복원에 fault injection 검증 범위를 추가한다.

일회성 실패 케이스에서는 영향받은 명령이 리다이렉션 대상에 데이터를 출력하지 않고 상태 1을 반환해야 하며, 이어지는 명령은 정상 표준 출력으로 계속 쓸 수 있어야 한다. 이는 설정에 실패한 뒤 실행하지 않는 실패 시 동작과, 복구 가능한 실패 뒤 셸의 영속 디스크립터를 변경된 상태로 남기지 않는 복구 동작을 함께 검증한다.

복원 중 반복되는 `dup2` 실패는 복구 불가능한 경계를 검증한다. 부모가 자신의 표준 디스크립터를 복원할 수 없으면 이후 명령 I/O를 신뢰할 수 없으므로, 손상된 프로세스 환경에서 계속 실행하지 않고 셸이 상태 1과 진단 메시지로 종료해야 한다.

## refactor(runtime): heredoc 임시 파일 I/O 경계 분리
heredoc 임시 스트림 연산을 런타임 경계 뒤로 이동한다.

리다이렉션 코드는 이제 `fflush`, `rewind`, `fileno`를 직접 호출하지 않고 flush, seek, 디스크립터 추출 래퍼를 사용한다. 또한 `fseek(..., 0, SEEK_SET)`를 사용한다. 이 연산은 `rewind`와 달리 명시적인 반환 값을 제공하므로 이후 일반적인 오류 전파에 포함할 수 있다.

이 커밋은 flush와 seek 결과를 여전히 무시해 동작을 의도적으로 그대로 유지한다. 구조적인 목적은 임시 파일 준비 전체를, 이미 프로세스 및 디스크립터 시스템 호출에 사용하는 것과 동일한 경계에서 관찰하고 주입 가능하게 만드는 것이다.

## fix(heredoc): 임시 파일 저장 오류를 전파
메모리에 있는 heredoc 본문을 임시 입력 스트림으로 만드는 모든 단계를 실패 가능 연산으로 처리한다.

리다이렉션 경로는 이제 본문 write, 스트림 flush, 되감기, 디스크립터 조회가 모두 성공해야만 `dup2`를 호출한다. flush나 seek 실패를 무시하면 불완전한 데이터가 들어 있거나 파일 위치가 EOF에 있는 디스크립터를 설치할 수 있고, 명령은 리다이렉션 오류 대신 아무 진단 없이 잘린 데이터를 입력으로 받을 수 있다.

공통 오류 경로는 `errno`를 진단이나 `fclose`가 덮어쓰기 전에 저장하고, 실패한 표준 I/O 연산이 오류 코드를 남기지 않았으면 `EIO`를 대신 사용하며, 실패한 연산 이름을 표시한 뒤 스트림을 닫고 상태 1을 반환한다. 따라서 임시 스트림은 전체 준비 절차가 성공한 뒤에만 명령 입력으로 사용된다.

## test(heredoc): 임시 저장 실패의 데이터 절단 방지 검증
`fflush`와 `fseek` 실패를 주입 가능하게 만들고, heredoc의 임시 기반 스트림을 완성하거나 되감을 수 없을 때 해당 heredoc을 거부하는지 검증한다.

본문 write에 성공한 것만으로는 충분하지 않다. 버퍼링된 바이트가 임시 파일에 반영되어야 하고, 표준 입력을 교체하기 전에 파일 위치를 시작 지점으로 되돌려야 한다. 둘 중 하나의 실패를 성공으로 처리하면 명령이 잘린 데이터나 즉시 EOF를 읽을 수 있다. 회귀 케이스는 상태 1을 요구하고 `cat` 출력을 억제하며, 그 뒤 셸이 다음 명령을 실행할 수 있는지도 확인한다.

이 테스트는 임시 스트림 준비 전체가 성공한 뒤에만 리다이렉션을 명령 입력에 적용한다는 heredoc 준비 규칙을 고정한다.

## refactor(runtime): 실행 경로의 동적 할당 래퍼 통합
파이프라인 설정, heredoc 버퍼링, 입력 확장, 공용 문자열 유틸리티의 동적 할당을 하나의 런타임 계층으로 통합한다.

래퍼는 처음에는 일반 `malloc`, `calloc`, `realloc` 동작을 유지하지만, `shell_calloc`은 곱셈 오버플로를 명시적으로 검사하고 해당 조건을 `ENOMEM`으로 보고한다. 이 호출들을 한곳에 모으면 중요한 경로가 직접적인 libc 호출 뒤에 숨어 있지 않으므로 할당 정책과 테스트 계측을 일관되게 적용할 수 있다.

이는 소유권 규칙을 바꾸는 커밋이 아니라 구조적 경계를 만드는 변경이다. 기존 호출자는 여전히 실패를 복구할지 치명적으로 처리할지 결정한다. 이후 실패 전파와 결정적 할당 주입이 각 하위 시스템을 다시 작성하지 않고 전체 실행 경로를 다룰 수 있게 하는 것이 핵심이다.

## fix(memory): 구조화 단계의 할당 실패를 명령 오류로 전파
프로세스를 종료하던 할당 헬퍼를 NULL을 반환하는 연산으로 바꾸고, 메모리 부족을 셸의 기존 명령 오류 경계를 통해 전파한다.

기존 `sh_xcalloc`과 `sh_strdup`은 오류를 출력하고 `exit`를 호출했기 때문에 토큰화, 파싱, 환경 상태 복사, 단어 확장 중 할당이 실패하면 모든 소유권 정리를 건너뛰고 셸 전체가 종료됐다. 이제 유틸리티 계층은 `NULL`을 반환하고 문자열 할당이나 결합 전에 크기 연산을 검사한다. 각 호출자는 완전한 결과만 확정하거나 부분 구성물을 해제할 책임을 가진다.

환경 저장소도 이 규칙을 명시적으로 따른다. 노드의 구조체, 키, 값이 모두 준비된 뒤에만 리스트에 연결한다. 교체할 값은 기존 값을 해제하기 전에 먼저 복사한다. 환경 가져오기가 실패하면 부분 리스트 전체를 폐기하고, `env_to_environ`은 일부만 직렬화된 벡터를 해제한다. 이 순서로 교체용 할당이 실패해도 기존의 유효한 상태를 보존한다.

토큰화와 파싱 역시 각자의 경계에서 구성 과정을 트랜잭션 방식으로 만든다. 토큰 생성은 소유할 수 없는 텍스트를 해제하고, 파서의 추가 연산은 필요한 모든 할당이 끝난 뒤에만 새 배열이나 리다이렉션을 확정한다. 하나의 `parse_failure` 경로가 현재 명령, 현재 파이프라인, 이미 완성된 파이프라인 앞부분을 모두 해제한다. 확장과 소스 수준 파싱/인용 제거 API도 이제 불완전한 구조를 조용히 반환하지 않고 명시적인 할당 오류를 전달한다.

명령 루프에서는 구문 오류가 기존 내부 상태 258을 유지하고, 할당 실패는 일반 상태 1 실패로 처리되어 이후 입력을 계속 실행할 수 있다. 시작 시 환경 가져오기 실패는 사용할 수 있는 셸 상태 자체가 없으므로 여전히 치명적이지만, 이제 저수준 헬퍼 내부에서 종료하지 않고 진단 후 반환 경로를 통해 끝낸다. 이로써 할당 실패가 부분 초기화된 표현을 노출하거나 임의의 유틸리티 함수에서 실행 중인 셸을 종료하지 않는다는 프로젝트 전역 불변식을 확립한다.

## fix(memory): 실행 자원 할당 실패를 pipeline 오류로 전파
운영체제 pipe를 하나라도 만들기 전에 파이프라인 관리 테이블 두 개를 모두 할당하고, 각 테이블에 오버플로를 검사하는 할당 래퍼를 사용한다.

실행기가 생성 루프에 안전하게 진입하려면 pipe FD 테이블과 명령마다 하나의 PID 슬롯이 모두 먼저 준비되어야 한다. 두 할당을 선행하면 할당 실패는 순수한 준비 단계 오류로 남는다. 아직 자식도 없고 pipe 디스크립터도 생성되지 않았으므로 공통 할당 경로에서 상태 1을 보고하고 로컬 메모리만 해제하면 된다.

파이프 테이블에도 `shell_calloc`을 사용해 PID 테이블과 동일하게 래퍼의 곱셈 오버플로 검사를 적용한다. 다만 명시적인 `-1` 초기화는 계속 필요하다. 0으로 채워진 디스크립터는 정리 코드에서 유효한 표준 입력 디스크립터처럼 보일 수 있기 때문이다.

## fix(heredoc): 준비 실패 뒤 입력 구분자 경계 복구
heredoc 준비가 이미 실패했더라도 남아 있는 모든 구분자까지 입력을 계속 소비한다.

구분자 인용 제거, 버퍼 초기화, 본문 확장이 실패한 즉시 반환하면 현재 heredoc의 나머지 본문과 같은 파싱된 줄에 있는 이후 heredoc이 표준 입력에 남는다. 그러면 명령 루프가 이 본문 줄들을 새 셸 명령으로 해석할 수 있다. 이제 수집기는 준비 실패 상태를 기록하고 현재 본문의 나머지를 폐기하며, 이후 heredoc도 본문을 만들지 않고 구분자까지 입력만 소비한 뒤 최종 실패를 반환한다.

구분자 복구 과정에서는 인코딩된 대상과 입력을 비교하되 리터럴 마커는 건너뛴다. 따라서 이미 실패한 할당 경로에 다시 의존해 구분자의 인용을 제거하지 않아도 인용된 구분자를 찾을 수 있다. 로컬 본문 버퍼도 용량을 두 배로 늘릴 때 `SIZE_MAX / 2`를 초과하는 경우를 거부해 크기 계산 오버플로를 막는다.

핵심 불변식은 heredoc 준비가 실패할 수는 있어도 heredoc 데이터와 이후 명령의 경계를 조용히 바꿔서는 안 된다는 것이다.

## fix(input): EOF와 입력 실패를 구분
줄 입력에 명시적인 실패 채널을 추가해, 데이터가 없는 EOF를 할당 또는 `read` 오류와 더 이상 같은 결과로 처리하지 않는다.

기본 입력기는 이제 런타임 `read` 래퍼를 직접 사용하고 `EINTR`이면 재시도하며, 개행 없이 끝나는 마지막 줄을 보존하고, 용량 두 배 증가 시 오버플로를 검사한다. `NULL` 결과가 정상 EOF인지 실패인지 별도로 보고하므로 메인 루프는 정상 EOF에서 기존 마지막 상태를 유지하고 실제 입력 오류에서는 상태 1을 설정해 진단할 수 있다.

heredoc 수집도 같은 구분을 사용한다. heredoc은 복구 조건이 더 엄격하기 때문이다. 구분자 전에 EOF가 오면 기존처럼 경고 후 지금까지 수집한 본문을 사용하지만, 입력 자체가 실패하면 heredoc을 중단한다. 이런 실패 이후 수집기는 남은 입력을 구분자까지 버려 다음 명령 경계를 복구하려고 시도한다. 복구 과정의 read마저 실패하면 명령 경계를 더 이상 신뢰할 수 없으므로 셸을 종료한다.

이로써 하나의 `NULL` 포인터에서 스트림 위치와 오류 종류를 추론하지 않고, 둘 다 입력 API 계약의 일부로 명시한다.

## fix(io): builtin과 환경 출력 실패를 상태로 전파
builtin, 환경, 프롬프트 출력을 명시적인 파일 디스크립터 기반 write 헬퍼로 통과시키고 실패를 명령 상태로 전파한다.

`stdio` 호출은 오류가 이후 flush 시점까지 지연될 수 있어 어느 builtin에서 실패했는지 불분명해지고, 부모 실행기가 전역 스트림 상태를 검사해야 했다. `shell_write_all`은 부분 쓰기를 처리하고 `EINTR`이면 재시도하며, write가 0바이트를 반환하면 `EIO`로 간주하고, 해당 출력 연산에서 직접 실패를 반환한다. 따라서 `echo`, `pwd`, `cd -`, `env`, 인자 없는 `export`는 나중의 `fflush(stdout)`에 의존하지 않고 상태 1을 보고할 수 있다.

`env_print`를 `void` 함수에서 상태를 반환하는 연산으로 바꿔 여러 조각으로 구성된 환경 출력에도 같은 계약을 적용한다. 어느 조각에서든 write가 실패하면 순회를 중단하고 호출자에게 전달한다. `cd`도 `OLDPWD`나 `PWD` 갱신 중 실패를 기록해, 성공한 `chdir` 뒤 환경 또는 출력 업데이트가 실패할 수 있음을 상태에 반영한다. 디렉터리 변경 자체는 롤백하지 않지만 부분 실패를 더 이상 성공으로 보고하지 않는다.

대화형 프롬프트에도 같은 헬퍼를 사용해 프롬프트를 쓸 수 없으면 입력 획득 자체가 명시적으로 실패하게 한다. 결과적으로 출력은 뒤늦게 검사하는 부수 효과가 아니라 builtin 실행이 소유하는 명확한 경계가 된다.

## test(memory): 범위별 할당 실패 순회 검증
할당 실패 주입에 처리 단계별 범위를 추가하고 주요 명령 처리 단계마다 연속된 할당 호출 위치를 순회하며 실패를 검증한다.

런타임 할당 래퍼는 현재 단계와 명령 번호를 함께 관찰한다. 토큰화, 파싱, heredoc 입력/본문 구성, 확장, 실행이 할당 전에 명시적 범위를 설정하므로 이전 계층의 관련 없는 할당 횟수에 결합하지 않고 특정 할당 하나만 실패시킬 수 있다. 일회성 실패는 한 번 발생한 뒤 비활성화하고, 명시적인 반복 모드는 할당기를 지속적으로 사용할 수 없는 상황을 모델링한다.

순회 검증은 모든 주입 위치에서 두 가지 일관된 결과만 허용한다. 대상 연산이 깔끔하게 실패하고 이후 명령이 상태 1로 계속되거나, 지정한 위치가 해당 단계의 실제 할당 횟수보다 뒤에 있어 명령이 정상 완료되어야 한다. 별도 케이스에서는 부모 builtin 준비 실패가 환경을 변경하지 않는지, 외부 명령 준비 실패가 명령을 실행하지 않는지, heredoc 실패가 이후 입력 경계를 복구하는지, 지속적인 할당 실패가 반복 실행이나 남은 입력 실행 없이 종료되는지도 검증한다.

이로써 메모리 정리를 정상 경로가 잘 동작할 것이라는 신뢰에 맡기지 않고 체계적인 실패 경로 계약으로 만든다. 범위 마커는 테스트를 위한 경계일 뿐이며 프로덕션 할당은 계속 C 할당기에 직접 위임한다.

## test(io): read·write와 heredoc 입력 실패 검증
저수준 `read`, `write` 호출을 테스트 런타임에서 주입 가능하게 만들고 입력, builtin 출력, heredoc 수집 실패에 대한 회귀를 추가한다.

케이스는 복구 범위가 다른 실패를 구분한다. 최상위 입력 read 실패는 버퍼에 남은 명령을 실행하지 않고 상태 1로 종료해야 한다. builtin write 실패는 해당 명령 상태가 되고 다음 줄에서 그 상태를 관찰할 수 있어야 한다. heredoc read 실패는 현재 명령을 중단하되, 이후 입력을 명령으로 오해하지 않도록 남은 구분자 입력을 충분히 소비하거나 폐기해 다음 명령 경계를 복구한 경우에만 실행을 계속한다.

반복 실패 케이스는 더 엄격한 경계를 검증한다. heredoc 입력과 나머지 내용을 폐기하려는 시도까지 계속 실패하면 읽지 못한 heredoc 텍스트를 이후 명령으로 처리하지 않고 셸을 중단해야 한다. 이 테스트는 단순 상태 코드뿐 아니라 입력 스트림 위치 자체를 오류 복구의 일부로 확정한다.

## build(test): 테스트 시간 제한 하네스 추가
전용 시간 제한 실행 함수를 추가하고 smoke, fault injection, 할당 실패 테스트 스위트를 모두 이 실행 함수를 통해 실행한다.

하네스는 대상을 별도 프로세스 그룹으로 실행하고 단조 시계로 제한 시간을 측정한다. 시간 초과가 발생하거나 하네스가 `SIGHUP`, `SIGINT`, `SIGTERM`을 받으면 직접 자식을 회수하기 전에 프로세스 그룹 전체를 종료한다. 멈춘 셸이 이미 파이프라인 자식을 fork했을 수 있으므로 그룹 정리가 중요하다. 직접 프로세스만 종료하면 테스트가 실패한 뒤에도 하위 프로세스가 남을 수 있다. 자식의 정상 종료와 시그널 상태는 관례적인 상태 값으로 보존하고, 시간 제한과 하네스 자체의 실패는 서로 구분한다.

실행 전에 테스트 입력을 파일에 기록해 입력 생성자 역할의 셸 파이프라인을 테스트 대상 프로세스 그래프에서 제거한다. 따라서 각 케이스는 시간 상한이 있는 독립 실행이 되며, 멈춤 상태가 전체 테스트 스위트를 막거나 백그라운드 프로세스를 남기지 않고 결정적으로 보고된다.

## test(lifecycle): FD와 자식 프로세스 누수 검증
일반적인 출력 검증만으로는 안정적으로 드러나지 않는 두 자원, 즉 파일 디스크립터와 직접 자식 프로세스에 대한 수명 주기 회귀 검증을 추가한다.

테스트 스위트는 프로세스의 디스크립터 상한을 48로 제한한 상태에서 부모에서 실행되는 리다이렉션, 3단계 파이프라인, 파일 입출력을 반복적으로 섞어 실행한다. 진단 없이 마지막 마커까지 도달하면 각 명령이 임시 디스크립터를 반환해 점차 프로세스 테이블을 고갈시키지 않았음을 보여 준다. 테스트 전용 파이프라인 실행 후 검사는 `waitpid(-1, ..., WNOHANG)`를 사용해 실행기가 완료를 보고한 뒤에도 직접 자식이 실행 중이거나 회수되지 않은 좀비로 남아 있으면 실패시킨다.

시간 제한 케이스는 블로킹된 파이프라인이 시간 한도 안에 정리되는지와 시간 제한 하네스 종료가 자신이 실행한 프로세스를 고아 프로세스로 남기지 않는지도 검증한다. 이 검사를 `SMALL_SHELL_TESTING` 뒤에 두어 프로덕션 프로세스 모델은 유지하면서 테스트 바이너리에서는 수명 주기 불변식을 직접 관찰할 수 있게 한다.

## refactor(env): 사용하지 않는 환경 저장소 래퍼 제거
사용하지 않는 센티널을 인식하는 `shell_env_*` 래퍼 계층을 제거하고 연결 리스트 `env_*` 인터페이스를 유일한 환경 저장소 계약으로 남긴다.

래퍼는 합성 센티널 노드와 직접 리스트 헤드 두 표현을 모두 지원했지만, 남은 호출부 중 이 대체 표현을 사용하는 곳은 없다. 이를 유지하면 실제 호환성 경계 없이 같은 데이터에 대해 소유권과 변경 모델 두 개를 남기게 된다. 선언과 구현을 삭제해 향후 코드가 잘못된 모델로 환경을 초기화하거나 해제할 위험을 줄이되 런타임 동작은 의도적으로 바꾸지 않는다.

## refactor(buffer): 가변 문자열 빌더 모듈 추가
초기화, 추가, 폐기, 소유권 이전 연산이 명시된 재사용 가능한 문자열 빌더를 추가한다.

빌더는 항상 NUL 종단 상태를 유지하고 작은 초기 할당에서 시작해 용량을 기하급수적으로 늘린다. `length + extra + 1` 계산과 용량 2배 확장 모두 `SIZE_MAX` 오버플로를 검사하며, 한 번 더 두 배로 늘리면 오버플로가 발생하는 경우 정확히 필요한 용량으로 확장한다. 모든 할당은 런타임 래퍼를 거치므로 기존 할당 실패 주입으로 초기화와 증가 경로를 검증할 수 있다.

`discard`와 `take`를 분리해 호출부에서 소유권을 명확하게 드러낸다. 구성 실패 시 부분 버퍼를 해제하고, 성공 시 할당을 호출자에게 이전한 뒤 빌더를 초기 상태로 되돌린다. 이 추상화는 이후 어휘 단어 구성과 확장에서 함께 사용하는 성능 및 정리 계약을 제공한다.

## refactor(lexer): 단어 조립을 가변 버퍼로 전환
소스 문자마다 완성된 토큰 텍스트 전체를 다시 할당하는 대신 공용 가변 버퍼에서 렉서 단어를 조립한다.

작은따옴표 구간은 각 문자를 리터럴 마커와 실제 문자 두 바이트로 인코딩하므로 이 변경이 특히 중요하다. 두 바이트를 하나의 빌더에 추가하면 전체 버퍼 복사를 반복하지 않고 기존 표현을 유지할 수 있다. 인용되지 않은 텍스트와 큰따옴표 텍스트의 인코딩, 토큰 단위 `quoted` 플래그는 기존과 동일하게 유지한다.

렉서의 부분 결과 처리 규칙도 명확해진다. 할당 실패 또는 닫히지 않은 인용이 발생하면 빌더를 폐기하고, 유효한 단어라면 완성된 버퍼의 소유권을 토큰에 이전한다. 따라서 구문 오류 정리나 인용 의미를 약화하지 않으면서 점근적 동작을 개선한다.

## refactor(expand): 확장 결과를 가변 버퍼로 조립
문자나 치환을 하나 추가할 때마다 완성된 새 문자열을 할당하고 복사하지 않고, 공용 가변 문자열 빌더를 사용해 확장된 단어와 인용 제거된 단어를 구성한다.

기존 `sh_strjoin_free` 반복은 데이터를 추가할 때마다 지금까지 쌓인 전체 출력을 복사하므로 긴 단어의 비용이 계속 증가했다. 용량을 기하급수적으로 늘리는 버퍼에 데이터를 추가하면 리터럴 마커, `$?`, 환경 변수 이름, 설정되지 않은 값, 빈 결과 처리 의미는 유지하면서 구성 비용을 상각 선형 시간으로 바꿀 수 있다.

실패 처리도 명시적인 빌더 소유권 규약을 따른다. 부분 문자열 할당이나 데이터 추가가 실패하면 부분 버퍼를 폐기하고, 성공한 경우에만 완성된 할당을 이전한다. 따라서 호출자 관점에서 확장은 원자적하다. 완전한 소유 문자열을 반환하거나 부분 결과를 전혀 노출하지 않는다.

## test(performance): 긴 입력 처리 시간 상한 검증
512 KiB 단어를 전체 입력, 토큰화, 파싱, 확장, builtin 출력 경로로 통과시키고 5초 제한 시간 안에 처리되는지 검증하는 회귀 검증을 추가한다.

테스트는 단순 프로세스 완료만 확인하지 않는다. 상태가 0이어야 하고 진단 출력이 없어야 하며, 마지막 개행을 포함한 출력 데이터 길이도 정확히 일치해야 한다. 이로써 문자열 빌더가 의도한 상각 성능 특성을 end-to-end에서 관찰 가능한 제약으로 만들고, 전체 문자열을 반복 복사하는 동작이 다시 들어오거나 큰 입력이 잘리는 회귀를 탐지한다.

## build(test): ASan·UBSan 검증 경로 추가
프로덕션 바이너리, fault injection 바이너리, 소스 수준 파서 API 테스트 각각에 전용 AddressSanitizer와 UndefinedBehaviorSanitizer 빌드 그래프를 추가하고, 기존 smoke·실패·할당·수명 주기·파서·성능 테스트 스위트를 sanitizer가 적용된 산출물에 대해 실행한다.

sanitizer 바이너리를 일반 오브젝트와 분리해 호환되지 않는 컴파일 산출물을 실수로 재사용하지 않고, 테스트 경계도 제품 실행 경로와 동일한 런타임 검사로 계측되도록 한다. 테스트 스크립트는 의도적으로 `env -i`로 환경을 다시 구성하는 경우에도 sanitizer 옵션을 보존해 fault injection이 진단을 우연히 비활성화하지 않도록 한다.

컨테이너 타깃은 컴파일러/런타임 환경을 GCC 13으로 고정하고 네트워크 접근을 제거하며 저장소를 읽기 전용으로 마운트한 뒤 tmpfs 작업 영역으로 복사해 빌드한다. 이렇게 생성되는 오브젝트와 바이너리에 필요한 쓰기 권한은 유지하면서 검증 경로의 재현성을 확보한다.

## fix(exec): pipe 생성 실패 시 PID 배열 해제
실행 배열 두 개를 모두 할당한 뒤 파이프라인 pipe 생성이 실패하면 PID 배열도 해제한다.

이 실패는 자식을 하나도 생성하기 전에 발생하므로 정리 책임은 전적으로 부모에 있고, 파이프라인 준비 중 획득한 모든 자원을 정리해야 한다. 이미 열린 pipe FD를 닫고 파이프 테이블을 해제한 뒤 아직 로컬에만 있는 PID 테이블도 해제한다. 이 반환 경로에서 PID 할당을 남겨 두면 실제 또는 주입된 `pipe` 실패마다 실행을 시작하지도 않았는데 메모리가 누수된다.
