## feat(parse): 철학자 실행 인자 검증
명령행 인자 계약을 별도의 `t_config` 값으로 표현하고, 동시 실행 상태를 만들기 전에 이를 검증한다. `philo_parse_args`는 필수 숫자 인자 네 개와 선택적 식사 목표 횟수만 허용하며, 목표 횟수가 생략된 경우에는 `has_meal_limit`으로 구분한다. 정규화된 값은 이후 런타임 코드가 문자열을 다시 파싱하지 않고 사용할 수 있도록 필드에 저장한다.

숫자 변환 헬퍼는 관대한 라이브러리 변환 함수를 호출한 뒤 사후 검증하는 대신, 변환 과정 자체에서 유효성을 검사한다. 선행 `+` 하나는 허용하지만 빈 문자열, 숫자 없는 부호, 10진수가 아닌 문자, 0, 음수 형식은 거부한다. 또한 다음 곱셈과 덧셈을 수행하기 전에 대상 타입의 범위를 넘는지 검사한다. 따라서 래핑된 산술이나 구현별 변환 동작에 의존하지 않고 오버플로를 결정적으로 거부할 수 있다.

철학자 수는 프로젝트 제한인 200 이하로 제한하며, 선택적 식사 목표 횟수는 `int`로 축소하기 전에 `INT_MAX` 이하인지 확인한다. 잘못된 입력을 시뮬레이션 초기화 이전 단계에서 차단하므로 이후 코드는 철학자 수와 시간 값이 모두 양수이고, 선택적 완료 목표가 올바르게 구성되어 있다고 가정할 수 있다.

## feat(cli): 입력 계약을 실행 진입점에 연결
실행 진입점에서 파싱을 프로그램 수명주기의 첫 번째 관문으로 사용한다. 잘못된 입력이면 전체 사용법을 표준 오류에 출력하고 0이 아닌 상태로 종료하며, 올바른 입력이면 일부만 해석된 값이 이후 코드에 노출되지 않은 채 정상 성공 경로로 진행한다.

이 단계에서는 파싱한 설정을 아직 실제로 실행하지 않지만, `main`에 연결함으로써 앞으로 추가될 테이블 및 스레드 구현과 독립적으로 실행 파일의 공개 동작을 확정한다. 또한 인자 검증을 동기화 자원이나 worker 생성 없이도 테스트할 수 있도록 분리한다.

## build(philo): 실행 파일 빌드 규약 구성
필수 `philo` 실행 파일을 재현 가능하게 빌드할 수 있는 구성을 추가한다. 모든 translation unit을 `-Wall`, `-Wextra`, `-Werror`로 컴파일하고, `-pthread`도 같은 플래그 집합에 포함해 컴파일과 링크 모두 소스가 기대하는 POSIX 스레드 모델을 사용하도록 한다.

패턴 규칙을 통해 object 파일을 `.obj` 아래에 분리하고, `clean`, `fclean`, `re`로 생성 상태의 전이를 명확히 한다. 지원하지 않는 변형이 있는 것처럼 조용히 넘어가는 대신 `bonus` 타깃은 의도적으로 실패한다. 생성된 실행 파일, object, dependency 산출물과 로컬 파일 시스템 잡음도 버전 관리에서 제외해 저장소 상태와 빌드 결과를 분리한다.

## feat(init): 테이블 저장소와 철학자 관계 초기화
시뮬레이션에 명시적인 소유권 모델을 도입한다. `t_table`은 변경되지 않는 런타임 설정, 전역 종료 및 식사 완료 상태, 동기화 객체, 포크 배열, 철학자 배열을 소유한다. 각 `t_philo`는 자신의 식별자와 worker별 진행 상태를 소유하고, 두 포크와 공유 테이블은 포인터로 참조한다.

포크 관계는 원형으로 구성한다. 철학자 `i`의 왼쪽 포크는 `forks[i]`, 오른쪽 포크는 `forks[(i + 1) % number]`를 가리킨다. 이 표현은 인접한 철학자들이 포크 상태의 복사본을 갖는 것이 아니라 같은 mutex 객체를 참조한다는 점을 데이터 모델에 드러내며, modulo 연산으로 마지막 철학자에 대한 별도 예외 처리 없이 원형 테이블을 닫는다.

두 배열은 연속 메모리로 할당하고 실행 전에 초기화한다. 할당에 실패하면 테이블 destructor 경로를 통해 이미 성공한 할당만 해제하고 해당 포인터를 null 상태로 만든다. 이 커밋에서는 저장 공간과 토폴로지만 확립한다. 동기화 객체 초기화는 별도 단계로 추가해 자원 구성을 명확한 단계별 수명주기로 발전시킬 수 있게 한다.

## feat(init): 뮤텍스 수명주기와 실패 롤백 구현
테이블 초기화 과정에서 공유 상태 설계에 필요한 동기화 자원을 구성한다. 상태 mutex 하나, 출력 mutex 하나, 포크마다 mutex 하나를 초기화한다. 준비 여부 플래그와 `fork_count`로 실제 초기화에 성공한 객체를 기록하므로, 공통 destructor가 한 번도 초기화되지 않은 객체를 조작하지 않도록 한다.

초기화는 성공한 단계마다 테이블이 소유하는 자원 기록을 확장하는 순서로 진행한다. 이후 단계에서 실패하면 동일한 테이블 수준 rollback 경로를 호출하고, 정상 파괴 시에는 초기화된 포크 범위를 순회한 뒤 공유 mutex를 해제하고 배열 메모리를 반환한다. 이는 부분 생성에 적합한 일반적인 모델이다. 정리는 최종적으로 요청된 구성값이 아니라 실제로 확보한 자원 기록을 기준으로 수행해야 한다.

다만 이 시점의 포크 초기화 헬퍼는 뒤쪽 포크 초기화가 실패하면 앞서 초기화한 포크들을 자체적으로 파괴하면서도 공통 destructor가 참조하는 `fork_count`는 그대로 둔다. 이 때문에 정리 책임이 중복되고 rollback 과정에서 같은 mutex를 다시 파괴할 가능성이 생긴다. 이후 커밋에서 로컬 파괴를 제거하고 자원 기록 기반 destructor가 rollback을 단독으로 담당하도록 수정한다. 따라서 이 커밋은 수명주기 설계의 기반을 마련하지만, 아직 정확히 한 번만 정리하는 최종 구현은 아니다.

## feat(time): 밀리초 시각 계산 함수 추가
시간 처리를 worker와 monitor 코드 곳곳에 분산하지 않고 `philo_now_ms`와 `philo_sleep_ms`로 모은다. 현재 시각을 정수 밀리초로 변환해 시뮬레이션 시작 시각, 식사 기한, 로그 timestamp, 설정된 시간 간격에 동일한 표현을 사용한다.

대기는 중간에 끊을 수 없는 한 번의 sleep 대신 deadline loop로 구현한다. 각 반복에서 `state_mutex`를 잡고 공유 종료 플래그를 확인해 시뮬레이션이 끝났으면 즉시 빠져나오며, 그렇지 않으면 500마이크로초 `usleep`으로 실행을 양보한다. 이 방식은 일정한 polling 비용을 추가하는 대신 종료 반응성을 높인다. 다른 스레드가 이미 종료 상태를 확정한 뒤에도 worker가 설정된 전체 대기 시간을 계속 기다리지 않게 한다.

이 시점에는 `gettimeofday`를 사용하므로 경과 시간 계산이 여전히 wall clock 조정의 영향을 받고, 호출 실패도 처리하지 않는다. 이후 시간 관련 수정에서 monotonic clock으로 교체한다. 여기서 시간 접근을 추상화해 둔 덕분에 시뮬레이션 전체를 수정하지 않고도 구현을 국소적으로 바꿀 수 있다.

## feat(log): 상태 로그의 동시 출력 보호
공유 종료 상태 접근과 출력 직렬화를 작은 상태 API 뒤로 이동한다. `philo_has_ended`와 `philo_finish`는 `state_mutex`를 잡은 상태에서 종료 플래그를 읽거나 설정하므로 worker와 monitor가 해당 플래그를 동기화 없이 직접 접근하지 않는다.

일반 상태 메시지는 `print_mutex`를 획득한 뒤 종료 여부를 다시 확인하고, 테이블 시작 시각을 기준으로 timestamp를 계산한 다음 한 줄 전체를 출력한다. 종료 확인과 `printf`를 모두 print mutex 안에서 수행하므로 서로 다른 worker의 필드가 한 줄에 섞이는 것을 막고, 종료 이후 관찰된 일반 로그를 억제한다. 전용 사망 경로 역시 `ended`를 한 번만 변경하고 guard를 사용해 최대 한 호출자만 `died`를 출력하도록 한다.

다만 종료 상태 전이와 사망 출력은 아직 하나의 원자적 로그 transaction이 아니다. 사망 경로는 `state_mutex`를 놓은 뒤 `print_mutex`를 획득한다. 따라서 이미 print lock을 잡고 있던 일반 logger가 사망 상태가 게시되기 전에 종료 검사를 통과한 뒤, 사망 경로가 print lock을 기다리는 동안 로그를 출력할 수 있다. 이후 이력에서는 공통 lock 순서 아래에서 사망 조건을 다시 검증하고 종료 상태 게시와 마지막 줄 출력을 직렬화한다. 이 커밋은 그 강한 불변식을 구현하기 위한 출력 경계를 먼저 마련한다.

## feat(routine): 철학자의 식사·수면·사고 흐름 구현
worker routine에 시뮬레이션의 핵심 사이클을 구현한다. 철학자는 두 포크 mutex를 획득하고, 공유 상태 lock 아래에서 식사 시작 시각을 기록한 뒤 식사 로그를 남긴다. 설정된 식사 시간만큼 기다리고 식사 완료를 기록한 다음 두 포크를 해제한다. 이후 종료 플래그가 관찰될 때까지 수면과 사고를 반복한다.

포크 획득 순서는 철학자 ID의 홀짝에 따라 달라진다. 짝수 ID는 오른쪽 포크 후 왼쪽 포크를, 홀수 ID는 왼쪽 포크 후 오른쪽 포크를 획득한다. 모든 worker가 왼쪽 포크부터 잡을 때 생길 수 있는 단일 원형 대기 순서를 깨므로, 각 worker가 포크 하나씩을 든 채 서로를 기다리는 고전적인 deadlock을 방지한다. 짝수 worker에 1밀리초의 초기 지연도 두어 즉시 발생하는 경쟁을 줄이지만, 이는 scheduling 보조 수단일 뿐 fairness 보장은 아니다.

식사 시각과 완료 횟수는 `state_mutex`로 동기화한다. 식사를 시작할 때 `last_meal_ms`를 갱신해 monitor가 일관된 기아 기준 시각을 보도록 하고, 철학자 자신의 카운터가 정확히 `must_eat`와 같아지는 순간에만 `full_count`를 증가시켜 각 철학자가 전역 완료에 최대 한 번만 기여하게 한다.

초기 routine은 왼쪽과 오른쪽 포크가 서로 다른 객체라고 가정하며, interruptible wait가 아직 완료 여부를 반환하지 않으므로 반환값도 고려하지 않는다. 따라서 철학자가 한 명이면 같은 non-recursive mutex를 두 번 잠그려 하고, 전역 종료로 식사가 중단되어도 완료된 식사로 계산한다. 두 가정은 이후 커밋에서 수정되며, 첫 번째 완전한 worker 메커니즘이 가진 중요한 역사적 경계다.

## feat(monitor): 사망과 식사 완료 조건 감시
메인 실행 스레드에 전역 종료를 결정하는 monitor loop를 추가한다. worker는 각자의 식사 timestamp와 카운터를 갱신하고, monitor는 `state_mutex` 아래에서 해당 값을 검사한다. 모든 철학자가 선택적 식사 목표를 달성하면 실행을 끝내고, 마지막 식사 이후 경과 시간이 `time_to_die`에 도달한 첫 철학자를 선택해 사망으로 처리한다.

이 역할 분리는 종료 정책을 개별 worker에서 분리한다. worker가 다른 worker의 사망을 판단하지 않고, 전역 식사 완료는 동기화되지 않은 개별 스레드 관찰이 아니라 공유 `full_count`에서 결정된다. 500마이크로초 간격의 polling으로 탐지 지연과 계속 CPU를 점유하는 monitor loop 사이의 균형을 맞춘다.

첫 구현에서는 여전히 관찰과 확정을 분리한다. 완료 여부는 lock 안에서 감지하지만 `philo_finish`는 lock을 해제한 뒤 호출하고, 사망 후보도 샘플링한 시각으로 선택한 뒤 상태 critical section 밖에서 로그를 남긴다. 이 간격 때문에 판단과 종료 상태 게시 사이에 상태가 바뀔 수 있다. 이후 이력에서는 완료 상태를 lock 안에서 확정하고, 사망도 게시와 출력 직전에 다시 검증한다.

## feat(thread): 철학자 작업 스레드 시작과 종료
`philo_run`이 worker 생성, monitoring, join을 담당하도록 한다. 시뮬레이션 시작 시각을 기록하고 각 철학자의 기아 기준 시각을 초기화한 뒤, 철학자마다 하나의 스레드를 생성한다. 모든 생성에 성공하면 호출 스레드에서 monitor를 실행하고, 종료 후 모든 worker를 join한 다음 반환한다.

부분 생성 실패 경로에서는 종료 상태를 게시하고 실제로 시작된 스레드만 join한다. 이는 필수적인 자원 경계다. 성공적으로 생성된 worker가 아직 해당 메모리를 참조할 수 있는 동안 테이블 저장 공간이나 동기화 객체를 파괴해서는 안 된다. 시작된 스레드 집합을 모두 join한 뒤에야 오류를 반환하므로 호출자가 일반 실패 경로에서 안전하게 정리할 수 있다.

이 시점에는 시작 timestamp를 스레드 생성 loop 전에 잡고, 각 worker는 자신의 `pthread_create`가 반환되는 즉시 실행될 수 있다. 따라서 나중에 생성되는 worker는 스레드 생성 지연만큼 사망 제한 시간을 이미 소모하게 되며, join 실패도 무시한다. 이후 start barrier와 lifecycle 기록이 이 두 가정을 보완하지만, orchestration 책임 자체는 이 커밋에서 확립된다.

## feat(main): 입력부터 자원 정리까지 실행 흐름 연결
실행 파일에 정상 전체 수명주기를 연결한다. 설정을 파싱하고, 테이블을 초기화하고, 동시 시뮬레이션을 실행한 뒤 테이블 자원을 파괴한다. 각 단계에는 별도의 실패 메시지와 0이 아닌 종료 상태가 있으며, 정상 실행과 일반적인 런타임 실패 모두 테이블 정리 경로를 거친다.

이로써 `main`은 파서나 worker 안에 할당 또는 스레드 정책을 넣는 대신 프로세스 수준의 실행 순서를 담당한다. 결과 계약은 단순하다. 초기화는 사용 가능한 테이블을 반환하거나 이미 rollback을 마치며, 실행은 worker들이 종료했다고 가정할 수 있는 시점에만 반환하고, 파괴 단계는 테이블이 소유한 자원을 해제한다.

그러나 마지막 가정은 join 실패가 아직 보고되지 않기 때문에 구현이 실제로 보장할 수 있는 것보다 강하다. 이후 lifecycle 강화에서 worker가 여전히 실행 중일 가능성이 있는 경우를 나타내는 명시적 unsafe 상태를 추가하고, 이때는 자원 파괴를 막는다. 이 커밋은 이후 오류 모델이 세분화하는 최상위 책임 경계를 먼저 확립한다.

## fix(single): 철학자가 한 명일 때 포크 재잠금 방지
철학자가 한 명이면 원형 매핑 때문에 `left_fork`와 `right_fork`가 같은 mutex를 가리킨다. 일반 포크 획득 routine은 non-recursive mutex를 잠근 뒤 같은 스레드에서 다시 잠그려 하므로, monitor가 요구되는 사망 시나리오를 완료하기도 전에 영원히 block된다.

전용 단일 철학자 경로에서는 유일한 포크를 한 번만 잠그고, 가능한 단 하나의 포크 획득 이벤트를 출력한 뒤 `time_to_die`보다 약간 더 오래 기다리고 포크를 해제한 후 반환한다. 사망 감지와 로그는 여전히 monitor가 담당하므로 다중 worker 실행과 동일한 권한 경계를 유지한다.

이 특수 처리는 가짜 두 번째 포크를 만들거나 locking을 우회하지 않고 실제 자원 제약을 모델링한다. 철학자 한 명은 포크 하나를 집을 수 있지만 식사는 시작할 수 없다. interruptible wait 덕분에 외부에서 종료 상태가 확정되면 worker도 신속히 포크를 놓을 수 있다.

## fix(meals): 식사 제한 도달 시 작업 루프 즉시 중단
식사 제한 완료를 마지막 필수 식사를 기록한 worker가 직접 확정하도록 한다. `record_meal_done`은 `state_mutex`를 잡은 상태에서 철학자의 카운터를 증가시키고, 정확히 임계값에 도달했을 때 `full_count`에 기여하며, 모든 철학자가 기여한 순간 즉시 `ended`를 설정한다. 따라서 완료 전이를 monitor의 polling 지연에서 분리한다.

`eat_once`는 상태를 반환하는 연산이 되며 두 포크를 모두 획득한 뒤 종료 여부를 다시 확인한다. 이 worker가 포크를 기다리는 동안 다른 worker가 시뮬레이션을 완료했다면 새 식사를 시작하지 않고 두 자원을 모두 해제한다. 완료된 식사 이후에도 종료 여부를 다시 확인해 전역 식사 목표 달성 뒤에 수면이나 사고 로그를 남기지 않는다.

이 변경은 진행 중인 사이클과 다음 상태로 넘어갈 수 있는 조건 사이의 경계를 강화한다. 포크를 소유했다는 사실만으로 종료 후 새 식사를 시작할 권한이 생기지는 않는다. 다만 이 시점에는 전역 종료로 식사 대기가 중단되어도 카운터가 증가한다. 이후 중단된 식사 수정에서 전체 식사 시간이 끝난 경우에만 완료로 인정하도록 바꾼다.

## fix(parse): 밀리초 인자의 상한 적용
세 개의 시간 인자도 `INT_MAX`를 초과하면 거부하도록 해, 선택적 식사 목표에 이미 적용된 공개 입력 범위와 맞춘다. 파싱 자체는 더 넓은 중간 타입을 사용하므로 문법적으로 유효하지만 애플리케이션 범위를 벗어나는 값은 host `long`이 표현할 수 있다는 이유만으로 받아들이거나 축소하지 않고 명시적으로 거부한다.

이는 숫자 파서가 표현할 수 있는 범위와 애플리케이션이 지원하는 입력 계약을 분리한다. 변환기는 넓은 표현 범위에서 오버플로를 안전하게 감지하고, 시뮬레이션에는 지정된 동작 범위 안의 duration만 전달한다. 이 제한은 이후 시간 계산에서 극단적인 deadline 산술과 플랫폼 의존 동작이 발생할 위험도 줄인다.

## fix(cli): 명령행 오류 출력 길이 계산
오류 출력에서 수동으로 관리하던 byte 길이 상수를 제거한다. 로컬 문자열 길이 헬퍼와 `put_error` wrapper가 각 메시지를 표준 오류에 쓰기 전에 정확한 크기를 계산하며, usage, 초기화 실패, 런타임 실패 모두 같은 경로를 사용한다.

문자열 리터럴과 숫자 상수 사이의 숨은 결합이 사라진다. 메시지 문구를 바꿔도 출력이 조용히 잘리거나 `write`가 리터럴의 유효 범위를 넘어 읽도록 만들지 않는다. buffering을 사용하지 않는 오류 출력을 한곳에 모아 프로세스 실패 보고를 표준 출력 buffering과 분리한다.

## test(smoke): 주요 입력과 종료 조건 검증
`make test`에 portable shell smoke suite를 연결해 실행 파일의 공개 명령행 및 출력 인터페이스를 검증한다. 임시 출력은 별도 공간에 두고 trap으로 제거하며, block될 수 있는 각 시뮬레이션은 별도의 timeout 프로세스로 감싸 deadlock이나 종료 조건 누락을 제한된 시간 안의 테스트 실패로 바꾼다.

테스트는 잘못된 철학자 수와 숫자 overflow를 다루고, 단일 철학자 실행에서 포크 획득과 사망이 모두 출력되는지 확인하며, 유한한 두 식사 스케줄이 사망 없이 정상 종료하는지 검증한다. 식사 횟수 검증은 정확히 하나의 interleaving을 요구하지 않고 최소 횟수를 기준으로 한다. 이는 scheduler에 따라 실행 순서가 달라질 수 있음을 허용하면서도 모든 실행이 의도한 전역 작업 임계값에 도달했음을 확인하는 방식이다.

이들은 black-box 검사다. 내부 lock 순서를 가정하지 않고 외부에서 관찰 가능한 파싱, 종료, 진행 계약을 검증한다. 자체적으로 race freedom이나 가능한 모든 schedule을 증명하지는 않지만, 이후 결정적 fault injection 및 concurrency 테스트가 확장할 수 있는 반복 가능한 기준선을 만든다.

## fix(time): 짧은 대기 시간의 초과 지연 완화
interruptible sleep loop가 deadline에 가까워질수록 polling 간격을 조절하도록 한다. 1밀리초보다 많이 남았을 때는 계속 500마이크로초씩 대기하지만, 마지막 구간에서는 100마이크로초 간격으로 전환한다.

짧은 설정 시간이나 deadline 직전 wakeup에서 발생하는 overshoot를 줄이면서도 전체 대기 동안 가장 높은 polling 빈도를 사용할 필요는 없다. 함수는 매 반복마다 전역 종료 상태를 확인하므로, 고정 500마이크로초 단위가 상대적으로 큰 구간에서 시간 정밀도를 높이면서 종료 반응성도 유지한다.

구현은 여전히 협력적 polling sleep이지 real-time 보장이 아니다. scheduler 지연으로 wakeup이 늦어질 수는 있다. 이 변경이 줄이는 것은 프로그램 자체가 추가하는 피할 수 있는 지연이며, 구현이 통제할 수 있는 속성은 이 부분이다.

## test(format): 필수 상태 로그 형식 검증
smoke suite에서 텍스트 로그 grammar를 실행 가능한 계약으로 취급한다. `awk` validator는 숫자 timestamp, 양의 철학자 ID, 다섯 개의 필수 상태 문구 중 하나로 구성된 줄만 허용하며 그 외 모든 줄을 거부한다.

단일 철학자, 유한 식사, 더 큰 사망 없음 실행에 validator를 적용해 잘못된 형식뿐 아니라 interleaved write로 인한 출력 손상도 탐지한다. 이제 예상 substring이 포함되어 있다는 이유만으로 동시에 깨진 줄이나 예상하지 않은 줄을 출력하는 실행이 통과할 수 없다.

검사는 특정 이벤트 순서가 아니라 syntax만 검증한다. 올바른 스레드 schedule에서도 동작 순서는 달라질 수 있기 때문이다. 이후 concurrency 테스트에서 이 기본 형식 계약 위에 timestamp 순서와 종료 줄의 위치 같은 속성을 추가한다.

## fix(init): 포크 초기화 실패 시 중복 정리 방지
포크 rollback을 `philo_table_destroy` 한 곳으로 통합한다. 포크 초기화 헬퍼는 이제 실패를 보고할 뿐 자체적으로 아무것도 파괴하지 않으며, `fork_count`를 성공적으로 초기화된 포크 mutex의 유일한 기준으로 둔다. destructor는 해당 카운트를 역순으로 소비한 뒤 공유 mutex를 해제하고 준비 플래그를 초기화한다.

이렇게 하면 정확한 소유권 규칙이 복원된다. 초기화된 각 동기화 객체에는 하나의 정리 책임자만 있으며 최대 한 번만 파괴된다. 역순으로 자원 기록을 줄여 나가므로 부분 진행 상태와도 일관되고, 플래그와 카운터를 초기화해 두 번째 cleanup 호출이 이미 해제된 테이블에 다시 파괴 작업을 수행하지 않게 한다.

이 수정은 헬퍼와 테이블 destructor가 같은 포크 mutex를 모두 조작할 수 있었던 이전의 분산 책임 설계를 해결한다. 여기서 공통 rollback 경로는 단순한 코드 재사용이 아니라, 어느 초기화 단계에서 실패하더라도 정확히 한 번만 자원을 해제하도록 보장하는 메커니즘이다.

## test(init): 부분 뮤텍스 초기화 롤백 검증
initializer를 컴파일할 때 `pthread_mutex_init`과 `pthread_mutex_destroy`를 대체해 결정적인 fault injection 테스트를 구성한다. mutex 세 개가 성공한 뒤 네 번째 초기화 호출을 강제로 실패시키고, 모든 파괴 대상 주소를 기록해 중복 해제를 직접 탐지한다.

테스트는 초기화가 실패를 반환하는지, 실제 소유한 mutex 세 개만 정확히 파괴되는지, 두 할당 배열이 모두 해제되고 포인터가 null 상태가 되는지, 그리고 이후 테이블 destructor를 다시 호출해도 추가 파괴가 발생하지 않는지 확인한다. 자연스럽게 발생하기 어려운 할당 또는 pthread 실패에 기대지 않고 자원 rollback 기록 자체를 검증한다.

컴파일 단계에서 동기화 API만 interpose하므로 제품 초기화 및 cleanup 코드에 테스트 분기를 추가하지 않고도 실제 구현을 실행한다. 이로써 정확히 한 번의 자원 해제와 실패 후 cleanup의 idempotence를 모두 고정한다.

## fix(time): 단조 시계로 경과 시간 계산
경과 시간 측정을 wall time에서 `clock_gettime(CLOCK_MONOTONIC)`으로 변경한다. 시뮬레이션 시작 시각, 마지막 식사 시각, deadline, 로그 offset이 모두 시스템 달력 변경의 영향을 받지 않는 clock을 공유하므로, 시간이 뒤로 가거나 갑자기 앞으로 보정되어 거짓 기아를 만들거나 대기 시간을 늘리는 문제를 막는다.

시간 필드와 파서의 중간값을 `int64_t`로 변경하고, 로그 형식에서는 고정 폭 값을 명시적으로 cast한다. 이를 통해 의도한 숫자 범위가 플랫폼의 `long`이 32비트인지 64비트인지에 의존하지 않으며, parser, monitor, state logger, sleeper 사이의 밀리초 산술도 일관되게 유지된다.

monotonic clock을 얻지 못하면 프로세스 치명적 오류로 취급한다. 모든 worker와 monitor의 판단이 같은 시간 소스에 의존하므로, 임의의 timestamp를 만들어 계속 실행하거나 일반적인 cross-thread unwinding을 시도하면 시뮬레이션의 정확성을 정의할 수 없다. 따라서 간단한 비버퍼링 `write` 인터페이스로 고정 오류를 출력하고 `_exit`를 호출한다.

## test(time): 단조 시계와 시계 실패 경로 검증
컴파일 시 `clock_gettime`을 대체해 시간 추상화를 테스트한다. 성공 stub은 요청된 clock 식별자를 기록하고 알려진 `timespec`을 반환하며, 이를 통해 `CLOCK_MONOTONIC` 사용 여부와 초·나노초에서 밀리초로의 정확한 변환을 모두 검증한다.

fatal 분기는 자식 프로세스에서 실행한다. stub을 실패 모드로 전환하고 `philo_now_ms`를 호출한 뒤, 부모는 자식이 `PHILO_ERR`로 종료되었는지 확인한다. fork로 의도적인 `_exit`를 격리하므로 테스트 runner 자체를 종료하지 않고 프로세스 수준 계약을 검사할 수 있다.

두 검사를 합쳐 시간 관련 결정의 양쪽을 보호한다. 경과 시간은 올바른 clock domain에서 가져와야 하며, 해당 clock을 사용할 수 없다면 확인되지 않은 값이나 오래된 값을 반환하는 대신 실행을 중단해야 한다.

## fix(thread): 시작 장벽으로 기준 시각 통일
worker 시작을 condition variable 기반 barrier로 변경한다. 각 worker는 `state_mutex`를 획득하고 `ready_count`를 증가시킨 뒤 coordinator에 알리고, `start_released`가 참이 될 때까지 predicate loop 안에서 대기한다. coordinator는 성공적으로 생성된 모든 worker가 준비될 때까지 기다린 후 하나의 monotonic 시작 시각을 샘플링해 table과 모든 철학자의 `last_meal_ms`에 저장하고 release를 broadcast한다.

이 변경으로 사망 제한 시간의 의미가 달라진다. barrier 도착 전의 스레드 생성 및 scheduler 지연은 더 이상 먼저 생성된 worker의 기아 시간으로 계산되지 않으며, 모든 worker가 같은 시간 기준을 공유하기 전에는 어느 worker도 포크 획득을 시작할 수 없다. 초기 상태 게시와 barrier release를 state lock 안에서 수행하므로, worker가 일부 식사 timestamp만 초기화된 상태에서 release된 barrier를 관찰할 수 없다.

barrier는 실패 복구에도 참여한다. 스레드 생성에 실패하면 이미 생성된 worker를 종료 상태로 release해 반환 및 join이 가능하게 한다. worker 또는 coordinator의 condition wait가 실패하면 `run_error`, `ended`, `start_released`를 게시하고 peer에 broadcast해 다른 스레드가 무기한 block되지 않게 한다.

condition variable에는 spurious wakeup이 있을 수 있고 broadcast는 상태를 저장하는 이벤트가 아니라 알림이므로, condition signal 하나가 상태 전이 하나에 대응한다고 가정하지 않고 readiness count와 predicate loop를 사용한다.

## test(thread): 지연된 작업자의 공통 시작 시각 검증
의도적으로 worker 시작을 크게 어긋나게 만들어 start barrier를 검증한다. `pthread_create`를 wrapper로 감싸 모든 생성된 스레드를 테스트 gate 뒤에서 대기시키고, 다섯 번째 worker에 추가로 150밀리초 지연을 주며, 다섯 개의 스레드 객체가 모두 만들어진 뒤에야 실제 routine을 release한다.

설정된 `time_to_die`는 80밀리초로 주입한 지연보다 짧다. 모든 worker가 barrier에 도달하기 전에 사망 clock을 시작하는 구현이라면 거짓 사망을 보고할 것이다. 테스트는 대신 다섯 철학자가 모두 한 번씩 식사하고 정상 종료하는지, `ready_count`가 전체 worker 수에 도달했는지 확인한다.

이는 barrier가 제거하려는 scheduler 조건을 우연에 맡기지 않고 직접 구성한다. 통과 조건은 단순히 스레드가 결국 시작된다는 것이 아니라, 스레드 생성 지연이 공유 시뮬레이션 epoch에 포함되지 않는다는 것이다.

## test(thread): 시작 대기 실패 전파 검증
routine object의 첫 번째 `pthread_cond_wait` 호출을 `EINVAL` 반환으로 대체해 worker 측 condition wait 실패를 주입한다. 여러 worker가 barrier에 도달하는 동안 테스트 자체에 별도의 race를 만들지 않도록 one-shot 주입 플래그 접근도 mutex로 보호한다.

실행은 `PHILO_ERR`를 반환하고 `run_error`를 보존하며 모든 peer를 release하고 외부 timeout 안에 종료해야 한다. 이 검증은 barrier API 실패가 무시되거나 정상 완료로 잘못 보고되거나 다른 worker를 영원히 재우는 대신 run 수준 오류 계약으로 승격되는지 확인한다.

이후 condition wait는 실제 pthread 함수에 위임하므로, 테스트는 주변의 제품 동기화 동작을 유지하면서 단 한 번의 wait 실패만 격리한다.

## fix(monitor): 종료 상태와 사망 로그를 원자적으로 확정
종료 상태 게시에 명시적인 linearization point를 부여한다. 식사 완료 조건은 이제 `state_mutex`를 잡은 상태에서 확인하고 즉시 확정하므로, 다른 스레드가 전역 완료 predicate는 참인데 `ended`는 아직 거짓인 상태를 관찰할 수 없다.

사망 감지는 두 단계 연산으로 바뀐다. monitor가 샘플링한 scan에서 후보를 먼저 찾을 수는 있지만, `philo_try_log_death`가 `print_mutex`를 먼저 잡고 이어서 `state_mutex`를 획득한 뒤 현재 monotonic 시각을 다시 샘플링한다. 그리고 종료 플래그와 후보의 최신 식사 timestamp를 다시 검증한다. 여전히 유효한 사망일 때만 `ended`를 설정하고 timestamp를 계산해 `died`를 출력한다.

일반 로그와 동일하게 print 먼저, state 다음의 중첩 lock 순서를 사용해 종료 전이와 출력을 직렬화한다. 사망이 확정된 뒤에는 어떤 일반 logger도 상태 검사를 통과해 뒤에 출력할 수 없고, 일반 logger가 먼저 print lock을 소유했다면 그 한 줄 전체가 사망 transaction보다 앞선다. 따라서 사망 줄은 단 하나이며 단순히 마지막일 가능성이 높은 것이 아니라 실제 종료 줄이 된다.

재검증은 monitor의 초기 scan 이후 식사를 시작한 철학자가 오래된 후보 정보 때문에 사망 처리되는 것도 막는다. monitor scan은 이제 참고용이며, 정확성은 동기화된 commit 지점에서 최종 결정된다.

## test(monitor): 완료 상태와 오래된 사망 판정 검증
타이밍 운에 기대지 않고 동기화 경계에 상태 변경을 주입해 monitor의 종료 불변식을 검증한다. wrapper mutex unlock은 식사 제한 완료가 state critical section을 빠져나가기 전에 이미 `ended`를 설정했는지 관찰하며, predicate 평가와 종료 게시가 하나의 transaction임을 확인한다.

두 번째 모드는 처음에는 이미 사망한 것처럼 보이는 철학자로 시작한 뒤, 같은 경계 hook을 이용해 monitor의 초기 관찰 이후 `last_meal_ms`를 갱신하고 식사 완료 상태를 만든다. monitor는 후보를 다시 검사해 유효한 완료 상태로 종료해야 하며 오래된 사망 로그를 출력해서는 안 된다.

이 테스트는 구현이 닫은 정확한 race window를 겨냥한다. 시뮬레이션을 반복 실행하는 데 그치지 않고 후보 발견과 종료 확정 사이에서 상태가 변하도록 강제해, 최종 판단이 현재의 동기화된 데이터를 사용함을 보여준다.

## fix(routine): 중단된 식사를 완료 횟수에서 제외
`philo_sleep_ms`가 deadline에 도달했는지, 아니면 시뮬레이션이 종료 상태가 되어 대기가 끝났는지를 반환하도록 한다. 식사 로직은 이를 연산 계약의 일부로 사용한다. 식사 시간이 중단되면 worker는 두 포크를 모두 해제하고 식사 카운터를 전혀 증가시키지 않은 채 반환한다.

`record_meal_done`도 값을 변경하기 직전에 `state_mutex`를 잡은 상태에서 `ended`를 다시 확인한다. sleep이 deadline에 도달했지만 카운터를 갱신하기 직전에 다른 스레드가 종료를 확정하는 race까지 포함한다. 따라서 식사는 설정된 시간이 온전히 끝났고 동기화된 완료 지점에서도 시뮬레이션이 활성 상태일 때만 카운트된다.

모든 실패 경로에서 두 포크 mutex를 해제하므로 논리적 연산이 commit되지 못해도 자원 소유권 불변식은 유지된다. 이제 “식사를 시작함”과 “한 끼를 완료함”이 명시적으로 구분된다. 식사 로그를 남겼거나 자원을 획득했다는 사실만으로 quota 진행이 완료되었다고 볼 수 없다.

## test(routine): 중단된 식사의 카운터 불변식 검증
routine object에서 `philo_sleep_ms`를 대체해 중단된 식사 경로를 결정적으로 만든다. stub은 제품 routine이 실제 포크 locking과 주변 상태 갱신을 수행하는 동안 `ended`를 게시하고 `PHILO_ERR`를 반환하며 중단이 발생했음을 기록한다.

직접 호출한 worker는 start barrier를 이미 지난 상태이며 local meal 수와 전역 완료 수가 모두 0으로 설정된다. 주입된 중단 이후에도 두 카운터는 모두 0이어야 한다. 이 검증은 완전한 식사 시간이 끝난 경우에만 철학자별 또는 전역 식사 진행에 반영된다는 의미 불변식을 고정한다.

worker를 직접 호출하면 scheduler 변동성을 제거하고 `eat_once` 내부 transaction 경계에 집중할 수 있다. shell 수준의 횟수 검사만으로는 중단된 식사를 올바르게 거부한 경우와 해당 코드 경로 자체에 도달하지 않은 interleaving을 구분할 수 없다.

## fix(lifecycle): 부분 시작과 정리 오류를 호출자에 전파
스레드 및 동기화 자원 해제에 명시적인 안전 모델을 도입한다. 테이블은 성공적으로 시작한 worker 수, 성공적으로 join한 worker 수, 파괴가 여전히 안전한지를 기록한다. `join_started`는 기록된 모든 join을 시도하고 성공한 경우에만 join 기록을 증가시키며, 어떤 worker라도 정지 상태임을 증명할 수 없으면 `PHILO_UNSAFE`를 반환한다.

`philo_table_destroy`는 join되지 않은 worker가 기록되어 있거나 `destroy_safe`가 해제된 경우 공유 메모리나 동기화 객체를 해제하지 않는다. 이는 join 실패를 일반 오류로 취급하는 것보다 엄격한 정책이다. worker가 여전히 포크, 상태, 철학자 저장 공간에 접근하고 있을 수 있으므로 해당 자원을 해제하면 use-after-free 또는 활성 mutex 파괴 위험이 생긴다.

파괴 실패도 상위로 전파한다. destructor는 해당 pthread 자원 파괴에 성공한 뒤에만 자원 기록을 감소시키거나 준비 플래그를 해제한다. 따라서 남은 상태가 아직 소유 중인 자원을 정확히 나타내며 cleanup을 재시도할 수 있다. 일반 초기화 및 실행 실패도 소유 자원 정보를 잃지 않고 보고할 수 있다.

`main`은 unsafe 상태를 복구 가능한 오류와 구분한다. join 실패 시 비버퍼링 diagnostic을 출력하고 `_exit`를 호출한다. worker가 살아 있는 동안 프로세스 상태를 건드릴 수 있는 테이블 파괴, 표준 I/O flush, 일반 exit handler를 의도적으로 건너뛴다. 안전한 run 실패에서는 여전히 cleanup을 시도하고 cleanup 자체가 실패하면 별도로 보고한다.

이 커밋은 lifecycle 카운터를 정확성의 근거로 바꾼다. `philo_run`의 제어 흐름이 끝에 도달했다는 이유가 아니라, 모든 worker가 정지했다는 증거가 있을 때만 파괴를 허용한다.

## test(lifecycle): 생성·결합·정리 실패 경로 검증
thread 생성, join, mutex 파괴를 감싸는 wrapper로 lifecycle 실패를 검증한다. 세 worker 실행에서 각 위치마다 생성 실패를 강제하고, run이 일반 오류를 반환하기 전에 실제로 시작된 prefix만 정확히 join되는지 확인한다.

join 실패는 unsafe 분기를 검증한다. 다른 worker에 대한 join은 계속 시도하더라도 실패한 worker는 미join 상태로 기록된다. 이때 테이블 파괴는 포크 포인터, 포크 개수, 파괴 호출 횟수를 변경하지 않은 채 `PHILO_UNSAFE`를 반환해야 한다. 테스트는 이후 실제 API로 해당 worker를 join하고 테스트용 자원 기록을 복구한 뒤 cleanup이 다시 합법적으로 수행되는지 확인한다.

destructor 실패는 역순 cleanup의 여러 단계에서 주입한다. 각 실패 이후 backing allocation과 남은 자원 기록은 아직 무엇을 소유하고 있는지 정확히 나타내야 하며, 주입 없이 두 번째 호출을 수행하면 정상 완료되어야 한다. 단순 오류 보고가 아니라 재시도 가능성을 검증한다.

여러 인덱스에서 실패를 다룸으로써 broad policy뿐 아니라 경계 계산도 확인한다. 생성 또는 파괴가 0개, 일부, 거의 전부 진행된 상태 모두 정확한 소유 자원 기록을 남겨야 한다.

## test(main): 결합 실패 시 안전하지 않은 정리 방지
실제 `main` 주변의 parsing, 초기화, 실행, 파괴를 대체해 프로세스 수준 unsafe 경로를 격리한다. run stub은 buffering된 표준 출력을 남긴 뒤 `PHILO_UNSAFE`를 반환하고, parsing 단계에서는 `atexit` hook도 등록한다. destroy stub은 호출될 경우 눈에 보이는 marker를 출력하도록 한다.

실행한 테스트 프로세스는 실패해야 하며, 비버퍼링 join diagnostic은 출력하되 destroy marker, buffering된 출력, 정상 exit hook 출력은 하나도 포함하면 안 된다. 이 negative assertion은 `main`이 `_exit`를 직접 호출하며 `main`에서 반환하거나 `exit`를 호출하지 않음을 보여준다.

바로 이 차이가 검증 대상인 안전 속성이다. worker가 아직 종료되지 않았을 수 있는 상황에서는 테이블 파괴만 피하는 것으로 충분하지 않다. 일반 프로세스 teardown이 공유 라이브러리 상태를 flush하거나 모든 worker가 끝났다고 가정하는 callback을 실행해서도 안 된다.

## test(concurrency): 철학자별 진행과 종료 로그 불변식 검증
전용 concurrency suite로 개별 실패 경로를 넘어 반복되는 실제 schedule에서 관찰 가능한 동작을 검증한다. 철학자 2명, 5명, 17명의 유한 실행은 사망 없이 끝나고 모든 철학자가 식사 목표에 도달해야 한다. 추가로 철학자 7명의 workload를 여러 번 반복해 schedule에 민감한 진행 실패를 드러낸다.

사망 workload는 별도로 반복하며 `died` 줄이 정확히 하나만 존재하고 그 뒤에 어떤 줄도 없어야 한다. 모든 로그는 필수 grammar와 nondecreasing timestamp 조건을 검사하므로 출력 직렬화, monotonic 경과 시간, 종료 순서를 서로 독립된 substring이 아니라 함께 검증한다.

집중 race harness에서는 12개의 logger 스레드를 시작해 각각 수백 번 일반 상태 출력을 시도하게 하고, 다른 경로에서 같은 테이블의 사망을 확정한다. 결과 stream에는 여전히 종료 사망 줄 하나만 존재하고 종료 이후 상태 로그는 없어야 한다. logger들을 gate 뒤에서 동시에 출발시켜 print/state 경계에서의 겹침을 늘리고, 종료 상태 강화에서 도입한 lock 순서를 직접 압박한다.

반복 실행만으로 모든 scheduler에 대한 starvation freedom을 증명할 수는 없으며 구현도 이를 보장하지 않는다. 다만 확립된 lock 순서, 진행 카운팅, 종료 로그 불변식이 현실적인 contention에서도 유지된다는 훨씬 강한 근거를 제공한다.

## test(tsan): ThreadSanitizer 검증 경로 추가
`make test-tsan`을 통해 선택적으로 ThreadSanitizer 빌드와 workload 경로를 사용할 수 있게 한다. compiler는 설정 가능하며, `TSAN_REQUIRED`로 sanitizer 지원이 선택적인 로컬 기능인지 반드시 제공되어야 하는 환경인지 구분한다.

sanitizer 결과를 해석하기 전에 작은 pthread probe를 컴파일하고 실행한다. compiler가 `-fsanitize=thread`를 지원하지 않거나 instrumented binary를 runtime에서 실행할 수 없으면, sanitizer 지원이 필수라고 지정된 경우를 제외하고 exit status 77과 함께 명시적으로 skip한다. 인프라 제약을 프로젝트 race로 잘못 분류하지 않으면서도 CI에서는 지원 여부를 강제할 수 있다.

probe가 성공하면 전체 실행 파일을 thread instrumentation과 debug 정보로 다시 빌드한다. 유한 실행, 강제 사망, 더 높은 contention schedule을 `halt_on_error` 및 전용 오류 종료 코드로 실행하며, sanitizer diagnostic이 없어야 할 뿐 아니라 로그 grammar, 철학자별 진행, 사망 없음 기대값, 하나의 종료 사망 불변식도 다시 확인한다.

동적 race 탐지는 결정적인 경계 테스트를 보완한다. 실제 실행된 schedule에서 동기화되지 않은 메모리 접근을 관찰하고, 동작 검증은 instrumented run이 필요한 작업 자체를 하지 않아 우연히 race를 피한 경우를 차단한다. 다만 여전히 schedule 의존적인 도구이지 exhaustive proof는 아니므로 두 검증 방식을 모두 유지한다.

## fix(state): 식사 완료 횟수의 정수 범위 확장
철학자별 내부 식사 카운터 타입을 `int`에서 `int64_t`로 넓힌다. 공개 `must_eat` 인자는 여전히 `INT_MAX` 이하이지만, 한 철학자가 임계값에 일찍 도달한 뒤 다른 철학자 때문에 전역 `full_count`가 테이블 크기에 도달하지 않은 동안 추가 식사를 계속 완료할 수 있다.

공개 임계값과 누적 런타임 상태에 같은 좁은 타입을 사용하면 충분히 긴 유효 실행에서 signed overflow가 발생할 수 있다. C의 signed overflow는 undefined behavior이며, mutex로 증가 연산을 보호한다고 안전해지는 문제가 아니다. 더 넓은 카운터는 임계값과의 정확한 비교를 유지하면서 이후 내부 진행을 훨씬 넓은 정의된 범위에서 표현한다.

## test(routine): 최대 목표 이후 식사 카운터 검증
넓어진 식사 카운터를 기존 타입의 정확한 경계에서 검증한다. 두 철학자 테이블에 공개 목표로 `INT_MAX`를 사용하고, 한 철학자의 카운터를 해당 값으로 설정하며, 이미 임계값 기여가 기록되었다는 의미로 `full_count`도 미리 설정한다.

대체한 sleep은 한 번의 추가 식사 시간을 정상 완료한 뒤 다음 수면 중 routine을 종료시킨다. 내부 카운터는 `INT_MAX + 1`이 되어야 하므로 공개 목표를 넘어서는 증가가 정의되어 있음을 확인한다. 반면 `full_count`는 그대로여야 한다. 임계값 기여는 정확히 같은 순간에만 발생하며 두 번 집계되어서는 안 되기 때문이다.

이는 숫자 범위와 완료 집계를 동시에 검증한다. 필드 타입만 넓혔더라도 임계값을 넘은 뒤 전역 완료에 다시 기여한다면 불완전하며, 반대로 임계값 로직을 유지했더라도 내부 증가가 여전히 overflow한다면 역시 불완전하다.
