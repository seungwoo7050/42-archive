# 프로젝트 중요도 프로필
프로젝트: `small-shell` (`c/minishell` 브랜치)
분야: C99/POSIX 명령 인터프리터 및 프로세스 런타임 엔지니어링
주요 목적: 표준 입력에서 제한된 셸 언어를 읽고, 인용 의미를 보존하며, 명령·파이프라인·리다이렉션·heredoc·조건 시퀀스를 파싱한다. 환경 변수와 상태 값을 확장하고, 부모 상태를 변경하는 builtin과 fork된 명령을 실행하며, 자원과 실패 동작을 관찰하고 복구할 수 있게 한다.
확정 커밋 범위: `c/minishell`의 루트 `30d34c745714`부터 팁 `3ed97fb01ff3`까지 이어지는 독립적이고 선형적인 78개 커밋 전체 계보를 포함한다. 범위에는 문서 전용이 아닌 엔지니어링 커밋 76개와 문서 전용 커밋 2개가 포함된다. 병합 커밋이나 관련 없는 상위 커밋은 없다. 12자리 축약 SHA로 범위 내 모든 커밋을 고유하게 식별할 수 있다.

## 핵심 기술 영역
- 명령, 리다이렉션, 파이프라인, 연결 연산자 시퀀스를 위한 인용 정보를 보존하는 어휘 표현과 파서 소유권.
- 올바른 실행 시점의 환경 변수 및 이전 상태 확장.
- 부모와 자식의 builtin 실행 차이, 셸 환경 변경, 종료 상태 계약.
- fork, exec, wait, 다단 파이프라인 토폴로지, 부분 생성 프로세스의 수명 주기 복구.
- pipe, 리다이렉션, 부모 표준 스트림, heredoc 임시 저장소의 파일 디스크립터 소유권.
- heredoc 구분자 출처 정보, 순서가 보장되는 사전 수집, 본문 확장, 입력 경계 복구, stdin 설치.
- 구성·실행·명령 루프 전반의 복구 가능한 할당 및 I/O 실패 전파.
- 결정적 fault injection, 수명 주기 검사, 시간 제한 격리, sanitizer, end-to-end 회귀 검증.

## 핵심 아키텍처
- `shell_loop`는 최상위 줄 입력을 소유하며 명령 사이에서 `t_shell`의 환경, 마지막 상태, 실행 상태를 유지한다.
- `tokenize_line`은 소스 텍스트를 소유 토큰으로 변환하면서 리터럴 마커 의미와 단어에 인용 구문이 사용되었는지를 보존한다.
- `parse_tokens`는 토큰 데이터를 소유 계층으로 복사한다. 시퀀스는 파이프라인으로, 각 파이프라인은 명령으로, 각 명령은 argv와 순서가 있는 리다이렉션으로 구성된다.
- heredoc은 연결 연산자 조건 판단 전에 파싱된 줄 전체에 대해 수집한다. 항목은 자신을 소유한 리다이렉션 노드의 주소를 키로 사용하며 파싱 트리보다 먼저 해제한다.
- `execute_pipeline_list_ctx`는 연결 연산자 조건 판단을 적용하고 현재 셸 상태를 사용해 선택된 파이프라인만 확장한 뒤, 부모 명령 또는 fork된 파이프라인으로 디스패치한다.
- 부모 상태를 변경하는 builtin과 리다이렉션만 있는 명령은 표준 스트림 저장·적용·복원 경계 안에서 셸 프로세스가 실행한다. 파이프라인 구성원과 외부 명령은 자식에서 실행한다.
- 런타임 래퍼는 프로덕션 위임과 결정적 테스트 실패 주입을 위해 할당과 시스템 호출 경계를 분리한다.
- 소스 수준 `t_sequence`와 훅 실행기는 파서 테스트용 경계로 유지하고, 실제 제품 실행 경로는 `shell_process_line`과 구체적인 실행기를 사용한다.

## 핵심 불변식
- 파싱 결과의 소유권은 계층적이고 모호하지 않다. 구성이 확정된 모든 토큰, argv 항목, 리다이렉션, 명령, 파이프라인, heredoc 본문, PID, 디스크립터에는 하나의 정리 소유자가 있다.
- 인용 효과는 필요한 모든 단계를 지나도 유지되어야 한다. 최종 구분자 텍스트에서는 인용 표식을 제거할 수 있지만, heredoc 본문 확장 여부를 결정하려면 인용 여부 정보를 계속 사용할 수 있어야 한다.
- 연결 연산자 판단은 직전에 생성된 상태를 사용하며, 건너뛴 파이프라인은 확장도 실행도 수행하지 않는다.
- 기록된 자식 PID는 해당 자식이 종료되거나 관찰될 때까지 부모의 책임이다. 파이프라인이 일부만 생성된 경우에도 멈추거나 좀비를 남겨서는 안 된다.
- 각 프로세스는 필요하지 않은 pipe FD를 모두 닫고, 부모의 표준 스트림은 다음 명령 전에 복원한다. 복원이 불가능하면 셸을 중단한다.
- heredoc 준비 실패가 heredoc 본문 데이터와 이후 명령 사이의 경계를 바꿔서는 안 된다.
- heredoc 임시 저장 과정의 write, flush, seek, 디스크립터 조회, 디스크립터 복제 실패를 성공한 명령 입력으로 보고해서는 안 된다.
- 할당 실패는 기존의 유효한 상태를 그대로 두거나 부분 결과 전체를 해제해야 한다. 저수준 헬퍼가 실행 중인 셸을 임의로 종료하지 않는다.
- EOF는 정상 종료이고 read 또는 write 실패는 상태를 갖는 명시적인 실패다. 다음 명령 경계를 신뢰할 수 있을 때만 실행을 계속한다.
- 외부 명령 및 자식 종료 상태는 프로젝트의 126, 127, 정상 종료, 시그널, 하위 8비트 종료 계약을 유지한다.

## 주요 엔지니어링 난점
- 완전한 POSIX 셸 AST 없이도 셸의 결합 규칙과 인용 의미를 보존하는 간결한 표현을 설계하는 문제.
- 조건 단락 평가와 변경되는 `$?` 상태에 확장 시점을 맞추는 문제.
- 파이프라인 구성 도중 fork, wait, 정리가 실패해도 디스크립터와 자식 소유권을 정확히 유지하는 문제.
- 스트림 위치를 복구 가능하게 유지하면서 렉서, 파서, 입력 수집, 확장, 실행 컨텍스트, 리다이렉션 전반에 heredoc 의미를 전달하는 문제.
- 서로 의존하는 여러 하위 시스템에서 치명적인 할당 동작을 트랜잭션 방식의 객체 구성과 호출자에게 전달되는 오류 처리로 교체하는 문제.
- 프로덕션 의미를 바꾸지 않고 드문 실패 경로를 재현한 뒤 디스크립터, 자식, 부분 상태, 읽지 않은 heredoc 데이터가 남지 않는지 검증하는 문제.
- 마커 인코딩, 오버플로 검사, 원자적 소유권 이전을 유지하면서 제곱 시간 복잡도의 문자열 구성을 제거하는 문제.

## 실무 엔지니어링 영역
- 잘못된 구문, 식별자, exit 인자, 공개 API의 NULL 허용 여부 검증.
- 지연되거나 조용히 무시되는 표준 I/O/시스템 호출 실패 대신 정확한 오류 및 상태 전파.
- 부분 할당, 디스크립터, 프로세스, 환경 값 교체, heredoc 본문의 정리 순서.
- EINTR과 부분 I/O를 고려한 I/O 경계.
- 연산 종류, 호출 위치, 처리 단계, 명령 번호에 따른 결정적 fault injection.
- 프로세스 그룹, 단조 시계 기반 제한 시간, 리소스 제한, 수명 주기 검사, 분리된 sanitizer 빌드 산출물을 이용한 테스트 격리.
- 출력, 상태, 진단, 성능, 실행 지속 여부에 대한 end-to-end 회귀 검증.

## S 등급 기준
- 이후 여러 하위 시스템이 의존하는 지속 가능한 파싱 결과 표현, 실행 모델 또는 단계 간 의미 계약을 확립한다.
- 빠지면 프로세스, 파이프라인, heredoc, 조건부 실행 아키텍처를 설명할 수 없는 핵심 셸 메커니즘을 구현한다.
- 하위 시스템 경계를 가로지르는 심각하고 비직관적인 소유권 또는 의미 불변식을 근본 원인 수준에서 복원한다.
- 모든 주요 구성 경로의 동작을 실질적으로 결정하는 방식으로 프로젝트 전역 실패 모델을 교체한다.

## A 등급 기준
- 중요한 컴포넌트 경계, 리소스 수명 주기, API 계약, 실패 경로, 테스트 경계를 확립하거나 강화한다.
- 실패 시 셸 상태, 스트림 위치, 프로세스 소유권, 디스크립터, 정확한 상태 보고를 손상시킬 수 있는 중요한 엣지 케이스를 수정한다.
- 일반적인 정상 경로 검증 범위가 아니라 어려운 실패 또는 단계 간 불변식에 대한 회귀 검증 근거를 제공한다.
- 프로젝트 전체를 다시 정의하지는 않지만 영향이 큰 재사용 가능한 구조 또는 성능 추상화를 도입한다.

## 일반적인 B 등급 작업
- 이미 정립된 파서, 환경, builtin, 확장, 실행 설계 안에서 예상 가능한 셸 기능이나 보조 단계를 구현한다.
- 이미 선택된 추상화를 다른 모듈에 적용한다.
- 기존 계약에 대한 일반적인 동작, 호환성, 빌드 지원, 회귀 검증을 추가한다.
- 주요 책임이나 소유권 경계를 바꾸지 않는 좁고 직접적인 결함을 수정한다.

## 일반적인 C 등급 작업
- 문서 전용 변경, 사용하지 않는 인터페이스 제거처럼 실행 동작이나 구조에 거의 영향을 주지 않는 변경.
- 빠져도 프로젝트의 메커니즘, 불변식, 어려운 수정 사항을 이해하는 데 지장이 없는 기계적인 정리.

## 프로젝트별 태그
LEX_PARSE — 어휘 인코딩, 파서 구조, 구문 검증, 파싱 객체 소유권
EXPANSION — 인용 제거, 변수/상태 확장, 확장 시점
SHELL_STATE — 환경, builtin, 셸 수명, 명령 사이에서 보이는 상태
PROCESS — fork, exec, wait, 자식 소유권, 파이프라인 프로세스 토폴로지
FD_IO — pipe, 리다이렉션, 표준 스트림, 임시 스트림, read, write
HEREDOC — 구분자 출처 정보, 본문 수집/확장, 스트림 복구, stdin 통합
FAILURE — 명시적 오류 전파, 부분 실패 정리, 복구, 결정적 fault injection 경계

# 핵심 커밋

## feat(parser): 명령 트리 소유권 모델 정의
커밋: `48670b845d7f`
중요도: S
태그: ARCH, LEX_PARSE, CORE

### 문제
원시 토큰만으로는 실행에 충분하지 않다. 셸에는 인자, 순서가 있는 리다이렉션, 명령 그룹, 연결 연산자와 이들에 연결된 모든 소유권을 안정적으로 표현할 구조가 필요하다.

### 결정
한 줄을 명령을 포함하는 파이프라인으로 표현하고, 명령은 argv와 리다이렉션을 포함하며, 연결 연산자는 완전한 파이프라인에 연결한다. 이 계층 구조에 대응하는 재귀 정리 진입점 하나를 둔다.

### 중요성
이후의 모든 파서, 확장기, heredoc 항목, 실행기 할당, 실패 정리가 이 소유권 경계를 전제로 한다. 지원 문법을 표현하기에 충분히 간결하면서 부분 상태와 완성된 상태 모두를 결정적으로 해제할 수 있는 모델이다.

### 변경 사항
`t_redir`, `t_command`, `t_pipeline`, 연결 연산자 메타데이터, 요소 개수를 도입하고 argv 문자열, 리다이렉션 대상, 명령, 파이프라인 노드를 말단부터 상위 방향으로 해제하는 정리를 추가했다.

### 프로젝트 이해에서의 중요성
셸의 데이터 아키텍처를 정의한 커밋이다. 각 단계가 무엇을 소유하는지, 이후 단계가 토큰을 보관하지 않고 복사하는 이유, 하위 시스템별 정리 세부 정보를 몰라도 임의의 부분 파싱을 오류 경로에서 해제할 수 있는 이유를 설명한다.

## feat(parser): 조건 연결자를 sequence로 결합
커밋: `f297aaad70fe`
중요도: S
태그: ARCH, LEX_PARSE, CORE

### 문제
단일 파이프라인 파서로는 세미콜론 시퀀스나 조건 실행을 표현할 수 없다. 모든 연산자를 같은 수준으로 처리하면 pipe가 더 강하게 결합한다는 규칙도 잃게 된다.

### 결정
`;`, `&&`, `||`를 만나면 현재 파이프라인을 끝내고 연결 연산자를 왼쪽 파이프라인에 저장한 뒤, 생성된 파이프라인 단위를 소스 순서대로 연결한다. 빈 단위와 후행 조건 연산자는 거부하되 후행 세미콜론은 허용한다.

### 중요성
불필요하게 범용적인 AST를 도입하지 않고도 프로젝트 문법을 보존한다. 또한 실행기가 단락 평가 판단에 필요한 정확한 실행 단위를 제공하고, 완성된 앞부분 뒤에서 파싱이 실패해도 정리를 올바르게 유지한다.

### 변경 사항
파서에 파이프라인 리스트 구성, 연결 연산자 변환, 비어 있거나 불완전한 피연산자에 대한 오류 처리, 현재 파이프라인과 이미 파싱된 시퀀스 앞부분을 함께 정리하는 경로를 추가했다.

### 프로젝트 이해에서의 중요성
셸의 우선순위 모델을 설명한다. pipe가 먼저 하나의 실행 단위를 만들고, 시퀀스 및 조건 연산자가 그 단위들을 왼쪽에서 오른쪽으로 연결한다.

## feat(exec): 다단 pipeline의 pipe FD 연결
커밋: `a71f98de0d92`
중요도: S
태그: PROCESS, FD_IO, CORE

### 문제
여러 명령을 fork하는 것만으로 파이프라인이 만들어지지는 않는다. 각 자식이 올바른 인접 디스크립터를 받아야 하고 모든 프로세스가 사용하지 않는 pipe FD를 닫아야 한다.

### 결정
`N - 1`개의 pipe를 `N`개 명령에 할당하고, 각 자식에서 이전 pipe의 읽기 끝을 stdin에, 다음 pipe의 쓰기 끝을 stdout에 연결한다. 원본 pipe FD를 모두 닫은 뒤 명시적인 명령 리다이렉션을 적용한다.

### 중요성
이 순서가 데이터 흐름과 리다이렉션 우선순위를 모두 결정한다. 부모와 자식의 디스크립터 닫기 규칙은 사용하지 않는 writer가 남아 reader가 무한히 기다리는 상황을 막고, 파이프라인 builtin을 자식에서 실행해 상태 변경이 부모 셸로 새지 않도록 한다.

### 변경 사항
실행기에 파이프 테이블 생성과 정리, 단계별 디스크립터 복제, 명령당 자식 하나 생성, 부모 측 pipe 닫기와 자식 회수, 마지막 단계 상태 선택, 단일 상태 변경 builtin을 부모에서 실행하는 경로를 추가했다.

### 프로젝트 이해에서의 중요성
프로젝트를 규정하는 프로세스 토폴로지다. 이후의 모든 fork 실패, 디스크립터 누수, 시간 제한, 자식 수명 주기 수정이 이 구조를 기반으로 한다.

## feat(exec): 조건 연결자와 지연 확장 실행
커밋: `13a70b408e89`
중요도: S
태그: ARCH, EXPANSION, CORE

### 문제
파싱된 줄 전체를 실행 전에 확장하면 건너뛸 분기까지 평가하게 되고, 뒤쪽 파이프라인은 오래된 `$?` 값을 보게 된다.

### 결정
파이프라인 리스트를 순회하며 직전 연결 연산자를 전달하고 다음 파이프라인 실행 여부를 먼저 결정한다. 실제로 선택된 파이프라인만 디스패치 직전에 현재 셸 상태로 확장한다.

### 중요성
제어 흐름과 확장은 의미적으로 결합되어 있다. 건너뛴 분기에서는 확장의 부수 효과나 할당 실패가 발생해서는 안 되고, 실행되는 분기는 바로 앞 파이프라인이 생성한 상태를 관찰해야 한다.

### 변경 사항
파이프라인 하나의 확장과 실행을 분리하고, 확장 중 해당 파이프라인을 리스트에서 임시 분리하며, `&&`와 `||` 조건 판단을 구현했다. 실행 단위마다 상태를 전파하고 `exit`가 셸을 종료하면 순회를 멈추도록 했다.

### 프로젝트 이해에서의 중요성
전체 줄을 미리 파싱하면서도 확장은 런타임 상태에 의존할 수 있는 이유를 설명한다. 이 시점 결정은 프로젝트에서 가장 중요한 셸 의미상 판단 중 하나다.

## feat(redirection): heredoc을 stdin으로 연결
커밋: `d297bd2e8908`
중요도: S
태그: HEREDOC, FD_IO, INTEGRATION

### 문제
heredoc은 `<<`를 인식하는 것만으로 구현되지 않는다. 본문을 실행 전에 읽고 정확한 파싱된 리다이렉션과 연결하며, 소스 순서대로 설치한 뒤 줄 처리가 끝날 때 해제해야 한다.

### 결정
heredoc을 정식 토큰 및 리다이렉션 타입으로 만들고, 리다이렉션 식별자를 키로 하는 실행 컨텍스트에 모든 본문을 미리 수집한다. 구분자는 일반 확장 대신 인용 제거하고, 선택된 본문은 기존의 순서 있는 리다이렉션 순회를 통해 설치한다.

### 중요성
기존 리다이렉션 적용 순서를 재사용하면 들어오는 pipe 및 뒤쪽 입력 리다이렉션과의 상호작용도 그대로 보존된다. 줄 단위 실행 컨텍스트는 본문 수명을 자식 수명과 분리하면서 파싱된 소유권과의 안정적인 연결을 유지한다.

### 변경 사항
렉서/파서 지원, heredoc 준비, 실행 컨텍스트 초기화, 실패 정리, stdin에 임시 스트림 설치, 실행 후 본문 해제를 제품 실행 경로에 연결했다.

### 프로젝트 이해에서의 중요성
하나의 셸 기능이 모든 주요 단계를 어떻게 가로지르는지 보여 주는 커밋이다. 저장소의 통합 및 소유권 설계를 가장 분명하게 드러낸다.

### 프로젝트 이해에서의 중요성
의미 처리 이력에서 가장 강한 근본 원인 수정이다. 정규화된 텍스트에는 남지 않더라도 이후 단계에서 필요한 정보라면 표현 계층이 보존해야 한다는 점을 보여 준다.

## fix(exec): 부분 생성 파이프라인의 자식과 FD 회수
커밋: `be2967a4b946`
중요도: S
태그: PROCESS, FD_IO, FAILURE

### 문제
뒤쪽 fork가 실패하면 이미 생성된 단계가 블로킹되거나 실행 중인 상태로 남을 수 있다. 디스크립터를 닫고 기다리기만 해서는 충분하지 않아 무기한 멈추거나 좀비가 남을 수 있었다.

### 결정
부분 생성 상태에서는 부모가 보유한 모든 pipe FD를 닫고, 기록된 각 자식에 종료 시그널을 보내며, 이미 종료한 자식도 허용한 채 모든 PID를 끝까지 회수한다. wait 실패가 하나라도 있으면 파이프라인 실패로 처리한다.

### 중요성
파이프라인이 완성되지 않았더라도 PID를 기록한 순간 수명 주기 책임은 부모에게 넘어간다. 정리 경로는 정상 실행과 동일하게 모든 소유 자원이 정리된 동일한 최종 상태로 수렴해야 한다.

### 변경 사항
실행기에 자식 종료, 구조화된 wait 재시도와 오류 보고, 마지막 자식을 정상적으로 관찰하지 못하면 해당 종료 상태를 사용하지 않는 처리, 부분 생성 뒤의 완전한 정리를 추가했다.

### 프로젝트 이해에서의 중요성
파이프라인을 단순 정상 경로 메커니즘에서 신뢰할 수 있는 수명 주기 소유자로 바꾼 커밋이다. 이후 fault injection 및 누수 검증 아키텍처가 필요한 이유를 설명한다.

## fix(memory): 구조화 단계의 할당 실패를 명령 오류로 전파
커밋: `0bb6f9de0947`
중요도: S
태그: ARCH, FAILURE, RISK

### 문제
토큰화, 파싱, 환경 변경, 확장 깊숙한 곳의 치명적 할당 헬퍼가 셸 전체를 종료할 수 있었다. 이 경우 소유권 정리를 건너뛰고 부분 상태를 노출할 가능성도 있었다.

### 결정
할당 헬퍼가 NULL을 반환하도록 바꾸고, 각 구성 계층이 완성된 결과만 외부에 확정하도록 한다. 교체가 성공할 때까지 기존 상태를 보존하고 부분 앞부분을 해제하며, 할당 실패를 명령 또는 시작 단계 경계를 통해 전파한다.

### 중요성
예외처럼 프로세스를 종료하는 방식에서 명시적인 트랜잭션형 실패 처리로 프로젝트 전역 정책을 바꾼다. 거의 모든 소유 표현에 영향을 주며, 실행 중인 셸이 한 명령의 실패를 진단한 뒤 안전하게 계속할 수 있는지를 결정한다.

### 변경 사항
유틸리티에 크기 검사와 NULL 반환을 추가했다. 환경 생성·교체·가져오기·직렬화는 트랜잭션 방식으로 바뀌었고, 렉서와 파서는 실패 시에도 완성된 구조만 확정하도록 바뀌었다. 확장과 공개 API도 할당 오류를 전파하며, 루프는 구문 상태와 명령 수준 메모리 실패를 구분한다.

### 프로젝트 이해에서의 중요성
실패 아키텍처의 중심 커밋이다. 파싱, 환경 상태, 실행, heredoc에서 얻은 소유권 원칙을 하나의 불변식으로 통합한다. 불완전한 오브젝트는 외부로 나가지 않고 임의의 헬퍼가 프로세스 종료를 결정하지 않는다.

## fix(heredoc): 준비 실패 뒤 입력 구분자 경계 복구
커밋: `c30b39c0bcf8`
중요도: A
태그: HEREDOC, FAILURE, RISK

### 문제
heredoc 준비 실패가 발생했을 때 본문 줄과 이후 구분자가 stdin에 남은 채 반환하면, 실패한 명령용 데이터가 이후 셸 명령으로 파싱될 수 있다.

### 결정
준비 실패를 기록하고 본문을 구성하지 않은 채 현재 heredoc의 나머지와 이후 대기 중인 heredoc을 모두 소비한다. 정상 인용 제거 할당을 사용할 수 없으면 인코딩된 구분자를 직접 비교한다.

### 중요성
스트리밍 명령 인터프리터에서는 다음 명령 경계를 보존하는 일이 메모리를 해제하는 것만큼 중요하다. 입력 위치를 복구하지 않고 오류를 반환하면 로컬 할당 실패가 의도하지 않은 명령 실행으로 바뀔 수 있다.

### 변경 사항
수집기에 구분자까지 폐기하는 동작, 마커를 인식하면서 할당 없이 수행하는 구분자 비교, 남은 heredoc 순회, 추가 용량 오버플로 방지를 도입했다.

### 프로젝트 이해에서의 중요성
예외적인 A 등급 커밋으로 실패 모델의 깊이를 보여 준다. 복구는 오브젝트와 디스크립터뿐 아니라 입력 스트림 안의 의미상 위치까지 고려해야 한다.
